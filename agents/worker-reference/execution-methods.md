# 连续执行与异常恢复

本参考用于批量操作、中断接续、部分完成或结果不明的任务。目标是在授权范围内完成结果，并让后续动作建立在真实状态上。简单、结果明确的单步任务直接完成相应检查即可。

## 开始与接续

把任务要求转成最终应当存在的状态，确认要操作的对象、当前状态、必要输入和会影响结果的约束。已确认的接口和要求沿用，普通内部方法自己确定。需要查看历史时，找会改变下一步的决定与结果，不重复整个调查。

多步或批量任务先识别相互依赖的步骤和会产生持久影响的位置。安排工作时让错误容易被发现和修正：可以先处理一个有代表性的对象，核对结果后继续。已有完整可靠的批处理能力时直接复用，不为形式拆成许多手工动作。

重启或接手后，以实际对象和现有记录核对哪些已完成、哪些未完成、哪些结果未知。记录只是入口，若它与实际状态不一致，先查明差异再继续。

## 动作后的观察

命令成功说明该命令返回了成功，完成判断还要看目标状态。检查动作作用于正确的对象、版本和范围，结果能够被实际使用方读取或使用。检查深度与错误影响相称，小文本修改可以读回，跨组件结果沿真实入口确认。

例如，文件复制命令结束后，任务要求仍需核对目标文件内容；上传返回任务 ID 时，应沿该 ID 查询处理状态，不能把排队完成写成文件已处理。工具已提供可靠的内容或状态校验时直接利用，不重复实现同一机制。

## 异常与部分完成

先区分确定未执行、部分执行、执行结果未知和已执行但结果不符合要求。保留足够的错误和当前状态信息，定位最早偏离预期的位置。针对可能原因选择能区分它们的读取或小实验，再决定继续、修正或交回。

能隔离的个别输入错误只影响对应对象，其余符合条件的工作按合同继续。影响共同前提、共享状态或后续结果正确性的异常，先暂停受影响部分。无需因一个文件无效而停止全部批次，也不能用忽略该文件制造全批成功。

再次执行可能重复写入、移动、提交或其他副作用时，先核实安全重复的依据。结果可查时先查；已有适用的事务、幂等或去重保证时可据此重试。结果不明且缺少安全重复的保证时，交回具体对象和未决状态。恢复、撤销或补偿动作仍需在原授权内，不能因修错扩大影响。

## 对照例子

**文件重名：** 合同要求不覆盖。发现目标同名但内容不同，保留双方，记录该项冲突，继续处理其他独立文件。冲突解除后按真实文件状态接续，已完成项不重复移动。

**远程写入超时：** 超时可能发生在写入前，也可能发生在写入后返回结果时。结果可查时按原操作标识查询；服务明确保证同一标识的重复请求只生效一次时，可以复用该标识重试。不能把超时直接解释为未写入，也不换新标识盲目重试。

**结果数量不符：** 预期处理二十项，输出十九项。先核对发现、读取、筛选和写入各阶段的对应关系，查明缺失发生在哪一步。数量本身不能判断遗漏的是哪一项，也不能用再跑一次替代定位。

## 交回可接续结果

回答约定结果成立到哪里，实际改变了哪些对象，用什么检查确认，还剩哪些影响后续的未决状态。受阻时写清恢复工作需要的事实或决定。复杂批次可以沿用简短记录逐项关联输入与结果，普通任务无需另建状态系统。检验与交接围绕目标状态，省去不影响复核的操作流水。

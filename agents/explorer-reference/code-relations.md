# 理解代码和运行关系

## 从问题追踪实际连接

定位与问题有关的入口、定义和引用，再检查连接成立的条件。名称搜索用于发现候选，理解关系需要读取绑定、调用参数、分支和配置。先解释关键路径，需要时再展开周边实现，不要求遍历全部仓库。

沿别名、导出、包装器、接口实现、注册表或插件入口追踪真实对象。存在多个同名实现时，确认导入解析、配置选择和覆盖顺序。环境变量、命令行、默认值及配置文件谁优先，要由加载代码或可靠文档支持。

数据问题沿输入、变换、分支和输出追踪，保留单位与状态条件。控制关系和数据关系分别核对：函数可以被调用，却未接收所讨论的数据；数据经过某函数，也可能被分支提前返回。

把代码条件转成文字时保留原有逻辑范围，核对相等、否定、默认分支和提前返回。分支名称、注释或文档中的预期用途不能替代实际条件。例如代码只排除了 `disabled`，剩余路径就包括所有其他值；只有找到输入校验把值域限制为 `disabled/enabled`，才能将剩余路径概括为 `enabled`。

## 选择可用工具并解释证据

文本搜索提供命中位置，语法解析提供结构，符号与引用工具帮助判断绑定，调用图和数据流分析帮助追踪可能路径。使用现有能力时检查它覆盖的项目、版本与构建条件。索引遗漏动态注册或依赖库时，补读相应源文件和配置。

工具未提供语义关系时，可以直接读源文件追踪。不能把尚未使用的 AST、LSP 或分析器当作已有证据。索引覆盖未知会限制“所有引用”等完整性结论，经原文件核实的局部事实仍然有效。

静态材料可以说明在给定条件下会走什么路径。若问题要求当前进程实际采用了什么，还需相应启动参数、日志或运行证据。只读角色无法取得时，说明具体缺少什么观察，保留已查清的静态结果。

## 判断示例

`from engine import calculate as run` 后调用 `run(9)`：追到 engine 中的 calculate，而不是另一个文件里的同名 run。

默认配置选择 A，部署参数覆盖为 B：读取覆盖规则与部署入口，按实际适用层次判断。README 写 A 不能替代当前配置链。

测试在提交 X、功能开关关闭时通过，待判断版本为 Y 且开关开启：测试证明的是 X 的对应条件。继续检查改变涉及的路径与可用验证记录，不能直接宣布 Y 已验证。

## 交回关系

简单关系用完整句子和定位说明；复杂路径可给短链或图。每个会改变答案的跳转应有可核查依据，区分确定连接、条件连接和未解决连接。无需为每条普通引用填固定表格。

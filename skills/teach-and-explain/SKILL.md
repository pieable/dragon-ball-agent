# 教学与解释

## 部署材料

本 Skill 的公共主干与个人材料分开安装。涉及本地样例、档案或维护历史前，读取 [本地依赖](LOCAL-DEPENDENCIES.md)；缺失材料不等同于方法已执行。

## 解释与共同决定

- **按用途与基础定深浅**：帮助用户以更少的阅读、查找和操作，准确理解问题、AI 成果与进展，判断后果并指导后续工作（常规专业方法与工具由当前模型按任务选择，本 Skill 聚焦理解、学习、决定和交付含义）。按共同探索、了解现状、比较方案、完成操作或专门学习等用途及用户已有基础决定范围和深度；沿用对话已确认背景，只询问会改变判断或路线的缺口。
- **直观建立与真实对应**：用具体对象连接现象、前因、机制、条件和结果，保留改变判断的事实、反例与不确定性。初学时允许用简化、近似和类比建立直观认识；成立范围和例外在影响当前理解或判断时补充，重要机制仍与真实对象对应。
- **处理异议与方案取舍**：用户表示看不懂、提异议或纠正时，先辨明是背景/关系不足、目标被误解还是不同意结论，据此补依据、修理解或保留分歧，不用重复讲解推动接受。重要设计或业务取舍说明目标适配、理由、使用变化、影响和风险，用同一情景比较方案（帮用户预测结果并能独立向他人说明）；涉及偏好或重要投入时用具体样例校准。区分“用户理解、同意方案、授权行动”，按明确表达更新要求。
- **跨会话接续与资料索引**：持续项目恢复或重整理解使用 [任务理解蒸馏](../workflow-state-distiller/SKILL.md) 及 [项目背景与共同理解](../workflow-state-distiller/references/project-context-and-understanding.md)，路线关系由 [探索路线图](../workflow-route-mapper/SKILL.md) 沿用现有入口维护；教学所得新认识同步回主资料。核对依据或借用方法时查阅 [资料索引](sources/index.md)（已读且仍有效的内容沿用）。

## 长任务报告与文档载体

- **HTML 与 MD 载体分工**：遵循全局双视图分工——给用户阅读的独立文档默认用 HTML（面向理解重新组织内容并提供详细记录入口，用关系图、对照、情境、时间轴或交互让整体结构、局部位置、机制和变化可见，保留理解所需的信息密度、因果与例子；简短对话直接回答，指定其他格式时从其用途）；AI 侧用 MD 保存可检索的工作材料（索引指向准确对象、前提、方法、尝试结果、决定和原始证据，维护必读入口与变更传达，**不因人不愿读长文而压缩 AI 所需信息**）。两者共用事实来源和对象编号，变化后更新已交付视图；交付用户提供 HTML，交接 agent 提供 MD 与原件位置。
- **从读者任务组织，拒绝文字堆砌与空壳卡片**：复杂报告先从读者要查找、比较、理解或决定的事筛出关键结论、必要条件、对象及关系，**以“需求、架构和验证”为理解入口**连接目标、运行情境、机制、取舍与证据；先用真实代表内容检查扫读和局部深入，再扩展全篇（框架随内容调整，**不把文字分装进卡片、不先搭空卡片再填字、不加无解释作用的装饰图，也不沿工作经过顺次堆叠**；短报告直接用简短文字）。
- **报告必含内容与阅读路径**：
  - 在阶段结果、重要决定、阻塞、路线变化和交付时，讲清整体目标、当前成果与影响、已验证范围、关键证据、风险或缺口，以及下一步与理由（常规验证概括结论并留查阅入口，**不用过程细节证明工作量**；重要失败、未完成项和改变决定的条件留在正文；路线理解结合路线记录概括问题、依据、关键选择与验证反馈）。
  - **多 agent 长任务综合**：围绕用户目标与实际对象合并重复发现，核对跨工作线的依赖、冲突和变化，讲清有效决定、整体完成度、缺口与下一步；不按原始段落、消息或 agent 数量切分单元，不让用户逐份读子报告自行拼接。
  - **路径与标题**：报告支持扫读后深入，参考资料支持直接查阅，操作指导支持定位当前步骤，连续论证保留展开顺序。标题直接呈现具体内容、问题或结论，**不用“先看……”等引导语充当标题**；重要条件在判断处可见，避免读者为理解一处而通读前文。
  - **诚实说明验证范围**：区分事实、推断与未知；分别说明文件写入、局部运行、完整使用或用户实际掌握所能证明的结果。
- **报告中的视觉创作边界**：复杂阶段报告和最终报告在组织内容时，主动判断生图能否解决具体视觉问题，适合时使用 [绘图创作与艺术指导](../image-art-direction/SKILL.md) 提出关系表达、风格稿、设计拆解稿或可组合素材。**普通信息报告从内容关系和成熟、朴素的排版出发；精确路线图沿用 Mermaid 或程序化绘图；只有整体美术或新视觉身份是作品关键且仍开放时，才先制作完整页面视觉稿**（不以每份报告都出图为目标）。准确文字、数据、来源和交互由内容及实现负责人落实，按真实成品的扫读、定位和理解效果验收。

## 项目词汇与随问题教学

- **项目根目录 `词汇表.html`**：每个项目开始或接手时主动建立或更新根目录 `词汇表.html`，复用固定模板，按项目用途和领域结构提前覆盖核心概念及关系（含尚未讨论但有助于准确表达和发现新问题的概念），按主题组织并随认识变化维护；选词、模板与数据方法见 [项目词汇表](references/project-glossary.md)。进入新领域或作重要选择时主动在对话中补充概念与区别；表达模糊时结合具体对象提候选与例子澄清（未确认匹配留作候选，不以找到术语代替理解）。
- **随当前问题教学**：知识缺口影响当前表达、选择或检查时，把术语和前提连到正在处理的对象、操作和结果（不为简单任务扩展无关课程；熟悉部分直接承接，用户要求只执行时直接推进）。对质疑先查针对的主张、前提或依据；只有真实选择或结果能消除重要歧义时才用具体情境确认理解，**不要求普通讨论复述或考试**。

## 持续理解与专门学习

- **结合真实项目深化系统设计**：从会反复影响路线、解释多个现象或帮助形成新判断的知识中选取核心关系，讲清适用条件和条件变化后的差异；后续讨论沿用已有背景逐步深化，不每次重讲全套。当前用户的学习目标与分工须从本地档案或本次明确要求取得，见 [个人学习档案](user/学习档案.md)：编码、部署与调试由 AI 执行，结合真实项目中的重要选择或异常，按基础提供完整案例、比较方案或支持用户预测后果，再用实际结果修正理解，让整体结构与关键机制、情境和证据相互对应；不默认安排实现练习，也不因等待学习作答中断已授权工作。
- **专门学习的目标与活动安排**：用户明确要学会方法时，先确定以后要独立完成什么，并结合基础、困难、已有学习证据与现实条件安排教学；问题、尝试或材料已说明的内容直接沿用，不为完成诊断步骤而多问。提问、示例、练习和复习服务于明确教学目的（诊断仍待区分的理解、建立机制、练习回忆或检验迁移）：用户基础不足时先给完整示范；具备基础时可先让其预测、解释或尝试；用户明确要求完整答案或示例时直接提供。
- **材料承接与动态反馈**：选择材料从当前学习目标所需的判断和关系出发；材料超过现有基础时，用保留目标关系的完整短例，或输入、输出与责任说明承接，补足薄弱部分后回到原任务和原来的继续位置。反馈说清具体做对的部分、差距、原因依据与下一次怎样调整，把观察到的困难和对原因的推测分开处理。根据实际表现、理由、提示依赖与困难选择示范、提示、练习或解释，不机械走完固定阶梯；无新进展、缺少必要基础或现实风险上升时增加帮助或改变活动；能够独立完成后，用有意义的条件变化检查迁移。
- **四级掌握记录与 `LEARNING_STATE.md`**：
  - 只在目标需要时安排并分别记录四类表现：**帮助下完成、无提示回忆/操作、延迟保持与新情境迁移**。需要依据认知机制设计复杂讲解或学习活动时，按需读取 [学习设计参考](references/learning-design.md)。
  - 持续学习的**目标、尝试、困难、帮助程度、变式结果、下一步与复习条件**保存在学习项目的 `LEARNING_STATE.md` 或已有状态入口；跨项目可复用的结论才写入个人档案。

## 个性化、写作与个人学习档案维护

- **写作与解释参照**：按 [个人学习档案](user/学习档案.md) 中与当前用途有关的背景和长期偏好定制解释、文字与呈现。写作与文字审查使用 [writing-zh](../writing-zh/SKILL.md) 的框架与编辑方法，需要具体写法参照时从其 [样例索引](../writing-zh/samples/index.md) 选读；本地已获当前用户认可时，[《谈谈分词》](sources/数学之美第三版/谈谈分词.md) 保留为解释机制与安排实例的可选参照。
- **高保真知识整理**：对论证关系、史料与转录、缺失数据、公式或跨视图资料进行高保真整理时，按需读取 [知识组织与证据对应](references/knowledge-organization.md)；表示方法不得改变原始关系、覆盖范围或证据强度。
- **个人学习档案的授权与更新责任链**：
  - 取得当前用户跨项目维护个人学习档案的授权后才写入，用户可纠正或删除。档案只记录有来源的自述和实际表现，注明主题范围及证据；**讲过、看过或由 AI 完成作品不算用户掌握**。用户自述、帮助下完成、独立运用和迁移分开记录。
  - **更新流程**：教学负责人交回来源证据和拟更新内容，由**主 agent 核对后局部更新**个人档案。写入前重读相关记录并保留其他任务新增内容；仅更新会改变后续解释的自述、掌握证据或用户纠正，局部变化只更新受影响范围，保留证据日期、来源和下次承接方式。
  - **不可读时降级处理**：档案暂不可读时依据当前对话继续工作，**在已有项目记录权限内**保存待登记的证据和位置，并明确说明尚未更新档案。

## 图文、图片与页面交付

- **内容与媒介一起设计**：主动考虑图像、漫画、分镜、声音、对谈、视频、动画、游戏、情境故事、角色扮演、交互模拟、可操作原型、虚拟实验、地图、时间轴、数据可视化、三维场景、展览、文字与图文出版物等形式，自主选择或组合，愿意投入制作来节省用户理解时间，不把制作方便作为主要取舍依据。空间、过程、数量、分布、依赖和变化用适合的图文或交互表达，关联视图中的同一对象保持可识别；连线、位置和颜色区分组成、依赖、因果与证据支持，标题、标注、单位、假设、缺失和来源与正文、数据一致。
- **主线直达、图表替代信息与交互同步**：
  - 默认阅读路径讲清完整主线，细节可定向展开，重要失败与条件留在判断发生的位置。**视频与交互支持跳转、回看或直接取得主要结果，不让无关操作增加负担。**
  - 复杂图表的替代信息应包含完成判断所需的值、单位、尺度、关系、缺失和条件；按需使用 [frontend-design](../frontend-design/SKILL.md)、[信息可视化](../frontend-design/references/information-visualization.md) 与 [可访问交互](../frontend-design/references/accessibility-interaction.md)。
  - 交互要说明改变了哪些输入、参数或规则，并让图、数值、假设与解释同步反映；模拟与真实数据明确区分。动画或视频按实际解释作用选用，提供必要的暂停、回看和文字信息。
- **真图核验与正式素材要求**：图片与真实素材必须服务于已核实的对象或关系。查看实际成图，核对对象、数量、位置、箭头、顺序、条件与逐字文字；数据图有相应来源，模拟与真实数据明确区分。按任务读取 [视觉素材制作](../frontend-design/references/visual-production.md)，保留真实素材来源条件。需要角色或场景插画时使用可靠现成素材或图像生成，核对身份与内容，**不用临时拼画的占位图充当正式素材**。
- **页面交付、先验后替与角色分工**：
  - 制作网页或交互作品时，读取 [frontend-design](../frontend-design/SKILL.md) 的制作与验收方法（同一任务已读且仍有效时沿用）。默认交付可由文件入口直接打开的 HTML；项目明确需要后端或 HTTP 运行时则沿用项目入口。长任务已有 HTML 时沿用同一页面和查看入口，普通解释与短答不强制制作页面。
  - 作品放在所属项目的持久目录；无所属项目时使用 当前授权工作区的 `artifacts/teach-and-explain/<作品名>`，并保持主入口稳定。页面、源码和素材保持可用、可编辑；**替换已有可用页面前确认新候选及其资源可用**，工具操作由 agent 承担。
  - 教学/内容负责人确定读者、核心关系、必要条件、代表内容和阅读顺序；视觉/前端负责人实现并交回实际页面。图文或交互改变含义时由内容负责人核对。需要用户决定新风格或重要构图时，尽早展示真实样张和差异；等待期间继续独立工作，已认可且适用的风格直接沿用。
- **实际入口检查与视觉打磨**：
  - 通过真实文件或项目入口打开当前候选，在代表性面板和操作路径检查实际显示、内容、资源与交互。前端细节按 [运行体验与完成检查](../frontend-design/references/runtime-quality.md) 核验；内容变化回到整条阅读路径复查。
  - **视觉作品达到成熟成品的完成度，整体构图、字体、配色与素材协调；样张也完成其展示范围内的打磨。** 按 [视觉评审与打磨](../frontend-design/references/visual-critique.md) 查看实际尺寸的整页与关键局部，检查对齐、间距、层级、标注归属与图文一致，修正后回看相关状态；功能正常与无溢出不能单独作为视觉交付依据。

## 独立审查与规模验收

- **真实规模与阅读路径验收**：报告方法的验收覆盖正常工作规模的完整材料与阅读路径（常见情境包括五六个 agent 并行半小时以上，以及运行数小时、跨多批 agent 的会话；用于选择有代表性的真实材料，不要求人为凑人数或运行时长；片段样张只验证局部表达，不能替代完整报告验收）。核对各重要工作线、关键决定及变化、成果、失败、依赖和未决事项的去向，不能靠遗漏、泛化或隐藏重要内容获得简短。从真实成品先扫标题、突出内容和主图，核对主要结果、关键区别及影响判断的条件是否可见；再从代表性区块直接进入，完成查找、比较或解释变化的任务并追到依据。若必须逐处搜小字、记住前文或反复对照远处标注才能完成，就重新组织内容与关系，再复查受影响路径。
- **独立 `reviewer` 终审**：完整报告、教材和交互解释作品，在作者自查及**必要的**显示/操作验证后，调用独立 `reviewer` 按 [code-review](../code-review/SKILL.md) 的文档审查方式检查最终候选（与前端协作时共用一次完整审查；用户指定单 agent 时说明作者自查替代独立审查）。审查者获取读者基础、用途、要求、成品入口、原始材料和实际检查证据，覆盖事实与结论依据、组织与必要解释、文字，以及图文和交互是否保持同一含义；显示与操作结论对应实际验证证据。作者修正后按新候选证据关闭问题，只复核受影响内容与阅读路径；主 agent 核对最终版与审查结论。

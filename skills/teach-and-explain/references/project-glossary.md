# 项目词汇表

每个项目默认维护根目录的 `词汇表.html`，帮助用户准确表达已有想法，并通过浏览发现尚未想到的问题、区别与可能性。项目开始或接手时先读取已有词条；没有时使用[固定模板](../assets/glossary.html)。日常维护更新数据，沿用模板布局与交互。遵守所在项目的访问权限；根目录不明确时先辨明所属项目，不在临时子任务目录另建一份。

## 内容与对话

- 从项目用途、领域结构和专家分析问题的主要维度梳理核心概念，提前覆盖理解目标、设计选择、使用过程和判断结果所需的内容，包括尚未在对话中出现的概念。按实际领域核对覆盖缺口，随调查补齐，不以已聊词汇或固定条数限制范围，也不照抄整个学科词典。
- 收录依据是能否使用户表达得更准确、辨明重要差异或发现新的思考角度。普通标签、显而易见的词义、任务状态和内部执行规则通常留在项目资料；常见词具有值得辨明的专业含义时可以收录。陌生或技术性强本身不构成收录理由。已有项目约定确实影响交流时，说明它的局部含义。
- 按领域、主题和概念关系组织词群，先让用户看清整体，再比较邻近概念。基础概念与依赖它的概念相连，易混、相对、上下位或共同作用的概念说明具体关系，不能将同组词一概当作同义词。
- 词条以词头和一句准确、通俗的关键释义供扫读；按理解需要补充英文、别名、项目实例、用户说法与语境、区别、关联和来源。较复杂的解释逐步展开。用熟悉情境解释陌生概念，避免定义循环；专业含义拿不准时查证。一般概念、项目约定、已实现行为与假设例子区分清楚。
- 对话是主要使用方式。进入新领域、发展构想或准备重要选择时，主动解释会帮助用户形成下一步指令的概念与关系，深浅按当前需要安排；完整核心词汇可预先收录，不要求用户先读完再讨论。
- 用户表达模糊时，从当前语境出发，可同时提供几个候选及具体区别，询问真正会影响理解的差异。未经确认的说法不写成确定映射；用户原话与模型归纳能够分辨。词汇表未收录的概念也继续调查，不能把表内候选当作全部可能。
- 用户认识拓展后，允许原来的问题、词语和目标一起修正。将已有依据的概念关系补入词汇表，将需求或决定变化同步到其主要资料；词汇表不替代项目规格和过程记录。
- 对话直接解释当前所需内容，不要求用户先打开字典。网页只承担浏览、已有词条搜索和关联跳转，不把关键词匹配宣传为语义理解，也不默认接入聊天服务。

## 固定模板与维护

模板自包含，双击即可离线打开。全部词条集中在 HTML 的 `script#glossary-data` JSON 中，用户页面与 AI 读取使用同一份内容。首页按分类词典连续呈现词群，词头和关键释义直接可见，详细解释按需展开；目录、搜索和关联跳转配合使用，不输入关键词也能浏览发现。以清楚的字号、层级、对齐和紧凑分栏提高信息密度，减少装饰占位和重复标签，词条长短服从内容，窄屏顺序清楚。图像只在帮助理解具体对象或关系时使用。

数据字段和更新命令见[数据维护说明](glossary-data.md)。使用[更新脚本](../scripts/update_glossary.py)读取、校验并替换现有 HTML 的数据块，保留其他条目和稳定 ID；输入 JSON 作为更新材料，不另建一份需长期同步的词条来源。已有页面先读取后合并，不用空模板覆盖已有内容。

更新后确认词条可读取，概念、实例和关系一致；初建或改版后，从根目录入口以完整真实词条检查整体扫读、查找、关联跳转、键盘和窄屏显示。验收同时覆盖：从模糊意图找到较准确的表达，以及浏览一个主题后发现有用的新区别并能据此形成问题。AI 可以按代表性情境检查内容与路径，用户是否实际获得新认识由其反馈校准；搜索可用与排版整齐只覆盖部分结果。不要将模板样例或其他项目的用法直接当作新项目事实。

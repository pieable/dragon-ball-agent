# 验证与退出

用于建立改造验收、裁决新旧差异，以及确认旧路径可以退出。

## 固定比较依据

保存相关旧输入、初始状态、操作序列、版本与环境、原始结果及已接受要求。让“旧版观察”与“新版目标”分别可查；已有缺陷或有意改变的行为另设预期，保留不变部分的回归依据。正常工程判断在授权内完成，涉及重要体验、外部兼容或数据取舍时交回用户决定。

预期来自需求、确认样例、适用规范或独立推导。新输出不能自行成为基准；同一解析器与写出器可能带着相同错误通过自往返。差异先判定版本、输入、状态、环境、比较方式是否可比，再定位语义差异。只有影响目标判断或存在歧义的差异才需要补充裁决证据，不强求每个结果有第三方实现。

## 选择能发现目标错误的方法

| 情境 | 方法与边界 |
|---|---|
| 有可运行旧实现或冻结输出 | 行为刻画、差分测试；比较相关输出、状态和失败语义。旧新一致只支持保留行为，旧缺陷另处理 |
| 保存、切换、取消、重试等顺序影响结果 | 检查动作序列与关键中间状态；独立情境重置、同一序列保留状态。模型需来自有效要求 |
| 精确答案难取得 | 使用有领域依据的不变量或变形关系，如支持范围内的语义往返；明确前提，别把幂等/可逆当通用规律 |
| 样本较多或组合复杂 | 生成合法边界输入、缩减失败用例；只有确有覆盖收益才扩展 fuzz/状态模型 |
| 怀疑现有测试会漏问题 | 在隔离候选或替身中引入一个合理错误，检验对应检查能否捕捉；不必建立大型变异测试系统 |
| 真实运行分布影响判断 | 在副作用可隔离时做影子比较，或按授权逐步切换；防止重复写入、通知或其他外部动作 |

控制会影响比较的时间、随机、并发、依赖和资源。无法逐项确定时，按契约比较分布、区间或属性，说明容差含义；不要通过忽略字段/扩大容差掩盖实际差异。特定录制工具只覆盖其声明的环境和边界。

视觉或动画结果同时检查相关实图、状态及实际运行；保持参数、姿态、相机、时间与渲染环境可比。静态截图不能替代连续过渡和交互。工程数据字段保持也不能替代实际求值结果。

## 沿真实产物检查

根据交付用途串起适用环节：输入 → 转换 → 保存/关闭重开 → 继续编辑 → 集成 → 目标运行。局部成功后继续检查受影响的整合边界，不用“可解析/可打开/可渲染”代替约定的完整结果。某一环节失败时，保留其他已成立结果，定位第一个偏离处。

用一个真正会发生的后续修改检验维护收益：原先需同步哪些位置，新方案现在需改哪些；哪些特殊处理已消失，哪些因真实约束仍在；失败是否更容易定位。若任务仅要求兼容或搬迁，不额外强加“必须减少代码/步骤”的完成条件；按本次承诺衡量。

## 完成旧路径退出

确认旧入口/格式/脚本的直接及间接消费者去向，检查相应配置、构建、资源和使用说明。按授权移除本次已替代且确认失效的部分；跨范围旧产物保持现状并说明。不要因一个调用图无边或一次运行无调用就删除。

保留迁移所需的恢复路径至退出条件满足，再按数据和发布约束清退。旧路径仍有必要时说明保护的消费者和保留原因；双栈尚未退出则报告该阶段状态。

对象、环境或解释变化后，重验受影响的要求、组件和验收，包括间接依赖。沿用未受影响且有身份与范围依据的历史结果；字节未变并不自动使旧结果仍有效，也不必一律全量重测。

收尾在现有项目记录留下：采用的改造方式与理由、已保留及有意变化的结果、实际验证边界、旧路径去向、未解决依赖和下一动作。用户说明按任务大小报告，不为了本 Skill 额外生成长报告。

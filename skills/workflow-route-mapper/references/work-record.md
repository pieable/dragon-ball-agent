# 项目工作记录

用户需要每个项目跨会话维护、以路线图为入口的工作记录，使上下文压缩或换会话后仍能找回过去做过什么及其原因。记录的价值在于恢复理解与避免重复失误，完整会话、文件和实际证据继续作为原始来源。

## 入口与记录

项目开始时主动建立共同入口，接手时先找已有资料并恢复相关状态。下列 MD 入口用于 AI 检索和接续；面向用户的独立文档遵循全局 HTML 分工。默认约定如下：

| 位置 | 职责 |
| --- | --- |
| 根目录 `项目规格.md` | 当前目标、用途、范围、约束、设计决定与验收标准；待决定内容明确标出，决定变化后更新。历史尝试进入路线记录。 |
| 根目录 `项目路线图.md` | 项目共同入口：规格位置、路线索引与关系、当前状态、未完成任务、负责人及相关材料位置。小项目的节点记录可直接保存在这里。 |
| `docs/工作记录/` | 节点细节增多后按核心问题或交付对象分开保存尝试、结果、决定演变与证据引用；由路线图索引，按需建立。 |

已有 `SPEC.md`、设计文档、状态记录或其他等价材料时沿用，在根目录路线图或已约定的根目录入口列出对应位置和职责；不另写竞争版本，不为统一名称迁移历史文件。项目已有根目录 `AGENTS.md` 或 README 时添加入口链接，未有时无需为链接另建文件。只有已授权开展项目工作时维护这些文件；纯问答或只读调查保持只读。

最初记录实际已知的目标、未知、拟采用路线和下一步即可，计划与已发生结果分开；不等待完整设计，也不预填虚假的尝试。不同项目分别维护，同项目的相关会话共用入口。工作增多后按问题分开，保持整体关系，不按会话数强行合成一张巨图。

入口让接手者快速找到：项目目标与当前有效要求、正在推进和未完成的工作、已获得的可用结果、关键阻塞、相关路线图，以及继续行动前需要回查的依据。背景细节与历史从这里定向进入，不要求每次加载全项目历史。

每项有意义的工作在对应节点留下足以接续的记录：所解决的问题与当前假设、实际行动、观察到的结果与验证范围、产物或证据位置，以及它如何影响后续安排。用户决定、授权变化和原因假设分开。没有发生的行动不写成结果，未查明的原因保持未知。内容按实际发生填写，不把字段当作固定问卷。

尚未形成的问题、观察片段或草图可以先保存在当前路线的探索记录中，注明来源和待理解之处；不要求立即为每个想法分配独立节点。进入行动、形成决定或阶段交回时，再把相关关系、状态和材料位置组织清楚，保留原始观察与后来解释的区别。

路线图负责关系和定位，节点记录承接细节，原始材料保留查证依据。AI 记录可以按日志追加，但入口必须能按具体问题、路线和节点找到记录，并沿明确关系向上恢复前提、向下查找影响；时间顺序不能替代这些联系。已经完成但未改变方向的实现、调查或整理，同样在所属节点记录实际结果；不必都增加图节点。多次近似尝试可以在同一节点合并说明共同前提、办法差异与结果，保留区分失败原因的关键证据。失败、暂停、废弃和暂时不用的发现按其后续价值保留，概览筛选不删除底层记录。

影响多条路线的共同前提放在项目概览或规格的一个明确位置，由相关节点引用；局部工作假设放在所属节点或试验记录。换阶段或条件变化时复核其适用性；已确认的条件注明决定来源或验证范围，避免多份记录各自改写出不同前提。

## 人与 AI 的文档视图

AI 从 MD 入口读取完整记录、关系与文件索引，按需追溯技术细节和证据。给用户交付规格、路线或其他独立文档时，默认提供对应 HTML；例如根目录 `项目路线图.html` 呈现整体路线、局部关系、进展和变化，链接到同编号记录。规格已有适用展示入口时沿用，各主题也可由同一页面组织，无需给每份内部 MD 配一张页面。

HTML 按人的理解任务组织关键点之间的可见联系，MD 按 AI 的检索、执行和接续需要保留详细材料；二者共用事实来源、关系和稳定编号，在入口说明对应关系及所依据的版本。用户主要读图，人读入口以当前问题的关系图为主，沿用旧规范的关系含义，按需要调整布局与层次；节点可进入对应详情与局部，正文和全部历史按需查阅，不默认平铺在图后。完整记录不因人读取舍而丢失，也不能只给一串阶段摘要。当前决定或结果改变后，同步受影响的已交付页面；保留历史页面时明确其时间与对应版本，避免旧展示冒充当前状态。原始代码、数据和证据保持原有适用格式并由记录引用。

## 按路线恢复具体工作

路线图及其节点详情应让接手者理解这部分工作的目标、技术路线、实际尝试、结果和当前位置，再按需打开原始文件。每条路线有可搜索的字母或既有标识、名称、所解决的问题、起点和当前节点。每个节点保留明确的上游引用与关系含义，以及受其影响的后续节点；跨路线依赖也显式链接。

有意义的技术尝试记录实际采用的方法、工具或框架、关键条件与相较上次的变化，说明预期、观察结果、验证范围、采用或放弃的理由，以及对应代码、实验或报告的位置。记录足以区分做过的方法，避免只写“尝试优化”“修复失败”。近似尝试可合并，但保留不同条件和结果；具体命令、完整输出等细节引用原件。

恢复时先在路线索引定位目标路线或节点，沿明确的上游关系回到理解该工作所需的目标、决定与前提，同时读取影响当前行动的旁支证据和跨路线依赖，再查看后续修正及未完成任务。编号用于定位，不能按数字大小猜测依赖。取得行动所需上下文后继续工作，无需读遍其他无关路线。

图形保留可搜索的文本或结构化来源，图、路线索引和节点详情共享身份与事实。体量增大时可拆分局部图或提供折叠、筛选视图，始终保留项目总入口；图片或截图不作为唯一记录来源。

## 材料去向与多 agent 接续

有后续用途的文件、调查结果、决定和验证证据，由产出者登记到所属节点：位置、用途、状态或版本，以及支持哪个结果。共用背景由项目入口索引，局部产物由所属路线索引，不在总入口堆每个临时文件。已有资料只登记或引用主要来源，不为集中而复制整份内容。

主 agent 负责共同入口与跨路线决定。委派时给出项目入口、相关路线或节点、当前有效决定、必读材料及定位、交付物位置和依赖状态；执行者可沿相关关系补读并反馈缺口，不要求其遍历全部文件。独立工作各自更新所属记录，共享入口按负责人整合，写入前读取最新内容，保留其他会话的新结果。

交回时同步结果、准确产物位置、节点更新、完成依据和对下游的影响。会改变正在执行的前提、接口、范围或验收的发现及时通知受影响负责人；负责人将变化落实到共享决定与依赖工作后，下游再继续受影响部分。文件已写入不自动代表别人已经知道或采用。暂时无法写入共享记录时交回待登记材料与接续位置，由负责人补入，不能让关键事实只留在临时消息中。

## 更新时机与身份

完成一次有意义的尝试、获得新证据、用户决定改变、转入重要支线或准备交接时，及时更新对应记录与当前位置。持续时间长的工作先保存已有结果、正在处理的对象与下一步，避免所有状态只留在最后总结。中途问题保留与原任务的关系和处理后接续点；收尾核对所有已授权目标的去向。

路线节点、记录和产物使用稳定身份，同一对象在图、详情、会话引用与证据中可相互定位。优先沿用既有编号；新图按[路线图的编号与表达](route-graph.md)建立路线节点编号。编号需在所属路线文档内唯一，跨任务引用带上文档入口；同一节点的多次尝试用时间或已有版本定位。目标、阶段和行动轮次编号按任务连续性规则维护，作为路线记录索引时沿用，不另造第二套轮次。重排、改标题或调整当前视图不改变对象身份；确需更改可见编号时保留旧号到新号的对应和原入口。

同一项目有多个并行会话时，写入前读取最新状态，核对当前负责人及其他会话已完成的工作。七八个 agent 并行时同样按路线分工：执行者维护所属节点与记录，主 agent 整合共享索引和跨路线关系，避免所有人重写同一份大图或总日志。分配路线时同时确定编号归属；新增跨路线联系交清两端节点、关系理由和依据，由共同入口承接，局部记录保留可回查链接。遇到冲突先查明实际情况，不用旧摘要覆盖新进展。共享事实引用主要来源，避免各会话维护互相冲突的项目状态。

## 压缩或换会话后的恢复

从项目入口读当前目标、未完成任务、最近实质变化和下一步，再沿将要依赖的节点回查前提、决定和证据。先前做过的尝试与否决原因应能查到；继续失败办法需要说明哪项条件、证据或方法发生了变化。恢复后选出实际下一步，必要时修正当前状态，再推进工作。

摘要与实际文件、运行结果或用户新要求冲突时，回到决定性原始材料核实，按真实范围更新受影响判断。缺少记录时按[项目背景与共同理解](../../workflow-state-distiller/references/project-context-and-understanding.md)恢复；注明事件发生时间与本次补录时间，不补造当时理由。

会话定位保留可取得的会话 ID、时间及关键原文位置；文件与产物尽量指向具体路径、版本、提交或稳定页面定位，并说明它支持什么。来源已经失效时标明，不以重复摘要替代缺失证据。压缩当前摘要时保留节点、来源和未完成工作入口，不能用新摘要覆盖全部历史。

## 检查记录能否帮助接续

给用户的说明另从不熟悉历史的读者出发，检查其能否从当前图或正文看懂主要选择、成立前提、重要分叉与否决原因，知道为什么走到当前位置；缺少关系时修图或补必要内容，不要求读者先遍历完整日志。内部检索记录不因这项检查变成页面，也不把模型自查称为真实用户已理解。

检查时给没有原会话上下文的接手者一个具体问题和项目入口，让其实际搜索定位节点，沿上游找回必要前提、决定与原件，再指出下游影响、已否决路线及仍未完成的工作；不预先交给它完整答案或整段历史。核对其引用与下一步是否有据，是否必须遍历无关路线才能理解。记录应使 agent 避免重复执行已完成工作、重试未改变条件的失败路线或忘掉原任务；找不到时补齐缺失的关系与定位。此类接续检查与七八个 agent 同时写入的并发验证分开报告，不把一次检索成功说成全部协作已验证。

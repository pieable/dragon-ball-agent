# 右侧面板的运行与数据

用户希望在 Codex 聊天中下指令，由代理负责准备、启动和更新右侧面板；每个新任务不要求用户手动启动其他软件。面板是本机页面，显示同目录 `state.json` 的内容。它只能呈现代理写入的进度，不能自行推断工具进度。

## 启动

1. 在任务的合适目录准备 `state.json`。用户指定位置优先；没有项目仓库的任务可使用该任务的 `work/route-map-panel`，将运行时文件与最终交付分开。不要覆盖已有同名用户文件，先检查。
2. 将本 Skill 的 `assets/探索进度面板.html` 复制到同目录，保留文件名。已有面板先核对用途和版本，不直接覆盖无关改动。
3. 代理运行本 Skill 的 `scripts/start-panel.ps1 -StateDirectory <目录绝对路径>`，读取返回的 `url`。脚本只在 `127.0.0.1` 启动服务；同目录已有可用服务时复用。Python 不可用或启动失败时，报告具体限制并继续用聊天和文档展示路线。
4. 使用 Codex 的浏览器工具将该 URL 放在右侧。今后本任务的内容更新只改 JSON，不要求用户刷新页面。服务或 Codex 退出后，由代理按同一步骤重开。

`url` 指向本机页面，不能作为公开链接分享。脚本在同目录保存一个服务标记文件以便复用；服务只提供面板 HTML 和进度 JSON。任务完成后可保留页面供本次会话回看；跨任务历史以路线图文档为准。

## 状态数据

`version` 是数据格式版本；带阶段过程的输入使用 3，面板继续读取既有的版本 2。它不是每次内容更新的计数，与服务健康检查中的协议版本分别使用。`updatedAt` 是内容真正改变的时间，使用带时区的 ISO 8601，例如 `2026-09-28T21:00:39+08:00`。页面轮询成功只显示“已连接”，不会把检查时间冒充内容更新时间。同一内容无需改时间。下面保留版本2的完整基础字段示例：

```json
{
  "version": 2,
  "updatedAt": "2026-09-28T21:00:39+08:00",
  "goal": "让用户随时看懂当前工作和重要改道",
  "needsYou": { "required": false, "summary": "现在不需要你回答或决定什么", "question": "", "options": [], "why": "" },
  "now": { "status": "active", "doing": "正在核对右侧面板的阅读效果", "detail": "检查实际侧栏里的阅读顺序。", "since": "2026-09-28T20:55:00+08:00" },
  "next": ["根据实际截图修正", "进入下一阶段"],
  "confirmed": [{ "text": "面板已经在右侧打开并读取到进度。" }],
  "open": [{ "text": "窄侧栏里能否看清改道原因。", "how": "用 360px 宽度查看浅色和深色页面。" }],
  "pivots": [
    { "id": "p1", "title": "改为显示关键改道", "from": "只列出执行步骤", "why": "步骤解释不了为什么换路线", "to": "显示关键改道及原因", "outcome": "worked", "result": "已在实际侧栏看见原因。" }
  ]
}
```

`pivots` 按发生顺序写，页面把最新的放在上面；只记录真正改变后续路线的决定。`title` 写新方向，`from` 写旧做法，`why` 写改变依据，`to` 写新做法，`outcome` 只用 `worked`、`trying`、`failed`，`result` 写实际结果。进入旧改道记录后，原因和结果直接可见。`now.status` 可取 `active`、`waiting`、`blocked`、`complete`；只有 `active` 继续显示从 `since` 开始的耗时。需要用户决定时把 `needsYou.required` 改成 `true`，在 `question`、`why`、`options` 里写清具体问题和取舍，`now` 与 `next` 同时保持一致。完成时用 `complete`，把 `next` 设为空列表，`needsYou` 改成符合完成状态的文字；可把 `needsYou.sub` 设为 `""` 隐藏默认的“需要你时”补充语。

## 阶段过程输入

版本3沿用上述当前字段，增加 `stages`。每个阶段提供稳定的 `id`、具体 `title`、当前 `status`、含关键结果及原因的 `summary`，以及 `rounds`。阶段 ID 在本页各阶段中唯一，轮次 ID 在本页各轮次中唯一；名称和标题可以相同。阶段状态按实际工作填写；原任务有计划编号时沿用，展示分组无需另造编号。

每轮用 `id` 和 `title` 定位，按实际内容填写 `problem`（本轮问题）、`actions`（行动概述数组）、`result`（所得结果）、`reason`（选择或改道理由）、`verification`（实际检查范围）、`routeStatus`（当前是否采用）。`relations` 中的 `type`、`target`、`label` 保留与其他记录的归属外关系，如支持、反证、调整、替代和吸收。缺少对应材料的项目保持缺项，不用格式示例补造事实。

`evidence` 数组的每项包含 `label`、`summary` 和取得的 `href`。摘要说明材料支持什么、覆盖什么；地址采用可实际打开的 HTTP(S) 来源或同页稳定定位。当前面板服务只提供 HTML 和 JSON，本地其他文件的路径作为来源定位保留，不能借这个服务自动打开。教学页已经提供同页原文或独立材料入口时，链接到对应位置并实际检查。

阶段选择与检索改变查看范围，记录继续保留。进入轮次记录后，结果、理由、验证范围和路线状态直接显示，依据细节按需查看。记录锚点由原 `id` 保持稳定，更新数据后继续使用已有选择与定位。只有既有 `pivots` 时，面板保留旧改道展示；新过程已承载相同变化时，使用同一记录，避免重复填写两套事实。

每次改动后检查 JSON 可解析、上述当前字段彼此一致、时间是本次内容变更时间，并在已打开的页面上看见新内容。浏览器自动刷新的是数据，不会自动生成正确的进度内容。

# 探索路线图

## 目标与职责边界

让项目入口和过程记录共同回答：要取得什么结果、现在在哪里、关键选择为何成立、已试过什么、哪些材料改变了路线、下一步依赖什么。

- **职责分工**：[workflow-state-distiller](../workflow-state-distiller/SKILL.md) 负责理解目的、证据推断、前提检验与行动状态；[product-development](../product-development/SKILL.md) 负责产品构思与体验验证；**本 Skill 只接收负责人核对后的认识**，负责组织来源、路线联系、材料入口与阅读视图，**不代替负责人下产品/实现结论，也不凭图形整理推导事实**（发现证据缺口或矛盾时标出并交回负责人核实）。
- **授权前提**：持续项目开始时主动建入口，接手时先找已有入口；维护项目资料前确认本次工作已获授权，**纯问答、只读调查和一次性小任务不因此创建或修改路线文件**。已有规格、状态、路线图或等价入口继续作为主来源，不另建竞争副本。

## 建立共同入口与记录工作

1. **查清再建**：先查看项目已有的 `AGENTS`、README、规格、计划、路线图、状态与研究索引，明确各自职责并沿用既有名称与位置（不为套模板迁移旧资料）。确实缺少入口且需跨阶段接续时，按 [项目工作记录](references/work-record.md) 建立最小入口：
   - 根目录 `项目规格.md`：目标、范围、约束、决定与验收；
   - 根目录 `项目路线图.md`：共同入口，连接规格、路线关系、当前状态、未完成事项、负责人与材料；
   - `docs/工作记录/`：细节增多后按问题拆分存入，由路线图索引。
2. **记录口径**：开始时写清已知目标、未知、拟采用路线与下一步，**严格区分计划与已发生结果**。每项有后续用途的工作记录实际行动、观察、验证范围、产物位置及对下一步的影响；同一事实只维护一个主来源。未改变路线的有效结果写入所属节点，不为每次工具调用新增节点；代码、数据与会话保持原格式并给出定位入口。
3. **编号与关系**：维护图或路线记录时先读 [路线图的编号与表达](references/route-graph.md)。
   - 路线节点沿用 `1A`、`2B` 等编号，证据/校准/边界用 `E1`、`C1`、`B1` 等旁挂标识；编号只作稳定定位，**不代表时间、因果或依赖**，连线必须写清关系。
   - 任务执行的 `A.1.1` 轮次编号由 [workflow-state-distiller](../workflow-state-distiller/SKILL.md)（及 `AGENTS.md`）维护，本 Skill 仅沿用作索引，不另造第二套轮次。

## 恢复、分叉与并行接续

- **定向恢复**：压缩上下文、换会话或接手旧项目时，先读共同入口（目标、未完成项、最近实质变化、下一步），再沿待依赖节点**向上找前提/决定/原件，向下找后续修正与遗留**，不遍历全部历史。计划、实现、实际验证与用户结果分开记；无法恢复的历史原因保持未知，分别标明事件时间与本次补录时间。
- **表达路线演变**：
  - 放弃旧方案核心时，新方案从**最近共同判断点分叉**；
  - 保留核心只改做法时，写明保留与改变之处；局部吸收时点明吸收内容；
  - 已修复但形成重要边界的失败按价值保留（普通报错与完整日志留在原件）；“已验证成功”与“当前是否仍采用”分开记录。
- **更新时机与并行协作**：行动开始、取得新证据、用户决定改变、路线变化、重要交接、暂停、受阻或完成时更新受影响路线与摘要。多路线/多会话并行时，执行者维护所属节点，主 agent 整合共同入口与跨路线联系；**写入共享资料前先读最新状态，不用旧快照覆盖他人更新**。交回材料标明位置、用途、版本、支持结果与下游影响；改变他人前提、接口、范围或验收的发现及时通知负责人。

## 人与 AI 的阅读视图

- **双视图共用同源事实**：AI 的 MD 入口保留可检索的完整路线、关系、定位与接续信息；给用户的独立路线/规格文档默认用 HTML 直观呈现核心判断、前提、分叉与当前位置（历史细节与原件按节点进入，完整探索图作可选视图），不维护竞争副本。
- **长任务页面与过程展示**：已有持续维护的 HTML 时沿用同一页。过程不断增长、单图难以连续阅读，或用户要审视 AI 的行动与选择依据时，按 [分层展示工作过程](references/process-view.md) 组织当前摘要、阶段查找、依据详情及更新；图难渲染或阅读时调整形式与层次，保留总览、局部与来源入口。
- **右侧面板触发条件**：**仅当用户明确要求右侧持续显示、且宿主确有对应能力时**，才按 [右侧面板的运行与数据](references/sidebar-panel.md) 复用面板资产与脚本。**面板只能呈现负责人核对后写入的状态，不能自行判断代理是否取得进展。**

## 验收

- 从共同入口可找到当前目标、位置、未完成工作、负责人与下一步；规格、路线、记录、图与原件职责清楚且彼此可达。
- 从任一当前判断可沿明确关系查回前提、支持/反证、理由与下游影响；时间顺序、因果、推理支持与决定变化未混淆。
- 稳定编号可定位同一对象，分叉、修正、失败、放弃与局部吸收表达准确，图、索引与详情无冲突。
- 多会话/多执行者接续未覆盖未读更新，记录整理未冒充原始证据或代替负责人判断。
- 交付或修改视觉页面时已实际检查可读性、主要操作与来源入口；未运行或未覆盖的条件明确标为未验证。

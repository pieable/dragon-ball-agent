# 探索路线图

## 当前状态与工作过程

让用户随时看懂正在解决什么、哪些事已有依据、下一步是什么、是否需要自己决定；回看时能追溯重要转向的原因和结果。让当前模型与接手模型知道任务为什么开始、有效要求怎样形成、哪些路线已经尝试，以及当前行动依据什么。

同一个 Skill 负责两种视图：进行中的任务用简短的当前位置和必要的右侧面板；需要跨任务回看时用路线图文档保存演变。它们表达同一任务，不各自形成一套相互竞争的目标或结论。普通纠偏、偏好和任务边界的恢复由 `workflow-state-distiller` 处理；状态已清楚时直接沿用。两者都需要时，先确定当前有效状态及改变路线的证据，再更新路线图。

过程记录说明围绕什么问题开展工作、取得什么材料、怎样比较与选择、做出和验证了什么，以及结果如何影响下一步。按实际阶段和已有轮次组织，关键取舍保留简明理由与依据入口。任务负责人核对当前摘要和委派结果后更新，记录以已取得的材料、行动和观察为依据。

一次性小任务不必启动面板。任务已有持续维护的 HTML 时，把当前位置和必要的路线变化更新到同一页，沿用现有查看入口。没有已有页面而用户明确要求右侧持续显示时，按 [右侧面板的运行与数据](references/sidebar-panel.md) 启动。若宿主没有可用的右侧浏览器，就在聊天中给出同样简短的当前位置，并保存必要的回看材料。聊天里的关键判断和问题仍由任务负责人直接告诉用户。

长任务按 [分层展示工作过程](references/process-view.md) 安排当前摘要、阶段查找、可读记录和依据详情。历史增长时，通过分组、选择和检索进入相关过程；重要结果、未决事项与关键改道原因留在相关摘要中。Mermaid 用于需要看清分叉或依赖的局部关系，同一批记录也可以提供全局关系总览。与 `teach-and-explain` 协作时，在对应决定和成果旁补足概念、原因与影响。

## 主动记录与接续

当任务开始积累会影响后续行动的背景、选择或探索结果时，主动建立或更新过程记录。是否调用取决于这些信息对后续判断的作用，任务尚短但已有关键取舍时也应使用。先沿用项目已有记录和入口，内容少时用简短正文；面板和图形按实际阅读需要采用。

记录起点时写清用户要解决的问题、成果用途与必要背景，并保留当前有效要求、约束、决定及理由。继续工作、交接或恢复上下文时，先读当前摘要，再沿相关选择回查决定性材料，据此安排后续行动。被替代的决定关联到当前决定。

## 全局假设与当前假设

过程记录同时写明当前任务的全局假设和当前假设，并纳入所有未经询问而采用的假设，便于用户检查和模型接续。

- **全局假设：** 支撑整个任务目标、范围、成果用途或整体路线的前提，影响可能跨越多个阶段。放在任务概览中，后续相关选择引用同一项记录。
- **当前假设：** 支撑当前阶段、试验或下一步行动的局部前提。放在当前状态或相应选择旁，注明适用范围；阶段变化后检查是否仍适用。

每项假设写清具体内容、采用依据、当前确认状态，以及不成立会影响哪些决定或工作。区分待用户确认、待验证、已确认、已否定或已替代；已确认项注明确认者或验证证据。能查明的事实由 agent 调查，涉及用户偏好和重要取舍的前提向用户取得确认。

新证据或用户反馈改变假设时，同步更新受影响的结论、路线、当前摘要和下一步。保留改变重要判断的旧假设及修正原因，当前概览呈现仍有效的前提与尚待确认的部分。每轮交流末尾展示未经询问而采用的假设及其当前状态，相关记录与对话保持一致。没有这类假设时如实说明。

## 用户首先看到什么

侧栏首屏优先回答：现在做什么、进度内容何时更新、是否等用户行动、下一步是什么。历史路线放在其后。当前目标和当前行动各有一句清楚的话；“已确认”只写有证据的结果，“还在查”只写尚未解决的问题。当前描述只写一个正在进行的动作，下一步写它之后的动作，不重复。一个字段不要拼接几件无关的事。

每次更新这些当前字段时，作为一组核对其一致性，并记录**内容真正变化的时间**。页面成功检查文件只说明连接正常，不能当作进度刚更新。长时间没有新内容时如实显示多久未更新，不推断代理已停住。进入等待用户、暂停、完成或受阻等状态时，写清目前由谁行动。

页面文案使用用户能感知的对象、动作和结果。内部命令、配置和模型编号只有在它们影响用户判断时才出现。任务本身已有 `A.1.1` 一类编号时沿用，不再给用户增加 `1A/2B` 等第二套路线编号；界面上的普通顺序数字仅帮助定位历史。

## 什么时候改变路线

路线节点只保留会改变后续判断的内容：目标实质修正、独立候选、改变判断的证据、新边界、改道、暂停、吸收、废弃、恢复，以及当前路线和下一步。失败虽已修复，只要留下边界或否决了路线，仍保留。临时命令错误、已解决且不再影响判断的杂事和完整工具日志不进入路线。试着删掉一项：若仍能解释为什么走到当前路线，就不记录它。

把原做法放弃或替换、导致下一步不同的变化标成改道。改道记录的标题始终写**改到哪里**，正文写原做法、改变的依据或实际代价，以及新路线是否已验证。阶段摘要让重要改道及其关键原因可发现；进入对应记录后，原因、选择与结果直接可见，依据详情按需查阅。保留旧路线核心而调整方法时写“调整”；否定旧路线核心时写“改为”或“放弃”。未验证的落脚点标为待验证，不把计划写成结果。

中途接手时，只读取现有路线图和直接改变路线判断的材料，恢复能确认的路线。缺证据的部分标待确认，不为图完整而猜测历史。

## 更新与回看

在新的阶段开始、证据改变判断、改道、用户需要决定、暂停、受阻或完成时更新当前位置和受影响的路线。普通工具调用不生成新节点。操作持续很久而当前描述已经失效时，写出实际仍在做的事；宿主已明确显示运行或等待时，不为维持“新鲜”而重复无内容的更新。任何更新都要与最近给用户的进度说明相符。

需要持久回看时，过程记录写入用户指定位置或项目既有文档结构；无约定时用 `docs/workflow-state/<topic>.md`，按阶段保存可读的行动、决定、结果与来源。长任务已有 HTML 时继续用该页呈现记录，保留可编辑的记录来源。选择展示范围、证据定位和更新的方法见 [分层展示工作过程](references/process-view.md)。Mermaid 的分叉画法见 [路线图语义](references/route-graph.md)；一张图渲染失败或无法连续阅读时，保留必要的全局分叉总览，再以局部图展开。简短关系可直接用标题与图表达，图外文字补足图中未呈现的原因和条件。用户只想知道现在到哪里时，先直接回答当前位置，不让用户先打开文档。

## 验收

无论产物是 Markdown、图还是页面，都单独检查内容的易读性。按未跟随全部对话的用户视角，从当前摘要读到一次关键选择：能否说清任务为何开始、为什么走到当前路线、结果意味着什么、还需判断什么。补齐影响理解的背景与因果联系，在相关对象旁解释必要术语，去掉没有帮助的过程细节。再按接手模型视角检查，能否找到有效决定、约束、全局与当前假设及其状态、证据、已否决路线及下一步依据。用户阅读和模型接续使用同一组事实，执行细节和原始材料保留查阅入口。

用实际侧栏宽度和至少一个窄屏宽度检查浅色、深色页面。只看首屏，用户应能回答当前目标、正在做的事、已确认什么、是否轮到自己以及下一步；扫过路线，能复述每次重要改道“从哪里到哪里、为什么、结果如何”。检查更新时间反映内容变化、页面文字与当前真实任务一致；如果有交互，检查键盘可到达且操作有效。状态不能只靠颜色区分。任何尚未实际验证的条件只报告为待验证。

过程较多时，再从阶段摘要进入一次重要选择及其原始依据，核对对象、来源与验证范围；查找一次放弃或失败的旧路线，确认原因仍可找到；新增记录后检查当前摘要同步更新，原来的定位与选择仍可继续使用。按实际增长量检查导航和阅读，不因图或页面拥挤而删除仍会改变判断的记录。

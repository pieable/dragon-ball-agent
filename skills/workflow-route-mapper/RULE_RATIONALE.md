# `workflow-route-mapper` 规则理由

本文件不参与运行。

## WRM-01 路线图保存演变，当前面板展示同一任务状态

- **状态：** `current-effective`
- **行为：** 路线图保存起点、分叉、修正、失败、废弃和路线变化。进行中的右侧面板展示任务负责人已经确认的当前位置；它和聊天说明指向同一状态，不另造一套结论。任务状态散落而无法可靠决定下一步时仍由 `workflow-state-distiller` 恢复。
- **理由：** 这个 Skill 最初就是为了保存失败。失败不是毫无价值的过程：它可能暴露限制、给成功路线提供灵感，也能直接告诉后来接力的模型为什么没有选择这条路，防止在相同条件下重复无用功。当前状态和演变历史用途不同，两份都当作当前真相又会产生漂移和循环更新。
- **来源：** `SKILL.md`“目标”；Git `f6d8ab0`；2026-08-30 用户对创建目的的确认。
- **验证：** 静态边界明确；真实跨任务回看效果未系统验证。
- **改变条件：** 页面可以展示当前状态，但不能与任务负责人掌握的状态相矛盾；若项目已有等价路线档案可写入既有结构。

## WRM-02 只记录会改变后续判断的节点

- **状态：** `current-effective`
- **行为：** 目的实质修正、独立候选、改变判断的证据、新边界、路线状态和下一步进入图；已解决报错、命令失误和实现杂事不进入。
- **理由：** 路线图用于恢复为什么走到现在，并把仍能改变以后选择的失败留下来，不是聊天和日志压缩。删除后不影响路线理解、也不能为后续路线提供边界或灵感的内容才是噪声。
- **来源：** `SKILL.md`“记录什么”。
- **验证：** 规则静态明确；大型真实路线图可读性待验证。
- **改变条件：** 一个失败虽然已修复，但若形成了新边界或否决路线，仍必须保留。

## WRM-03 中途调用只恢复可确认路线

- **状态：** `current-effective`
- **行为：** 读取现有图和直接改变路线判断的材料，无法确认的内容标为待确认，不为图完整猜测历史。
- **理由：** 路线图很容易把模型的合理推断伪装成用户曾作出的决定。
- **来源：** `SKILL.md`“记录什么”；全局事实/推断/未知规则。
- **验证：** 静态规则明确。
- **改变条件：** 新证据可以补全待确认节点，但必须保留来源。

## WRM-04 用图形关系表达结构，边表达路线因果

- **状态：** `revised 2026-09-28`；原先的 `1A/2B` 用户可见编号已停用。
- **行为：** 真实分叉通过共同判断点和边表示，回退原因写在边上；证据和边界作为旁挂节点，不伪装成路线推进。任务已有 `A.1.1` 编号时沿用，不增加第二套编号。
- **理由：** 若编号按时间或把所有信息都画成主路线，用户无法看出共同判断点和分叉逻辑。
- **来源：** 原 `SKILL.md`“编号与路线”“节点与连接线”；2026-09-28 用户要求一个统一的探索路线图 Skill，并在 Codex 右侧跟随任务。
- **验证：** Mermaid 示例静态完整；用户真实阅读测试缺失。
- **改变条件：** 可以更换视觉编码，但必须在黑白/样式失效时仍能从文字读懂状态和结构。

## WRM-05 否定从共同点分叉，修正才沿原路线顺承

- **状态：** `current-effective`
- **行为：** 放弃核心的旧路线与新路线从最近共同判断点并列；保留核心只改做法/边界时顺承；失败—修复—复测只有仍属同一路线时连接。
- **理由：** 保存失败不等于把失败路线写成成功路线的必经前身。把否定路线画成新路线的前身，会误导读者认为新方案继承了旧方案全部前提，也会丢失真正的回退原因。
- **来源：** `SKILL.md`“分叉语义”。
- **验证：** 语义规则和示例完整；复杂图实际渲染待验证。
- **改变条件：** 跨路线只吸收局部时使用明确“吸收”虚线，不改成主继承边。

## WRM-06 当前视图和过程回看各有用途

- **状态：** `revised + prototype-verified 2026-10-10`；过程分层依据 A.3.1。
- **行为：** 用户要求跟随进度时，已有任务页展示当前状态与可查找的阶段过程；跨任务回看时保存可编辑记录及来源。Mermaid 承担需要看清的局部分叉或依赖，必要时提供全局关系总览；一张图无法连续阅读时用总图加少量详图。用户问当前进度时先直接回答，不要求先打开图。
- **理由：** 路线图的价值是低负担恢复全局，图外重复长文会重新增加阅读成本。
- **来源：** 原 `SKILL.md`“默认产物”“验收”；用户对视觉优先报告的长期偏好；2026-09-28 用户要求右侧实时跟随；2026-10-10 当前会话用户要求记录 AI 工作过程，并指出一图流随着工作快速增长而膨胀。A.3.1 一手依据见 `references/process-view.md`。
- **验证：** 旧侧栏原型证据保留。本轮教学介绍与六阶段过程共用真实 HTML 入口，阶段选择、同页原文、刷新保持及宽窄屏已经检查；通用面板真实 HTTP 验证见 `artifacts/workflow-route-mapper/process-view-20261010/panel-candidate/`。后续长任务继续核对实际回查和阅读反馈。
- **改变条件：** 按用户当前需要选择连续阅读、阶段定位或局部图解；图文分别承担过程、关系和必要条件，不重复同一内容。

## WRM-09 按阶段查找可读过程，再进入依据

- **状态：** `current-effective + prototype-verified 2026-10-10`。
- **行为：** 当前目标、结果与待决定先可见；过程按实际阶段及已有轮次组织，阶段摘要使关键原因和未决事项可发现。进入记录后直接读取选择理由、结果、验证与路线状态，依据详情供按需回查。分组、选择与检索改变查看范围，记录与来源继续保留。
- **理由：** 单张关系图和所有历史常显的卡片都会随过程增长，用户难以恢复当前重点。分层查找同时保留审视所需细节；重要条件继续在相关选择旁显示。
- **来源：** 2026-10-10 当前会话用户关于过程记录和一图流膨胀的表达；LangSmith 同源过程/执行记录、Carbon 折叠适用条件及 Microsoft 决策记录，见 `references/process-view.md`。
- **验证：** 实际 HTTP 下，阶段与检索、清除、键盘、浅深色及360/600px显示通过；24阶段480轮的合成材料用于导航压力检查。独立执行者从限定原始材料生成可读记录，保留调用交接结果和文件入口缺口。测试材料、报告与审查保存在上述持久目录，合成材料不作为用户真实过程。
- **改变条件：** 内容需要连续全文阅读时采用正文；多层归属需要树时按内容选择；实际回查发现关键理由持续被隐藏时调整摘要与导航。

## WRM-10 记录定位、验证与是否仍采用分别保持

- **状态：** `current-effective + prototype-verified 2026-10-10`。
- **行为：** 沿用稳定记录标识，保留归属、先后、支持或反证、调整或替代的具体含义。旧方案已验证成功而后来放弃时，两项状态分别表达。当前摘要与历史引用同一项有效结果，来源链接按实际展示服务的范围提供。
- **理由：** 用时间先后暗示因果、用单一成功/失败状态表示是否仍采用，都会丢失选择依据。显示新内容与保留过去重要判断需要同时完成；路径存在也不能说明浏览入口能够提供原件。
- **来源：** 原有 `references/route-graph.md` 的真实分叉及局部吸收；2026-10-10 过程记录需求；Microsoft 旧新决定关联及当前服务的明确路由范围。
- **验证：** 版本2输入与版本3阶段数据均实际读取；稳定锚点、验证与采用状态分别显示、JSON轮询保留选择/展开/焦点/阅读位置通过。独立审查发现滚动回跳、原ID映射碰撞和离开区域后恢复旧焦点，均已修复。最终资产定向检查覆盖中文与近似编号分别导航、旧链接兼容、改名重排后定位、区域内保持及区域外焦点不被抢回；广泛检查与最终定向检查分别注明所测版本。服务健康协议仍为2，文件开放范围保持原样。
- **改变条件：** 当前任务的已有记录足以表达这些关系时继续复用，不因模板字段而补造事实或建立竞争记录。

## WRM-07 内容更新时间与连接状态分开

- **状态：** `current-effective + prototype-verified`
- **行为：** 页面显示内容真正变化的时间；连接成功只说明数据文件可读取。当前字段成组核对，改道标题写新方向，阶段摘要使关键变化可发现，进入对应记录后原因和落脚点直接可见。完成、等待用户或受阻时停止显示进行中的计时。
- **理由：** 用户靠右侧面板判断代理是否仍在推进。把轮询时间当作进度时间，或让当前信息相互矛盾，会给出错误印象。
- **来源：** 2026-09-28 用户要求 Opus 5.5 独立判断视觉与目标适配，随后要求把它的判断原则经主 agent 整理成 Skill；用户进一步指出旧页面可能影响设计，因此让 Opus 只凭目标从空白设计，再匿名比较两版。
- **验证：** 匿名截图评审选择独立设计版为默认版，主 agent 检查浅色 529px 和深色 360px 的实际页面；新版服务已在另一个目录启动并返回页面和 JSON，同目录复用已验证。真实长任务的长期更新节奏仍待观察。
- **改变条件：** 若宿主提供可靠的内置进度时间和路线视图，可复用宿主能力而不维护本机页面。

## WRM-06A 渲染失败和路线不可连续阅读都要拆图

- **状态：** `current-effective + unverified`
- **行为：** 一张 Mermaid 无法渲染时，不继续把全部节点硬塞进同一图；保留一张表达全局分叉的总图，再用少量局部图承载细节。从起点跟到当前节点必须穿过大量无关分支、难以连续阅读时，也使用同一总图加详图结构。
- **理由：** 渲染失败说明单图已经不能作为可交付载体；路线不可连续阅读则说明即使技术上能画出来，用户也不能低负担恢复路径。两种失败原因不同，但都要求同时保住全局关系和局部可读性，不能只删节点，也不能改成长篇文字重新制造理解负担。
- **来源：** `SKILL.md`“默认产物”；用户对视觉优先和注意力成本的长期要求。
- **验证：** 静态 fallback 已明确；不同 Mermaid 宿主的复杂度上限和真实大图可读性仍待实际任务验证。
- **改变条件：** 新渲染器能够稳定显示复杂图时可以减少因技术限制产生的拆图，但仍须通过从起点到当前节点的连续阅读检查。

## WRM-08 已有长任务 HTML 时共用页面

- **状态：** `current-effective`，2026-10-04。
- **行为：** 任务已有持续维护的 HTML 时，当前位置及必要的路线变化更新到该页；无页面时才沿既有面板启动方法。路线记录与事实标准保持。
- **理由和来源：** 用户在会话 <维护记录标识> 决定一个长任务维护一份 HTML，并让 teach-and-explain 指导其编写。避免两个 Skill 为同一任务分别建立进度页。
- **承载：** SKILL.md“当前状态与工作过程”的已有页面复用条件，以及“更新与回看”；teach-and-explain/SKILL.md“页面交付条件与前端协作”。
- **验证：** 差异与引用静态核对；新规则下的长期运行行为待实际使用。

# 项目文档

建立或更新项目规格、项目 `AGENTS.md`、设计说明或进度记录时使用。目标是让用户和下一位 agent 打开文档就能知道程序现在怎样工作，而不必从开发经过里自己拼出来。

## 先按内容决定去处

动笔前把要写的内容分成下面几类，各自放到对应位置：

| 内容 | 例子 | 放在哪里 |
|---|---|---|
| 当前规格 | 程序做什么、用户怎样使用、必须保持的规则、状态文件和接口 | 项目规格文件 |
| 决定理由和已否决路线 | 为什么选这个方案；试过但放弃的做法和原因 | 规格保留当前决定及理由，路线记录保留尝试、取舍和原始依据 |
| 进度和状态 | 做到哪一步、已安装、试用中、还差什么 | 项目路线图或已有共同状态入口；链接相应PR、提交及证据 |
| 过程材料 | 核验截图、日志、候选、失败和技术尝试 | 保留支撑关键决定与结果的材料并由路线记录索引；无后续用途的临时副本按授权清理，版本优先用Git保存 |

按读者用途组织材料。给用户看的规格、说明和报告应简洁易读，帮助其掌握需求、架构与验收：软件要解决什么、主要部分怎样配合及为何这样设计、怎样判断正常工作与实际结果。普通实现细节由 AI 决定，影响这些判断时才展开；常规验证概括结果，重要缺陷和未完成事项在正文可见。代码位置、命令、详细测试和部署证据按需引用。给开发 agent 的材料保留实现、核验和接续所需的接口、状态、约束与证据。两类材料共用事实和决定；给用户的独立文档默认HTML，给AI检索和接续的记录默认MD，用户指定或用途所需格式优先，已有等价入口沿用。变化同步到受影响视图，避免重复维护。

项目 `AGENTS.md` 写给开发 agent，放工作规则和资料索引。程序运行时交给模型的提示词放在程序自己的文件里，不和开发规则混在 `AGENTS.md`。

## 规格怎样写

只写现在成立的事实：

- 规则变了，直接改写原句或删掉旧句。不写“已由 A.21 取代”“历史阶段”“旧版曾经”。查旧版本用 `git log -p`。
- 不按开发阶段编号（A.4、A.5……A.22）组织正文。按功能或使用流程组织，标题说明这一节管什么。
- 开头三五句写清：程序是什么、给谁用、主要使用流程。不在开头写“当前处于实现阶段”“已安装试用版”这类进度。

给用户看的部分：

- 按“用户做什么 → 程序做什么 → 用户看到什么”写。例如“关闭任务窗口时，后台更新一起退出；下次从桌面快捷方式打开。”
- 一句话说一件事。术语第一次出现时用一句话解释。
- 不用“未证明……”“不能仅以……”这类层层限定的写法表达规则。规则写成要做什么；确有例外时，单独写一句例外。

给 agent 的约束单独成节，可以用列表和表格：状态文件位置和格式、模块职责、必须保持的不变量、对外接口。

规格简要说明已否决路线的做法、放弃原因及重新考虑的条件；完整技术尝试、结果与否决依据保留在路线记录并可查阅。

## 工作记录怎样处理

- 沿用项目共同入口：规格保存当前要求，路线图连接路线、状态、负责人、未完成工作和证据。细节增多后按核心问题分到 `docs/工作记录/` 或已有等价目录，多 agent 各维护所属记录，由共同入口索引。
- 合并、放弃或暂停时，将有效决定落实到规格，保留有助于接续的尝试、失败、否决原因及原始依据。更新完成状态和入口，不因阶段结束而删除仍有价值的记录。
- 原始研究资料按权限和项目约定保存，保留来源定位与读取范围。规格概括当前理由，路线记录提供完整材料与技术尝试入口，避免强迫接手者从 Git 差异重建全部上下文。

## 写完后检查

1. 只读规格开头，看能不能说出程序现在做什么、怎样使用。说不出来就重写开头。
2. 在规格里搜索“取代”“历史”“阶段”“已完成”“验收中”“试用”“已部署”。逐条判断命中的句子是当前规则还是进度、历史，后两类移出。
3. 规格中文超过约 8000 字时，先检查是否混进了进度、历史或过程材料。移出后仍然过长，再按功能拆成几个文件，并在 `AGENTS.md` 里索引。
4. 用 `git status` 和 `git diff --stat` 检查新增材料：有后续用途的依据和接续记录按项目约定纳入版本管理；可再生产物和临时日志按用途忽略或清理。删除前核对引用与恢复需要，不按文件类型一律移出仓库。

## 例子

改写前：

> `A.6.3` 是历史启动方式，已由 `A.21` 取代：Windows 重启后监视器曾由登录启动文件夹独立运行……登录启动随后已按用户决定移除，当前会话入口见 `A.21`。

改写后：

> 程序从桌面“下一件事”快捷方式启动，不开机自启。关闭任务窗口时，后台更新一起退出。

“不开机自启”的原因如果对以后有用，在“决定与理由”里写一句：“2026-10-21 用户决定取消开机自启，改为需要时手动打开。”

# 状态、失败与恢复设计

新增或修改持久状态、后台任务、重试、并发写入或恢复路径时使用与当前风险相关的部分。先核实平台提供的事务、任务取消和生命周期保证，复用成立的机制。这里的检查帮助选择实现，不预设必须增加数据库、队列或调度器。

## 明确身份和状态转换

1. 确定对象和操作各自的身份及有效范围。会话内、单次步骤内或进程内唯一的标识，只能在对应范围使用。关联请求与结果时优先采用宿主明确提供的关联关系。
2. 确定权威状态由谁持有、谁可以修改，以及内存、持久文件和界面视图之间怎样同步。派生视图应能说明来源和更新时点。
3. 列出当前任务涉及的状态和转换。每项转换注明触发事件、前置条件、写入或外部副作用、成功后的状态和失败后的状态。终态是否允许重新进入由业务合同决定。
4. 写出必须一直成立的不变量。例如一个已取消任务不能发布结果，一个未完成导入不能成为当前版本。这些约束用于审查全部相关转换及其测试。

复杂流程可用转换表或状态图。只有一个简单状态变化时，直接在代码和测试中表达即可。

## 检查部分完成

沿一次操作的真实执行顺序，在会留下外部可见影响的位置检查中断后果：此时已发生什么、还缺什么、重启后凭什么判断，以及下一次执行会不会重复副作用。

根据所需保证选择机制：

- 同一事务能覆盖的状态变化由事务一并提交，使完成标记与实际数据保持一致。
- 文件替换等操作先核实当前平台的原子性和持久性边界。只有候选完整且校验通过后才发布为当前版本，目录存在本身不能证明内容完整。
- 外部副作用无法加入事务时，使用已有操作标识查询结果，或设计可恢复的分步进度。补偿动作只有在业务语义成立且有授权时采用。
- 结果暂时无法确认时保留可诊断的未知状态，再通过查询或人工决定解决。贸然重试可能重复产生不可逆效果。

恢复路径应维持同一组不变量。用中断位置和恢复后的可见结果检验恢复逻辑，不能只验证正常完成。

## 重复请求与重试

先区分暂时故障、输入或权限拒绝，以及结果未知。可重试性取决于操作语义和当前平台合同。

需要去重时，用调用者表达的操作身份识别重复执行。相同参数可能代表两次独立意图。明确去重标识的作用域、保留时间和同一标识携带不同参数时的处理。记录标识与执行副作用必须有一致性保证，否则仍可能重复执行或漏执行。

为允许重试的故障选择次数或期限、退避和停止条件，并核实 SDK 是否已有重试，避免多层重试放大负载。失败处理应能结束当前工作或安排受控的后续尝试。只有收到与该操作对应且满足合同的成功结果，才推进成功状态。

## 并发任务与生命周期

确定任务由会话、插件或其他对象持有。当所有者失效、请求被替代或用户取消时，取消能取消的工作，并撤销旧任务发布结果的资格。底层调用可能无法立即停止，因此发布前还需依据当前任务身份或版本确认结果仍然有效。

检查“读取状态—决定—写入”的间隙是否可能被其他写入者改变。按实际竞争范围选择已有锁、事务或版本条件写入，并明确冲突时的行为。单进程锁无法自动保证多进程写入安全。

验收覆盖当前合同中的代表性时序。多种操作会相互影响时，结合 `testing-methods.md` 使用操作序列与不变量检查。

## 例子：后台生成报告

用户修改资料后启动报告任务，随后再次修改或关闭工作区。要求只有当前资料对应的有效任务能发布报告。

1. 任务保留所属工作区、输入版本和自身操作身份。相同输入是否允许独立重跑，由产品要求决定。
2. 发布前确认工作区仍有效、该任务仍被认可且输入版本匹配。失效结果被丢弃，不能覆盖较新的报告。
3. 工作区关闭时通知任务取消并清理资源。即使模型或网络调用稍后才返回，发布检查仍然成立。
4. 持久化失败时保留符合合同的失败状态，结束或受控重试。若需要重启恢复，先定义哪些信息足以判断任务是否完成，再保存必要进度。
5. 检查“启动—完成”“启动—输入更新—旧结果返回”“启动—关闭—结果返回”和发布写入中断等序列，观察最终报告和存储状态。

这些步骤按当前场景裁剪。没有重启恢复要求时，不为该例引入持久任务系统。

## 方法来源

- [Amazon Builders’ Library：幂等 API 与安全重试](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)。操作身份、原子记录、迟到请求及参数冲突。
- [AWS：控制和限制重试](https://docs.aws.amazon.com/wellarchitected/2024-06-27/framework/rel_mitigate_interaction_failure_limit_retries.html)。可重试性、退避及重试限制。
- [Hypothesis：状态测试](https://hypothesis.readthedocs.io/en/latest/stateful.html)。用操作序列与不变量检查状态行为。

任务所有权、取消和文件恢复部分是面向本地插件与后台任务的工程综合。具体机制和保证仍需按实际宿主核实。

# 项目文件管理

让人和接手 agent 能找到正确的材料、继续工作并理解版本关系，让有用成果得以保留、无用产物不持续增长。管理覆盖文件的产生、使用、交付和退出，整理服务于继续工作，不为目录外观统一而改动有效结构。

## 先理解项目对象与文件流向

- 核实项目边界、目录约定、当前入口和在进行的任务。先看目录与大文件的体积、数量和用途，再深入主要占用及混乱来源；不逐个通读所有文件，也不预设几 GB 就一定异常。
- 从用户和接手者要做的事反查材料：继续编辑、运行正式成果、比较候选、追查依据、重新生成。识别谁产生文件、谁读取它、依赖哪个版本；同时检查文档入口、脚本配置和实际使用路径，避免只整理一棵看起来整齐的目录树。
- 结合项目说明、构建配置、引用、版本状态和实际使用，识别当前成果、原始资料、必要历史、可重建产物、重复副本及待查文件。时间久、名字带 old/tmp/backup、未纳入 Git 或搜索不到引用，都不能单独作为删除依据；注意动态路径、用户手动打开的成果和其他任务的引用。
- 区分人维护的资料和工具管理的依赖、缓存、帧序列等。分别观察查找负担、文件数量和占用；扫描说明符号链接、联接点及共享存储的处理口径，逻辑大小不直接等于物理占用，也不把工具内部目录数量当成人必须管理的目录数量。
- 全项目整理按对象、生产批次或工具管理区覆盖目录，先形成可核对的范围，再深入主要占用及难找材料。记录已处理、因具体用途保留和仍待核实的区域；抽样结论标明覆盖范围。旧轮次排除的范围需要结合本次授权重新判断，不能只清缓存或抽查几个大文件后称全项目完成。

## 按对象组织，让当前版本容易找到

- **按对象归属，不塞宽泛目录**：沿用项目有效结构，以人会寻找的对象和用途组织人维护区（如角色、模型、模块或报告）。新建前先查已有归属，不把不相关工作不断塞入宽泛的 `output`、`outputs` 或 `work`。
- **把命名作为检索接口**：使用项目已有的领域词汇，同一对象在文件、目录、配置和记录中保持一致称呼。名称表达对象与用途，并只加入区分相邻文件所需的阶段、变体或版本；日期、编号和哈希用于区分身份，不能独自承担含义。对需要从搜索结果、附件或交付包单独识别的文件，让文件名本身可辨认，避免必须展开整串父目录才能知道它是什么。
- **层级承载职责而非试验嵌套**：目录层级承载稳定的对象和职责关系，尝试先后及分支来源由版本记录连接，不把每次试验继续嵌套进上一轮产物。层级造成反复跳转、同类材料散落时，按用途合并或缩短入口；只加索引不能代替解决确实妨碍使用的命名和结构。
- **源码、交付与预览分开且成组维护**：同一对象的可编辑源、运行或交付文件、预览与验证材料按消费方式分开，保留它们之间的版本关系。需要一起使用的资源作为一组交付和验证，不能只移动主文件而遗漏贴图、配置、数据或引用。
- **明确“当前版本”入口并清理过时称呼**：在现有项目入口给出明确用途的当前位置（如“当前制作工程”“已验收运行版”），链接到确切版本及必要条件。多个用途可以各有当前版本，同一用途避免多个互相矛盾的“最新”；重要历史保留稳定定位，切换当前入口不覆盖仍被引用的版本。版本状态变化时核对仍在使用的其他入口和历史页中的称呼，避免旧“当前”、候选或局部验证被误认成最新正式成果，保留原始事实与当时适用范围，由统一的当前入口承接后续工作。
- **按需新建并保留固定入口**：只在目录职责、访问方式或工具隔离确有需要时新建目录；已有目录职责重叠时按实际用途和引用关系合并。工具要求的固定目录可以保留，在入口说明对应用途，不为改名迁移整个项目。沿用工具固定文件名、平台字符和路径要求，不统一强加语言、命名样式或层数上限；不强套固定树形模板，不移动框架规定位置或稳定的用户入口。沿用已有索引、路线记录、发布记录和运行元数据；一组序列或一次运行整体登记，不逐帧建说明、不为每个 agent 或小步骤复制整套文档。

## 从生产者控制增长

- 开始生成、导出或重跑前，查找有效的已有结果、同条件的在途任务、原生增量机制和缓存；复用要核对输入、工具与配置，以及结果是否完整。已有任务可以提供所需结果时协调消费，避免同时重复生成。仅凭同名或时间接近不能判定可复用，缺失关键条件时不要把旧结果当新结果。
- 通过工具的输出目录、缓存、临时目录和运行参数安排产物位置，核实实际写入及隐式删除范围；可能影响在用版本的重跑先隔离候选，完整验证后再切换。需要多轮实验时复用共享工具与输入，以必要的对象、变体或运行标识区分候选；不为每次调用复制脚本、依赖或整个工程。优先修正持续制造副本的生产方式。
- 对有后续用途、重建成本或并发风险的产物组，在已有记录中保留来源版本、生成方法、用途、使用者和保留或清理条件。能从版本控制或工具元数据取得的信息直接引用，普通短任务不另造台账。昂贵或无法可靠重建的素材、模型及数据按其实际价值保留。
- 按实际规模选择保留内容：日常验证保留足以判断结果和复现问题的材料，失败、关键对照、批准成果及仍待审查的原始证据保留相应深度。采样、压缩或转格式会改变验收能力时先核实；大量文件可按工具支持成组存储，但须验证消费端读取、随机访问和恢复，不能为减少数量破坏工作方式。
- 长批次先用代表样本核实输出规模、内容和实际消费路径，再展开；同时检查主产物、报告和辅助文件是否重复保存同一大块数据。需要共享数据时优先让各入口读取同一份，改变格式或默认输出前核实消费者并保持兼容。失败或中断的部分结果不成为当前成果。持续膨胀时追到产生它的任务、默认参数和重复消费，调整保留策略或生成方式，不只反复做同一轮删除。

## 多个 agent 共用项目目录

- 分工同时交清要修改的对象、实际写入位置、依赖版本和交付给谁；共享输入、工具与依赖尽量复用，各任务拥有可区分的写入范围。不同对象可以并行，同一对象的不同候选在各自位置完成，只有确需隔离的内容才复制。
- 消费期间保持所用输入版本稳定且可访问；输入维护者需要更新时另发版本，无法并存时协调更新与读取的先后。尤其检查分次读取的长批次和链接回共享源的工作区，避免同一批混用新旧内容或意外改写共享源。旧版本退出使用后再按清理条件回收。
- 先检查工具是否暗中写固定路径、共享缓存、锁文件或状态库。路径不同不一定已经隔离；工具不支持安全并发时使用其原生隔离机制或串行运行。共享浏览器、编辑器与其他有状态应用沿用项目负责人和交接约定。
- 同一不可可靠合并的二进制工程同一时刻由一个写入者维护，必要时用现成文件锁或项目协作机制。文本代码需要独立分支时可用 Git worktree，但它不会自动隔离绝对输出路径、共享资产和外部进程。不要为每个 agent 复制整套大素材以获得名义上的独立。
- 共享索引、配置和当前版本入口由明确的整合者更新，或采用工具已经提供的并发检查与事务机制。更新前读最新状态，核对候选基于的版本仍适用，保留他人的有效贡献；后完成的旧候选不能仅凭时间晚就覆盖新批准结果。
- 候选完整、依赖齐全并通过相应用途验证后才交付和切换入口；使用工具支持的原子替换或受控切换，避免读者看到半套成果。提交、切换或进程中断后，接手者先查实际结果和已有记录，再决定恢复或重跑。
- 清理共享材料前核对所有已知消费者及在途任务。任务结束、负责人离开、文件久未修改或没有打开句柄都不能单独证明无人再用；仍被下游、恢复过程或待审查工作依赖的材料保留。共享缓存清理须覆盖所有相关项目的引用范围。

## 整理已有文件与安全执行

- 优先复用项目、包管理器、构建工具和版本管理已有的清理及恢复机制，核实命令范围，先预览影响。重复文件用内容校验确认，再检查每个路径的用途；不因内容相同就直接移除运行所需的副本。
- 对需要删除、覆盖或迁移的已有内容，先形成具体候选：准确路径、体积、处理动作、依据和恢复方式。已明确授权的范围直接执行；仅要求盘点、含义不清或候选超出授权时，先完成调查，再集中请用户决定这些具体项。未知项保留，不阻塞其他已授权且依据充分的工作。
- 优先清除已确认无用的临时输出、失效中间产物和多余副本。有独特决定、证据或恢复价值的旧版本，保留必要部分与查阅入口；确需归档时说明用途，避免把所有待删内容搬进 archive 后宣称完成清理。
- 对历史候选按同一对象的版本与依赖关系成组判断，查明每组是否仍支持制作、对照、故障复现、回退或重要决定。保留承担这些作用的具体版本及资源闭包，核实已被替代且失去独特用途的中间副本；不把“全部工程源”“全部图片”“全部历史”整体排除，也不把它们整体列为可删。待查项写清缺少的依据，继续调查，不以笼统的“可能有用”无限保留。
- 内容去重与版本取舍分开处理。字节相同但路径承担不同读取责任时，核实共享是否仍支持独立交付、读取和回退；只有消费者调整已获授权且这些用途仍成立时，才改为复用保留本，否则保留各自需要的副本。可编辑文件不能仅为省空间改成共享硬链接，以免一处改写污染多个版本。内容不同的旧版按用途判断，不能靠哈希或文件数量决定去留。归档按对象成组，并保留能找到所需版本与恢复方式的入口。
- 执行前复核候选仍未变化、未被其他任务使用，解析准确路径及链接目标，操作限于授权范围。使用适合文件体积与环境的可恢复方式；Git 恢复范围须实际核实，未跟踪文件不能依赖 Git 恢复。回收站或隔离区仍占磁盘，不能把移动的体积计为已释放空间。
- 改名、移动或合并文件时同步相关配置、脚本、文档与资源引用；无法同步的外部引用需保留兼容入口或先形成决定。把名称变更作为接口变更核验实际消费者，不以全文替换代替动态加载和工程内引用检查。大型结构调整影响协作、发布或运行时，先给出具体影响再执行。

## 验证与日常维护

- 从实际使用任务验证可找性：让不熟悉目录的接手者按项目中的自然称呼查找源文件、可用交付和必要对照，不预先告知答案路径。检查从项目入口浏览和按对象名搜索能否选中正确版本、是否反复绕路或误开旧版，再按实际影响核验打开、资源加载、构建或运行，复查引用与目录状态。索引有链接只证明可以导航，不能证明命名易辨认、版本正确或成果可用。
- 涉及生成、缓存或并发机制变化时，按风险核对重复运行、输入变化、并行写入和中断恢复，检查是否误复用、覆盖他人贡献或发布不完整结果。使用真实生产者和消费路径，不为文件整理另造测试框架；本轮未覆盖的情境直接说明。
- 报告主要入口、处理内容、占用变化及遗留项；区分项目目录缩小、可恢复隔离与磁盘真正释放，未完成或未测得的结果直接说明。前后比较保持统计范围和口径一致，不能用两个不同任务或扫描口径推导增长速度。
- 后续工作复用既有目录与文档，任务收尾清理本次已失去用途且不被其他工作依赖的临时产物。确需保留的备份、中间文件和证据注明用途及清理条件，尽量利用已有恢复机制，不为每个小步骤复制完整项目，也不把大批过程文件留在根目录。
- 本次清理记录保持紧凑，沿用已有维护入口；不额外生成多份重复报告、备份包和新的目录体系。日常维护只处理本任务明确产生且不再需要的内容，跨任务旧文件按上述调查与授权处理。

需要为持续生成、大素材或多人协作选择机制时，查阅 [专业方法与工具](references/methods-and-tools.md)。按已有生态和真实缺口采用，不因本 Skill 列出某个工具就安装或迁移。

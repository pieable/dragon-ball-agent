# 真实任务中的行为验证

用于判断一项提示词或 Skill 改动是否改变了模型的实际工作。普通文字纠错按风险完成必要核对；会改变工作流程、结果或权限判断的修改，选择能暴露差异的任务验证。

## 先确定要观察什么

从用户要求和已知失败中写出可观察的成功条件，以及什么结果会推翻改进判断。能由文件、程序、运行结果或外部证据直接检查的部分，优先用这些依据判断。涉及表达、取舍或设计质量的部分，给评审者明确标准和原始材料。

验证开始前固定条件，保留原有任务要求。待测结果暴露评分标准的歧义时，说明修订依据，对受影响的所有版本重新检查。

## 按正常使用方式交给模型

给待测模型自然的用户请求、实际使用时可见的资料和正常权限。通过目标宿主会使用的方式提供待测提示词或 Skill。不要额外提醒它“这是测试”、列出正在考察的规则，或要求它逐项自报调用了哪些能力。路径、标签和上下文不附带候选优劣或评测身份提示，任务本来需要的信息继续保留。

比较两个提示词版本时，使用同一请求和相同的输入数据，隔离工作目录与可变状态，保持模型、推理设置、工具权限和起始环境可比。若模型或环境本身也是研究因素，单独标明，避免把多项变化归因于提示词。根据结果波动和决定的重要性安排必要重复，不预设统一轮数。

## 从实际结果核对行为

检查模型真正读取的材料、调用的工具、产生的改动与最终结果，将每项成功条件对应到可查证据。只读取本次授权任务的记录。需要运行产物才能判断的主张，按该任务的正常验收方法验证。

需要独立评审时，给评审者匿名标签的产物、相同评分依据及必要原始材料，隐藏模型名称、提示词版本优劣和作者预期。评审者指出事实依据，负责人亲自核对决定性产物与记录，处理分歧。可运行检查未通过时，模型评分或多数同意不能替代通过证据。

记录每个版本实际完成与未完成的行为、关键差异、比较条件和证据入口。未加载待测指令、环境失败、未执行和正常任务失败分别记录。对当前案例有改善的结论限定到已观察范围，进一步推广时使用未参与修改的新案例核对。

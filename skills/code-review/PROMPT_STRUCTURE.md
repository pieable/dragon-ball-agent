## 2026-09-15 修订对应

评审合同新增结果、生产路径、不变量、反例和门槛。跨组件或外部边界的结果需要逐项追踪实现与证据，检查遗漏、部分完成、相反实现、未经确认增加、所有可执行入口和拒绝路径，以及门槛是否被实现者弱化。规格变化时核对受影响的计划、实现合同、测试和证据；未执行、报错、待定或跳过的检查不算通过；候选变化使旧证据失效时补验受影响范围。

接口功能块明确显示层限制不能代替权威服务边界，最终输出功能块补充共享预算所有者和组合结果。现有兜底专项审查、三态结论、按风险裁剪和只读权限不变。

`evals/review-convergence.json` 使用含真实规格偏差的候选分别评测遗漏、部分完成、相反实现和未经确认增加；它不参与普通运行，也不把复述术语当作行为通过。

## 骨架正文

评审判断当前候选能否在约定范围内安全合入或交付。结论只覆盖该候选与合同，不替代用户整个任务的完成判断，也不重新决定产品目标。

先确认基线、候选、差异、应产生的结果、已接受约束与已有证据。沿会改变结论的项目规则、实现和调用关系恢复合同。缺少决定性材料时补足或给出证据不足，不能猜测作者意图。

先判断需求、设计与系统集成是否成立，再根据真实后果深入局部风险。检查遗漏、相反行为和未经要求的范围增加。审查深度与变更风险相称，只读取判断所需的周边范围。

先判断正确性、必需行为、数据保护、权限和生命周期是否受到影响，再考虑维护与风格。风险由真实变更产生，具体检查随证据调整，不按固定类别凑齐意见。检查新增复杂度是否有当前需求或可靠证据支持，既有保护是否仍然成立。

独立核验证据是否对应当前候选，以及测试能否捕获目标错误。要求和真实接口决定预期，作者自述不替代证据。涉及真实宿主、界面、外部依赖或模型行为的声明，需要相应运行证据。

依据事实、实际影响和证据充分程度给出“可合入”“要求修改”或“证据不足”。没有发现问题不等于证据充分。只报告候选引入或暴露、作者可纠正且影响本次交付的问题，区分阻塞问题与非阻塞建议。

报告先给结论和范围，再按严重程度说明发现。每项发现给出准确位置、触发条件或证据、影响及需要纠正的机制。即使无阻塞问题，也说明验证依据、限制和未验证路径。候选变化使结论可能失效时，只复审受影响范围。

每次评审单列兜底路径审查结果，无发现时也明确说明。技术事实、项目规则和可复现证据高于个人偏好。纯风格意见、无实际影响的推测和无关旧问题不阻塞交付，可靠质量门禁已完全覆盖的机械问题不重复报告。

只读审查不修改代码或提供补丁。授权开发中的自查可以在原范围内修复并验证，但不能称为独立评审。阻塞发现必须经修复、技术证据反驳或用户明确改变要求处理，不得静默略过。

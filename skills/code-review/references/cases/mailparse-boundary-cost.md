# 子串搜索与行首过滤组合的高成本

记录时点：2026-10-14。Issue于当日创建，仍开放。

mailparse先寻找MIME boundary子串，再判断命中位置是否在行首。长重复或近似匹配输入会导致大量比较，命中后被行首条件拒绝，又从相邻位置继续搜索。报告者给出输入与耗时对照：改进内部子串搜索后，外层搜索与拒绝循环仍能造成极慢解析。

维护者追问是否为近期性能PR引入；报告者查看旧实现后认为问题早已存在，最早引入尚未确认。输出等价及普通样本加速，没有覆盖这种输入形状。记录时没有修复。

用于检查组合算法的最坏成本。报告中提出的长度限制和线性搜索是待决定方案，应用到当前项目时需依据实际合同与兼容条件判断。

来源：[issue #148](https://github.com/staktrace/mailparse/issues/148)、[相邻性能PR #143](https://github.com/staktrace/mailparse/pull/143)。

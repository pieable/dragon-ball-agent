# 接口、配置、权限与集成

当变更影响公共行为、配置、权限、消费者或发布入口时，同时核对提供方、权威边界和实际使用路径。

**接口、配置或权限：** 同时追踪提供方与所有调用方。确认默认值和公开能力有当前消费者或明确合同支撑，并沿拒绝路径检查所有可执行入口。显示层限制不能代替权威服务边界。

**加载、注册、CLI 或外部集成：** 关注实际发布入口，而不是只测试手工组装的函数。检查导出、配置、注册和失败诊断。

追踪默认值、特性开关、环境变量、旧状态和升级路径怎样改变可达行为。原来很少触发的实现成为默认路径时，核对它原有的消费者和环境假设。调用方、插件、下游依赖、实际安装包或发布配置没有出现在diff中，仍按影响检查其兼容性。

对拒绝和权限路径，恢复主体、对象、操作和授权的真实合同，核对每个入口执行的权威检查。用户预期、作者解释和已确认产品决定分别取证，再判断候选是否违反当前要求。

验证工具分别覆盖解析、类型、链接、加载和真实操作。按声明需要观察消费者实际经过的边界，以及它得到的结果和失败诊断。

## 协议、配置与交付边界

字段、枚举、默认值、版本头、消息或分页改变时，完整读取[接口、数据与版本演进](../../../code-development/references/contracts-and-data-evolution.md)。核对候选是否把缺失/null/显式零值合并，是否复用字段号或枚举值，是否在 JSON/字段复制中丢失未知数据，以及是否只验证了一个兼容方向。对分页检查空页续页、游标方向、唯一排序和快照承诺，不能由返回数量推断列表完整。

构建、依赖或发布入口改变时，完整读取[构建与发布](../../../code-development/references/build-and-release.md)。从实际产物检查导出/条件入口、entry points/SPI、生成客户端、数据文件、原生库和工具链，核对普通安装、下游链接与首次加载。测试源码树、editable 安装或类型检查各自只覆盖对应层。

删除、改名或退出对象时，同时读取[间接依赖与退出](dependency-and-retirement.md)，把控制面关系、动态名称和跨服务读者纳入实际影响。

## 权限与信任边界

变更影响身份、租户、授权、缓存、文件/归档、出站请求、解析或命令时，完整读取[权限与信任边界](../../../code-development/references/trust-boundaries.md)。用当前候选核对以下具体连接：

- 资源 ID 从哪一入口取得，父子归属和 tenant 是否在最终读/写/删除处验证。批量/后台/CLI 是否绕过同一合同。
- 对象授权之后，DTO 自动绑定和序列化是否暴露或允许写入内部属性。实际数据库角色是否绕过 RLS，多条 permissive 策略是否 OR 扩大范围。
- JWT 除签名外是否验证实际 issuer/audience/type 与算法，委托身份是否来自受信来源，取钥 URL 和 key ID 是否引入新解释器/网络边界。
- 每层缓存的 key 与实际权限/表示是否一致，撤权/对象转移后是否仍返回旧授权或另一主体的响应。
- 路径规范化后实际打开的对象是否仍在授权根内，符号链接/归档前序成员/检查后替换是否改变落点。
- URL 校验、DNS、重定向、代理和重试最后连接的目标是否同样获准。用本地模拟目标观察实际连接，保持 Host/SNI/证书校验。
- 不受信内容是否进入对象构造型解析、SQL 标识符或 shell 字符串。参数化值与标识符/命令构造分别检查，错误和诊断路径是否复制凭证或可注入日志。

这些检查由当前变更触及的边界触发，具体框架默认保护与版本从实际实现取证。有事实和触发条件的合同违反才形成问题；专项审计不因出现一个相关名词而自动扩展。

需要本包正确但下游链接失败的具体对照时，查看[Tauri构建案例](../cases/tauri-downstream-link.md)。

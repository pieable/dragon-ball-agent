# 持久化与恢复

当保存、替换、删除、迁移或多步提交影响已有数据、可见状态或重新加载时，沿操作次序检查。

确定每个阶段正在使用的对象、路径和权威状态，以及完成后必须能读回的结果。逐个检查失败、取消或中断发生后留下什么：原数据是否仍可用，部分新结果是否被发布，备份和临时内容能否由实际入口恢复。只在合同和平台保证成立的位置认定操作已经提交。

对象、路径或inode发生更换后，核对先前算出的校验、缓存、块匹配和进度是否仍适用。删除关系时追踪对象及其其他可见入口；判断递归清理是否遗漏依赖对象，或误删共享及无关对象。恢复和重试检查从留下的实际状态继续执行，不能只从干净状态测试。

进程终止、掉电、并发修改和普通错误返回覆盖不同条件，按本次风险选择证据。报告准确说明测试发生在哪个操作点、覆盖哪类失败，以及再次读取验证了什么。

## 存量格式和在线迁移

变更涉及 schema、单位、身份、默认值或存量数据时，完整读取[接口与数据演进](../../../code-development/references/contracts-and-data-evolution.md)中的生产者/消费者与迁移方法，按候选核对：

- **混合版本读写：** 用旧写新读、新写旧读、旧消息回放及回滚后的旧读器检查字段、枚举、presence 和数值/时间单位。原标识和幂等键是否跨迁移保持，需要从旧样本逐项对照。
- **旧进程仍在运行：** 读取 ORM/schema/default 缓存、后台任务和部署顺序，确认删列、改名及默认值变更不会让旧进程生成不再合法或含义不同的 SQL。
- **回填与在线写冲突：** 在回填读后、写前插入正常更新，检查新值是否被旧快照覆盖，游标/进度是否与已提交数据对应。
- **锁、表重写与空间：** 查实际 DDL 与目标数据库版本，核对长事务、锁等待队列、扫描、重写、复制延迟及临时空间。`CONCURRENTLY`、`NOT VALID` 等选项分别核对其保证与未覆盖阶段。
- **中断残留：** 检查 INVALID 索引、部分回填、完成标记和数据库隐式提交，恢复从实际留下状态开始。迁移脚本退出或 down 执行成功不足以证明业务数据可恢复。

以上判断对照参考中 PostgreSQL、MySQL、GitLab 等一手来源及项目实际实现。正式数据操作仍遵守授权范围，评审取证优先用只读材料与隔离副本。

需要具体中断窗口及证据区分时，查看[rclone配置保存案例](../cases/rclone-config-save.md)。一次性输入失败前已创建数据库对象的情形，见[sqlite-utils案例](../cases/sqlite-iterable.md)。

# 持久化与恢复

当保存、替换、删除、迁移或多步提交影响已有数据、可见状态或重新加载时，沿操作次序检查。

确定每个阶段正在使用的对象、路径和权威状态，以及完成后必须能读回的结果。逐个检查失败、取消或中断发生后留下什么：原数据是否仍可用，部分新结果是否被发布，备份和临时内容能否由实际入口恢复。只在合同和平台保证成立的位置认定操作已经提交。

对象、路径或inode发生更换后，核对先前算出的校验、缓存、块匹配和进度是否仍适用。删除关系时追踪对象及其其他可见入口；判断递归清理是否遗漏依赖对象，或误删共享及无关对象。恢复和重试检查从留下的实际状态继续执行，不能只从干净状态测试。

进程终止、掉电、并发修改和普通错误返回覆盖不同条件，按本次风险选择证据。报告准确说明测试发生在哪个操作点、覆盖哪类失败，以及再次读取验证了什么。

需要具体中断窗口及证据区分时，查看[rclone配置保存案例](../cases/rclone-config-save.md)。一次性输入失败前已创建数据库对象的情形，见[sqlite-utils案例](../cases/sqlite-iterable.md)。

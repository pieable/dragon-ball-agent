# 输入与跨层表示

当输入的使用方式、编码、规范化、数值宽度、对象布局或跨语言边界改变时，沿完整转换与消费过程检查。

按接口允许的输入形状追踪使用语义，包括是否可重复遍历、是否借用、何时被消耗，以及错误发生前已执行的副作用。多个消费者或分支复用同一输入时，核对它们取得的数据是否仍符合合同。

同一对象在创建、存储、列表、查找、读取和删除中应保持可对应的身份。比较不同大小、阈值、平台或重试路径使用的编码与规范化规则，确认往返操作能定位原对象。

跨语言接口核对参数宽度、符号、长度单位、终止约定和所有权。类型转换改变特殊值含义时，继续检查接收方实际执行的分支。证明或静态类型成立后，还要追踪运行时表示、共享、读取和释放是否使用相同布局。

## 对照原始输入和最终消费值

| 涉及的变化 | 具体核对材料与反例 |
|---|---|
| 默认值和更新语义 | 分别输入字段缺失、null、false、0、空串/数组，检查 parser/DTO/schema 到实际业务分支，查 `x or default`、`||` 等合并合法零值的表达式 |
| 数值与时间单位 | 对照原始字节、数据库类型、秒/毫秒和接收类型，用大整数、符号边界与历史数据走实际往返，不能只看格式成功解析 |
| JSON 多解析器 | 提交冲突重复键，比较网关、签名校验和执行端的最终值。解析后对象不能证明原始报文无重复键 |
| 文本截断和身份规范化 | 用非 BMP 字符、组合字符、大小写/编码差异跨过截断点，再查找/读取原对象。核对字节、代码单元、码点与平台路径规则 |
| 一次性输入 | 将 iterator、stream 或借用 buffer 交给连续消费者，核对先前遍历/释放是否让后续读取为空或变值，并观察失败前的副作用 |
| 集合边界 | 检查空页但有续页、相同排序值跨页、并发改动、聚合空集/null、`NOT IN` 含 null，以及 map 遍历中增删 |
| 时间与期限 | 注入墙钟跳变、夏令时重复/不存在时刻，检查单调时钟差值、持久期限、时区标签与实际换算是否保持合同 |

表示、分页/集合与时钟的详细取证和来源见[接口、数据与版本演进](../../../code-development/references/contracts-and-data-evolution.md)。本专题只把实际输入差异会改变当前候选结果的情况列为问题，语言或平台有明确不同保证时以其实际版本为准。

需要合法Iterable被重复消耗与失败残留的具体例子时，查看[sqlite-utils案例](../cases/sqlite-iterable.md)。

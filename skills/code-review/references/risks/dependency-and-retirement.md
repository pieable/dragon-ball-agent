# 间接依赖与退出变更

候选删除、改名、常量化、移除配置/开关/实验/层或退出旧路径时，先明确它究竟简化了哪个调用点、删除了哪个分支/公开符号/远端对象，以及必须保持的生产行为。

完整读取[间接依赖发现与安全退出](../../../code-development/references/dependency-discovery-and-retirement.md)的方法，并将下列核对用于当前候选：

| 候选依赖的主张 | 独立核对材料与动作 | 会改变结论的证据 |
|---|---|---|
| “没有引用” | 同时追符号、枚举/常量值、import/export 别名、wrapper、schema 和动态参数来源；从入口与清单反查目标 | 运行时拼接、反射、DI、插件/SPI、生成物或跨服务读者仍能到达它，或者工具有未解析/未扫描范围 |
| “已经常量化” | 读取相关生产项目、区域、条件/override/segment 与 SDK 实际版本，核对控制面依赖图及缺失/初始化/缓存路径 | 默认值与最终生产值不一致，其他配置依赖它，或替换后某条已约定失败/恢复路径改变 |
| “只是无副作用检查” | 阅读 wrapper 和 SDK 到返回位置，追曝光、审计、初始化、注册、刷新和指标消费者 | 删除调用同时移除合同要求的副作用，替代行为没有接入原使用者 |
| “永久或低频对象可删” | 查操作手册、事故/变更记录、当前负责人和有效决定，核对 killswitch、回滚、容量保护等职责 | 当前运行值稳定但运维职责仍需保留，或需要用户决定退出该能力 |
| “收益很大” | 读取实际调用量、profile 栈、采样/聚合和窗口，区分自身与含子调用成本 | 同一 CPU 展开成本被重复归因，测量未覆盖工作负载，或只有删除行数没有运行成本证据 |
| “审计已全部完成” | 将候选报告与所有相关项目/清单、引用常量和未求值动态名称对账，检查分页及别名 | 有未核对对象、外部消费者或生产环境却被写成全量完成 |

用实际反例核对保留与移除的行为，源码能证明的确定性事实直接读取。跨配置、外部消费者和运行职责依赖相应原始证据。将共享 wrapper、常量或控制面依赖作为关联问题核对，不能因为修改被分到不同文件/所有者而拆散共同前提。

问题报告说明具体退出动作、受影响消费者/条件、实际后果及决定性证据。缺少能决定安全退出的事实时按 Skill 的“证据不足”处理。未授权修改在线配置或服务时保持只读。

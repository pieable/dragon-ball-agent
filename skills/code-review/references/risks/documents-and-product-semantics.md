# 文档、可见语义与维护资料

变更影响使用说明、进度、维护依据、产品文案或用户理解对象时，按其用途和实际结果检查。文档核查方法见[Skill的文档专章](../../SKILL.md#文档正确性与进度同步)。

**项目可接续资料：** 未来正确修改依赖无法从代码和测试恢复的稳定信息时，检查项目权威资料是否能够被后续任务找到，并且与最终实现一致。缺失或失真会误导维护时作为问题报告。普通局部改动不要求为形式新增文档，任务流水也不充当项目资料。

**文档和可见文字：** 核对配置、默认值、错误、事件和公共行为是否同步。相关文档按“文档正确性与进度同步”章节检查。逐项判断可见文字是否帮助使用者识别状态、作出判断或采取行动，避免把提示词、需求理由、验收解释、设计自述或实现辩护当作产品内容。产品语义需要由结构和行为保持时，不要求把合同原句显示出来。

复用组件、提示或文案时，核对不同对象的含义、状态和操作是否相同。测试只检查某个key、标记或截图局部时，确认它能发现使用者获得的语义差异。

已知差异、作者提出的延期和合同负责人接受的取舍分别记录。先核对当前有效要求，再判断它是否影响交付；后续issue出现不能单独证明此前未识别问题。

需要区分本月回归、AI批准和作者已披露取舍的具体例子时，查看[OpenHands文案案例](../cases/openhands-profile-wording.md)。

# 组合预算、输出与计算成本

数据、配置、模型产物或算法改变最终占用、输出大小和处理成本时，沿组合后的实际结果检查。

**边界与输出：** 对长度、字节数、批量、异常输入、共享预算和包装层，检查限制是否由明确所有者在最终组合、发出或保存的完整结果上执行。

恢复预算涵盖的对象、单位、所有者和执行位置。追踪同时存活的组件、分配顺序、临时空间、缓存和最终包装；数据或配置变化即使没有改算法代码，也可能使原分配假设失效。分别满足局部限制后，仍检查组合结果的完整约束。

对解析、搜索和多层过滤，比较输入规模、近似匹配、重复内容及拒绝后重试的实际成本。结果等价、普通样本变快和最坏成本受到控制分别需要证据。需要限制输入时，依据合同、标准或已核实资源条件判断范围，并检查兼容影响；普通示例值不能自动成为产品限制。

候选依赖性能数字时，核对基线与候选是否处理相同的实际工作负载，并检查双方配置、有效完成量、错误、缓存或跳过的工作、预热、测量工具开销和环境噪声。运行次数与结果波动应足以判断差异是否稳定，不设固定轮数。核对瓶颈或加速原因时，读取 profile 或运行计数器并对应到代码路径。区分已测得的数值、已支持的原因和原因未知；关键测量条件缺失时，不采纳相应收益结论。声明用户体验变快时，还要检查完整用户路径上的收益，局部基准不能代替端到端结果。

需要数据扩张激活旧预算次序的具体例子时，查看[Strata显存案例](../cases/strata-draft-budget.md)。需要语义等价但组合搜索成本很高的例子时，查看[mailparse案例](../cases/mailparse-boundary-cost.md)。

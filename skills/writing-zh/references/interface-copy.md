# 界面中的文字

用于报告页面和操作界面中的标题、标签、控件、状态、图注与帮助。把文字放回实际位置和使用过程判断；源码盘点用于找全内容，实际页面用于核对显示和行为。

## 让读者找到内容，让使用者知道后果

报告标题直接表达具体主题、问题或有依据的结论。单独扫标题应能区分各部分；标题的范围要得到正文支持，主标题须覆盖整份作品的实际对象与范围，各层标题与所辖内容相称。避免“先看……”式领读标题，正文中有作用的过渡与教学引导按用途保留。操作步骤使用真实动作，必要顺序直接表达。

按钮写清动作与必要对象，链接和折叠入口让人判断将看到什么。字段标签持续可见，选项按真实差异命名。已有布局、标题或控件能解释的信息不再另加副标题和提示；分组本身含混时重组内容，不能靠堆叠说明补救。

制作时直接组织这些对象与操作，不先铺设眉题、标题、副标题、说明、脚注等文字槽位。要添加一块辅助文字，先明确它提供的独有信息及当前用途；布局与反馈已经表达的内容不再复述。页面的使用方法优先由清楚的控件和操作结果表达，制作、维护与检查说明保存在工作记录。作品本身讨论这些方法时，保留作为主题内容的论证，不把它与界面自我说明混为一谈。

## 在判断发生的位置给足信息

会改变结论或操作选择的条件就地可见，包括实际完成程度、费用、作用范围和不可逆后果。详细依据与少数人需要的帮助可按需展开，主线理解不依赖逐个打开折叠区。需要同时比较的信息并列呈现，避免让读者切换多个面板后凭记忆比对。

文字的突出程度匹配其作用；小字不能承担纠正大标题的责任。图的标注、单位、图例和限制靠近对应对象，让图可以被准确理解。图注补充图中缺少的必要信息，不再完整复述图与正文。

## 文案与真实状态一致

等待、成功与失败分别说明正在发生、已经完成和仍需处理的事。错误信息交代可理解的原因及可用的继续路径，不把未确认的原因写成事实；保留输入的承诺与真实行为一致。空状态区分尚无内容、无匹配结果、权限不足和服务故障。

完整界面检查所有可见文字与辅助技术名称；局部修改检查相关文字、邻近内容及关联状态。按正常路径查看折叠、切换、错误、插值、翻译和窄屏截断等受影响显示，核对文字与实际操作后果。整合或实现新增的文案也接受同样检查。

报告以扫读、跳入局部和按需深入核对阅读效果，操作界面沿任务核对含义与后果。与前端负责人共同处理显示及行为问题，具体发现和复查沿用当前任务记录，无需额外生成一份逐项自证报告。

## 最终对抗性文案审查

对最终候选采取严格的反证立场：逐块质疑可见文字为什么必须存在，尤其是次级标题、小字、眉题、图注、提示、页尾说明及切换后新增的文字。审查实际位置与状态，不能只检查是否有这些形式，也不能因未发现错字或内容属实就放行。

保留理由必须具体：这块文字帮助用户作哪项判断或行动；删除后会产生什么可观察的误解或缺失；已有标题、布局、控件与反馈是否已承担同一作用。没有独有作用的重复说明删除；分组或反馈缺失则修正界面；只有查证或少数情境需要的内容移入准确的按需入口。不能用“帮助理解”“更完整”“用户可能需要”代替依据，也不把需要的文字机械改成图标、悬浮提示或折叠项。

删减同时核查后果：必要名称、实际状态、因果边理由、费用与作用范围、异常原因、不可逆后果及可访问性语义仍须清楚；会改变当前判断的条件不能为了画面简洁而藏起来。严格性体现在检验作用与反例，不在字数配额或全部删掉辅助文字。

把该项并入成品的最后一次独立评审。一次交清用户任务、有效要求、完整候选、代表性状态和原始依据，不先用作者的设计辩解引导评审。评审者独立检查后集中交回明确位置、原文、问题与依据，并对被质疑但必须保留的项目给出具体理由；无需逐词登记所有正常正文。期间不频繁与主 agent 交换零散意见，真正阻断审查的问题除外。主 agent 集中处理，以实际用途和证据回应保留项；修正后只复核改动及受影响部分。最终判断依据成品，不以双方达成一致作为证明。

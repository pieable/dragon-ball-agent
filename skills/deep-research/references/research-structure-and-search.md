# 研究结构与搜索方法

用于研究怎样做成一个东西、改进流程、理解陌生问题，或从已有搜索跳出单一领域。根据当前未知选择入口，已有可靠认识直接承接。

## 用要形成的判断组织研究

科学研究主要形成可由证据检验的认识；工程与设计还要形成在具体约束下有效的方案。一个任务可以同时需要两者。以下结构是为搜索组织综合的工作提示，依据见文末；不是某套标准的原样阶段表。

| 当前要弄清什么 | 值得搜索的材料与问题 | 怎样影响后续工作 |
| --- | --- | --- |
| 问题与目标：为谁解决什么，怎样算改善 | 实际使用情境、原始工作记录、需求与失败案例、现有流程和衡量方式 | 确定边界与成功依据；发现用户原先没说出的必要环节 |
| 解释与机制：困难为什么发生，有哪些竞争解释 | 领域理论、原始研究、机制模型、反例和能够区分原因的数据 | 形成待检验的解释，明确哪些条件可能改变结果 |
| 方法与方案：可以通过什么方式达到目标 | 专业方法、替代机制、同类方案、其他行业的对应问题、设计权衡 | 形成实质不同的路线，比较各自依赖与代价 |
| 实施与集成：方法怎样在当前环境中实现 | 实验协议、操作手册、源码、样例、接口、材料与设备要求、运行和维护记录 | 判断所需输入、顺序、参数、能力和资源，暴露落地缺口 |
| 检验与反馈：结果是否支持主张或满足用途 | 对照与基准、测试方法、测量误差、真实任务结果、失败和复现材料 | 接受、修正或淘汰解释与方案，必要时回到问题定义 |

验证依据从起点参与设计。工程中分别检查是否符合规格，以及在真实情境中是否满足使用目标；科学解释需要能区分竞争解释的证据，描述性或探索性研究不必先编出假设。查询、访谈、观察、数据分析与试验各有用途，网上文献不能替代当前任务所需的实际观察。

这张表可应用于整体工作，也可递归应用于某个困难环节。实践细节随方案需要深入，不另设为所有项目必须走到的固定终点。每条重要路线至少能够说明当前未知、所需证据及证据将影响什么判断；记录详略服从任务，不要求固定表格。

## 从具体情境找到其他领域的相同问题

先用当前领域的工作流和案例确认真正的困难，再抽取目标、输入输出、关键关系、约束与失败方式。保留会改变解法的条件，临时去掉品牌、行业名和偶然外观。问哪些领域也必须处理这种关系，并查它们实际使用的术语和方法。

同一对象可按目的寻找不同机制，也可按机制寻找不同用途。前者扩大方案空间，后者帮助发现机制的适用条件。领域距离不是价值指标：近邻案例便于迁移，远领域可能揭示新思路，最终依据机制与约束判断。

真实研究参照：SOLVENT 将论文分开描述背景、具体目的、机制和发现，由此在创意筛选与众包劳动平台之间找到“通过社区来筛选对象”的共同关系。可借用这种分开表示的办法发现术语不同的材料；解释性研究或不同层次的问题可能需要别的对应关系，不能强行套用目的与机制两个槽位。

例如，假设一个制作流程的困难是“上游素材修改后，下游多处需要同步返工”，可暂时提炼为“依赖关系中的变更传播与一致性维护”：

| 搜索方向 | 可试用的术语或查询 | 需要继续核验的内容 |
| --- | --- | --- |
| 当前行业 | 当前工具名 + 素材更新 / 依赖 / 返工 | 工具已有能力、实际文件关系与专业限制 |
| 软件构建 | `incremental build dependency invalidation` | 怎样识别依赖、判定失效并只重做受影响部分 |
| 工程设计 | `engineering change impact analysis configuration management` | 怎样识别影响范围、管理版本与人工批准 |
| 数据处理 | `data lineage incremental recomputation` | 怎样记录派生关系、触发重算和检查一致性 |

这些是展示查询形成方式的候选路线，并未证明适用于某个具体产品。得到材料后，把“原领域对象及关系 → 当前对象及关系 → 不同的条件 → 可检验的效果”写清。例如构建系统能够自动追踪的依赖，在美术制作中可能依赖人工判断；这项差异会影响自动化程度。找到相似名词后继续追机制、真实操作和失败情形，按 [问题与方法的深入研究](problem-and-method-study.md) 核验迁移。

## 让查询随着发现变化

- 起点使用用户说法、领域常用术语与功能描述。术语未知时先用教材、综述、专业词表或高质量案例取得词汇，再回到原始材料；按领域补充原始发表语言与当地术语。
- 根据问题组合对象、关系或动作、决定性约束和材料类型，例如“变更传播 + 依赖 + 案例”或“方法名 + evaluation / failure / implementation”。按检索系统支持的语法调整，不把整段需求当作唯一查询。
- 用已经确认相关的文献、项目或案例作起点：向后查参考文献和前身，向前查被引文献、后续版本、复现和批评，横向查相似文献、作者或组织的相关项目。各路线按当前缺口选用。
- 找到有效结果时提取作者实际使用的术语、分类号、关键组件和反例，变成新查询。结果过窄时减少偶然条件、换功能描述或追上游；结果过散时加入关键约束或具体机制；结果为空时区分术语失配、入口覆盖不足和访问失败。
- 不同网站转载同一材料只算同一来源链。独立路线应补充不同机制、实践群体、材料系统或反证；重复排序前列结果不会自然扩大覆盖。

## 方法依据与适用范围

- [NASA《Systems Engineering Handbook》第 4 章](https://www.nasa.gov/reference/4-0-system-design-processes/)：需求、逻辑分解和方案定义迭代关联；用于连接目标、功能和实现条件，不搬用航天项目的全部管理流程。
- [Design Council：Framework for Innovation](https://www.designcouncil.org.uk/resources/framework-for-innovation/)：问题探索与方案探索均包含发散和收敛，早期制作与测试可以改变问题定义。
- [National Research Council：Scientific Research in Education，摘要](https://www.nationalacademies.org/read/10236/chapter/2)：方法服务于研究问题，理论与证据形成可检查的推理关系；其具体应用领域为教育研究。
- [Google Scholar 官方搜索帮助](https://scholar.google.com/intl/en/scholar/help.html)：从领域术语、参考文献、被引与相关文献推进搜索；引文关系帮助发现材料，结论仍需读原文。
- [Chan 等：SOLVENT（2018）](https://josephcc.com/static/papers/53236685/paper.pdf)，第 3 节、第 4.5 节及第 7 节：区分论文背景、目的、机制和发现以寻找跨领域类比；案例与研究规模支持其具体检索实验，不证明任意领域的迁移有效性。
- [Gusenbauer 与 Haddaway：What every researcher should know about searching（2021）](https://pmc.ncbi.nlm.nih.gov/articles/PMC7984042/)：查询、探索与系统检索应匹配不同目的、方法和检索系统；正式系统综述还需在范围探索后确定并报告检索方案。

上述结构是本 Skill 的综合；具体研究方法按任务与证据选择。实际研究的停止、权限与交付要求沿用主 Skill。

# 前端设计与信息展示

从使用者要理解的内容和要完成的任务出发，把真实内容、视觉设计、操作行为和实现组织成可读、可用的成品。营销页面围绕主要行动建立识别与信任，工作台支持发现、比较和处理对象，教学页面支持关系理解、观察与尝试。形式、密度、动效和实现投入服从当前用途。

## 部署材料

本 Skill 的公共主干与个人材料分开安装。涉及本地样例、档案或维护历史前，读取 [本地依赖](LOCAL-DEPENDENCIES.md)；缺失材料不等同于方法已执行。

## 分清设计依据与开放问题

先取得当前页面、项目约定、真实内容、用户情景和交付入口，分清哪些已确定为实现依据、哪些仍开放（同一任务可按页面或区块组合两种模式，用户本次明确要求优先于历史偏好与设计线索）：

- **视觉稿还原模式**：用户要求按图实现，或已采用整页视觉稿作为实现依据时，读取 [视觉稿还原](references/visual-reconstruction.md)，以整稿为视觉规格并以基本复刻为目标，尽力保留构图、位置、尺度关系、字体角色、图文关系、留白与美术细节。仅作风格参考的图片不自动触发逐稿还原，未采用的探索稿不覆盖当前依据，新建 HTML 或组件不改变已有美术决定权。仅当存在具体实现限制、画面关系本身不能成为真实网页关系，或真实内容、交互与可访问性要求冲突时，才在受影响位置作必要调整并保留原设计意图。
- **开放设计与局部修改模式**：内容重组、风格探索和模板选择只用于仍开放或已获授权改变的部分。简报缺失信息先从现有材料查明，会影响结果的自行选择交代清楚。局部修改直接从当前文件处理受影响部分，保留其他视觉关系和来源不明的已有内容。
- **产品歧义升级**：页面结构依赖的用户任务或成功结果仍有会改变产品范围或完整体验的不同解释时，使用 [产品开发](../product-development/SKILL.md) 共同明确。子代理将具体歧义、已有材料及其对设计的影响交回上级，由主 agent 组织产品判断，能独立调查的事实继续查明；沿实际使用情景取证或用能区分理解的原型取得反馈后，再带回页面结构和验证。
- **设计系统与真实材料**：存在设计系统时先读其使用说明与 tokens，再按需读组件、样式和真实素材；尺寸、颜色、字体与状态精确保留来源值（5px 就保留 5px）。真实价格、评价、客户身份和统计数字取自实际材料，缺失信息用明确待填标记；标志与身份素材取自真实来源，普通图标沿用已有体系。制作过程与检查记录留在任务说明与交流中；仅当作品本身用于讲解设计或比较方案时，才在成品保留理解所需的理由与条件。

## 让界面本身表达

- **用布局与状态表达关系和后果**：辨明用户面对的对象、关系、当前状态及可行动作与结果——用邻近、对齐与留白表达归属，用层级与位置呈现主次和当前位置，用控件呈现选择，用对象及状态变化反馈结果（不把每段说明都改成卡片、图标或交互）。需要理解选择与后果时，让操作和结果在可辨认上下文中关联（如改人数同步费用明细、筛选同步结果与范围）。预览、估算、提交中和已生效各按真实状态表达；**探索控件不得隐含付款、发送或其他外部提交**。静态展示已清楚时直接使用，交互须提供实际的比较、观察或操作价值。
- **文字分工与可访问语义**：文字承担名称、操作目的、必要状态提示、原因解释和不易从界面看出的条件（保留会改变选择的费用规则、异常原因和重要后果）。辅助说明较多时，检查是否由分组、状态或操作反馈缺失造成并在对应位置修正。视觉关系同时落实为语义结构与可访问的名称、状态和反馈，不能只靠颜色、位置、图标或动画传达。以用户能否准确理解并完成任务判断效果，不以字数减少为成功标准。
- **不套层叠文字槽位**：从真实内容与操作组织页面，不预设“眉题—标题—副标题—说明—脚注”层叠槽位。布局、控件、选中状态或反馈已表达的含义，不再写成阅读指令或界面自我说明。新增辅助文字前先明确它补足哪个无法直接看出的条件、原因或后果；制作与验收经过留在工作记录，不等最终审查才清理。

## 选择方法并形成可见结果

- **复用参照与自建边界**：先看当前工程、设计系统和成熟作品能否满足需要。方向开放且缺少参照时，使用 [深度研究](../deep-research/SKILL.md) 查找匹配的完整作品、组件实现与成套素材，按 [设计参照搜索与原件复用](references/design-resource-library.md) 查看原画面、版本、使用条件及可取得资源（本地原件库提供快捷入口，搜索范围随需求扩展）。可靠参照直接复用，完整模板适配真实内容并保留字体、色彩、图片、组件和布局关系；有具体缺口时再自建。
- **真实内容试排与多方向比较**：自行组织结构时，按对象、关系与状态安排总览、局部入口、比较和深入方式；先用真实代表内容及必要控件状态试排，检查阅读与操作路径后再扩展组件与视觉实现（内容不适合拟定框架时连同分组和布局一起调整，不先套版式再塞字；顺序过程才用序号）。整体视觉方向未定且影响完整作品时，制作足以比较结构、字体、配色或密度的可见方向并说明适用情境与取舍（低保真够用时先用低保真，候选名称保持稳定）。需要品牌识别、新风格或鲜明视觉方向时，读取 [审美方向与视觉身份](references/aesthetic-direction.md)。
- **视觉创作与网页视觉稿**：实现沿用项目实际框架、组件和正常入口。需要视觉创作解决表达问题、发展风格或制作网页视觉稿时，主动使用 [绘图创作与艺术指导](../image-art-direction/SKILL.md) 与 `imagegen`（可形成风格稿、设计拆解稿、解释图或可组合素材）。**当整体美术或新视觉身份是作品关键且仍开放时，先以真实内容画出完整页面设计（覆盖布局、关系表达、阅读路径与美术），再忠实实现已采用的设计；普通信息报告从内容关系和成熟、朴素的排版出发；精确路线图沿用 Mermaid 或程序化绘图。** 素材形式、来源与接入见 [视觉素材与页面制作](references/visual-production.md)，稿件创作、采用与交接见 [网页视觉稿落地](../image-art-direction/references/image-to-web.md)。交入读者任务、真实内容、必要交互、既有设计与可调整范围，接回后核对实际素材与页面结果，准确文案、数据、可访问性和交互在工程中落实。
- **渲染自检、视觉打磨与拼接处检查**：展开完整作品前，用真实中文、主图和代表性交互检查关键页面的内容容量与画面关系；制作中查看当前渲染，修正层级、溢出、排版、状态和操作问题，改后查看受影响的完整场景（反馈暴露结构或方向问题时先修决定再扩展）。需要判断整体视觉质量、解释用户所说的“平、乱、挤、像模板”或作实质视觉调整时，读取 [视觉评审与打磨](references/visual-critique.md)（只请求评审时交回发现与依据，已授权修改时修正结构与样式）。视觉验收先核对整页构图与阅读路线（有还原要求时以有效原稿为准），再查连接线、图标、排版、素材边缘及交互状态；不同组件或素材拼合时，按 [视觉评审与打磨](references/visual-critique.md)“拼接处与交界检查”在实际输出尺寸专查最终合成画面中的接缝、交点和裁切边缘。

## 内容、文字与实现的接续

- **HTML 与 MD 接续**：遵循全局 HTML（面向用户独立文档）与 MD（面向 AI 执行记录）分工。制作页面时按读者任务从主要记录或权威数据组织直观信息，让关系、机制和变化可见，避免把 MD 原样渲染成长文；页面与记录共用对象标识、事实和版本依据，保留定向查证入口，变更后同步受影响内容。无需为每份内部记录单独制作页面，明确要求其他交付格式时按用途处理。完整作品需要委派时，使用 `content-designer` 连续承担内容与呈现；内容与前端责任也可由同一执行者承担，按实际成果依赖安排可独立交付的工作。
- **教学与解释协作**：教学或解释作品先读取 [教学与解释](../teach-and-explain/SKILL.md)（同一任务已完整读取且仍有效时沿用），按其确定的读者、核心关系、必要条件与解释顺序设计。教学负责人定讲什么、为什么成立、怎样帮助理解与学习；前端负责人完成布局、可见关系、交互和显示检查。视觉或实现改变文字、尺度、数据或解释含义时交内容负责人核对。
- **代码开发协作**：业务功能、接口和状态连接结合 `code-development` 沿真实使用路径完成。多人委派提供准确材料路径、有效决定、交付入口、必须保留的事实与可调整范围，并明确要求接收者读取本 Skill 和适用参考；接收后核对真实成品并更新当前规格和内容。
- **界面文案与对抗性审查**：界面文案使用 [写作与文字审查](../writing-zh/SKILL.md)（同一任务已读且仍有效时沿用）。制作阶段按上述分工约束新增文字；最终候选按 [界面中的文字](../writing-zh/references/interface-copy.md) 进行独立对抗性审查，要求以具体作用证明文案需要存在（尤其检查次级标题、小字、提示与重复说明）。完整页面覆盖全部用户可见文字，局部修改覆盖受影响文字、关联状态与邻近内容；按 [界面文字与页面接续](references/interface-copy.md) 核对显示与行为。该审查并入下面的最后核查，不另起重复评审；后续整合新增文字同样检查。

## 交付

- **真实入口与操作自查**：从正常入口打开当前候选，按读者任务检查扫读定位、跳入局部、比较及深入查证，并验证代表性操作（不只按作者从头到尾顺序检查）。依据界面自身信息检查用户能否辨认当前对象与状态、找到可行行动、预判重要后果并在操作后确认实际变化。用实际使用观察支持结论，作者自查、独立评审与真实用户观察分别说明，不用额外口头讲解补齐界面后宣称界面已清楚。阅读检查结合教学 Skill，实际显示与行为执行 [运行体验与完成检查](references/runtime-quality.md)；修复后重查受影响部分，证据交实现、内容与验收负责人。
- **验收状态诚实记录**：内容、功能和视觉验收结果分别记录。需要视觉交付却未取得最终页面的实际渲染画面时，保留“视觉验收未完成”及其影响，不以源码、DOM、资源存在或文档审查通过替代；遵守当前工具与权限边界继续完成可执行工作。
- **独立 `reviewer` 终审**：完整页面或实质性改版在自查与运行检查后，须调用独立 `reviewer` 按 [代码与文档评审](../code-review/SKILL.md) 审查最终候选（教学页面共用这次最终审查；用户明确要求单 agent 时由作者完成并在交付中说明采用了自查）。一次交清用户情景、有效要求、成品入口、原始内容依据与实际检查记录；有还原要求时一并交入有效原稿、最终整页与关键区块截图及差异处理，覆盖完整页面。审查包含内容与标题、文案必要性、行为对应及交付声明，显示与操作结论对应实际证据。评审者独立完成后集中交回问题与依据（不频繁逐句商量，真正阻止审查的缺失或冲突及时交回）；负责人集中修正并以具体依据回应保留项，交回关闭问题（复审只覆盖修改及受影响部分）。主 agent 核对交付版本、实际证据与最终审查结论一致后交付，交回稳定入口、可编辑来源与正式素材、实际检查结果、重要自行选择及具体剩余问题。设计决定已记录、文件已写入与真实运行通过分别报告；美感和阅读舒适度结合用户反馈继续调整。

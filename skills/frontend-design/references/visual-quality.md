# 视觉质量与具体检查

按本次作品与修改范围使用这些要求。先读已有品牌、设计系统和页面，再对实际选择的颜色、文字、布局与操作进行检查。

## 文字与控件对比度

| 对象 | 检查基准 | 要检查的实际配对 |
| --- | --- | --- |
| 普通文字，包括说明、占位提示和操作反馈 | 至少 4.5:1 | 文字与它实际所在的底色 |
| 大字 | 至少 3:1 | 文字与实际底色；大字按至少 18pt 普通字或 14pt 粗体判断，CJK 字体使用等效尺寸 |
| 辨识控件、状态或信息所必需的边界、图标、焦点提示与图形 | 至少 3:1 | 提示与相邻颜色 |
| 用户要求高对比主题的文字 | 普通文字至少 7:1，大字至少 4.5:1 | 新主题的每个实际前景与背景组合 |

这是 WCAG 2.2 的文字 AA、非文字 AA，以及文字 AAA 对比度要求。18pt 对应 24 CSS px，14pt 粗体约为 18.7 CSS px；很细的字形、中文字体的等效尺寸和实际阅读效果还需查看。达标比值不四舍五入。装饰、标志、非活动控件与未改动的浏览器原生控件等例外按对应标准区分，正文和说明文字保持可读。

常见问题是浅灰说明文字、彩色底上的白字和深色主题的明亮强调色。按实际前景、背景及透明度合成后的颜色计算或使用浏览器检查工具；渐变和图片底检查文字所在区域。深色主题的明亮 accent 可能需要深色的 on-accent，不能默认总用白色。

按当前主题和真实组件状态逐项检查，不只看第一套颜色。状态之间通过词语、形状或图标补充颜色含义。多个 theme 的引用与实际呈现保持一致。

整理已有品牌来源时，精确保留来源值并标出不达标的配对。改品牌值或增加主题按用户当前范围决定；新选的配对直接满足当前目标。品牌参考中的问题不作为新页面忽略可读性的理由。

## 触控目标与语义

触控使用的独立按钮、图标按钮和菜单操作，优先提供至少 44×44 CSS px 的可操作区域。这里衡量实际可点击区域；小图标可通过控件 padding 扩大区域，扩大后检查相邻目标不重叠、不遮挡其他操作。

44×44 对应 WCAG 2.2 的目标尺寸 AAA 要求，也作为本 Skill 的触控设计基准。AA 的目标尺寸要求是 24×24 CSS px 或满足标准中的间距等例外。行内链接、原生控件、等效操作入口和确有必要的尺寸约束按对应标准处理；既有紧凑界面结合使用情境和项目要求检查。声称满足 AA 或 AAA 时按相应完整条件核对。

静态原型也使用真实 button、a、input 和 label 表达控件。图标按钮提供可理解的名称，装饰图形使用 aria-hidden，表达信息的图形提供名称或对应说明。可操作区域、键盘焦点与界面上看到的对象一致，沿真实路径检查。

## 字体、配色与布局

字体需要覆盖作品实际文字与所用字重，中文、中西混排、数字和长标签都查看真实效果。给 webfont 配置尺寸和字形尽量接近的 fallback，检查字体加载前后是否导致标题断行、按钮高度或布局变化。真实品牌字体优先。

先定义文字角色及其关系：展示标题、正文、辅助说明、控件标签和数据各自服务什么任务。用项目已有的文字样式承载这些角色；需要新增时，协调字号、字重、行高与宽度。主次差异可以来自位置、字重或留白，标题的大小与当前容器和阅读任务相配。弱化辅助信息时仍满足可读性与对比度要求。

用真实段落调整行长与行高。阅读页检查连续阅读和换行后的连接，工作台检查逐行扫描和跨列比较。中文字符宽度、标点和中西混排会改变每行容量，按实际字体与版面查看。标题换行应保留完整的词组与含义；窄屏或文案变化后，重新核对断行和周围空间。

需要按位比较金额、数量或读数时，可用等宽数字特性并按业务含义对齐，单位与精度保持一致。普通标签和正文使用适合阅读的字体。核对中英文字面大小、基线与图标在实际字号下的视觉对齐，调整后仍保持正确的点击范围与焦点位置。

保持前景、背景与强调色的色调协调。需要从品牌派生颜色或协调多个 accent 时，可以用 OKLCH 比较明度、彩度和色相；色彩角色与数量由内容和主题决定。准确品牌值继续作为来源。

按钮、卡片、导航、图标和工具栏等群组优先用 flex/grid 与 gap 排布。行内流用于段落中的文字与链接。网页使用流式宽度、max-width 容器与可收缩的列，手机宽度下允许导航堆叠、工具栏换行，宽表格在有边界的区域滚动。

间距表达分组与层级。核对标题与所属内容、字段与说明、行内操作与记录是否靠近，相邻组之间是否有足够区别。相同组件保持相同规则，明确不同的职责可以使用不同密度。发现零散取值时先查来源及用途，再决定是否统一到现有变量。

按用户需要扫描、阅读或操作的内容确定网格与区域比例。密集数据区应保留身份、列对齐和操作空间，阅读区应有稳定的行宽，重要图片区应给主体足够空间。长页面通过内容性质变化形成节奏，例如说明接实际作品、总览接详情。每个区块的边界、底色、圆角和阴影都应承担分组、层级或当前视觉方向中的作用。

图片按用途选择完整显示或裁切。展示外观、文字或步骤时保留必要区域；氛围照片可以填满容器，但要检查主角、视线方向、关键细节和文字叠加区。宽窄布局分别检查裁切结果，图形内容与邻近说明保持对应。素材身份与可编辑图层继续按 [视觉素材与页面制作](visual-production.md) 管理。

高度由内容和容器关系决定。全屏应用可用视口高度；下方仍有内容的 hero 按内容与 min-height 排布。核对百分比高度是否有确定的父级高度，检查标题断行、列宽和真实内容裁切。固定画幅用于明确尺寸的展示、海报和印刷；配套印刷正文以至少 12pt 为设计起点，根据观看距离、纸张和用途调整，核对页面尺寸、分页、字体与素材，并查看真实 PDF 或印刷渲染。

设备原型根据实际运行环境预留系统区域，真实手机已有的状态栏或键盘不重复绘制。营销页围绕用户的主要行动安排内容，具体说明提供什么、可信依据和怎样开始，证据取自真实材料。

## 中文文字与地区格式

用真实中文、实际字体、长名称与用户面板宽度检查段落、标题、标签和读数。正文自然流动，长标签通过重排取得空间，必要读数完整可取得。检查行距、行首行尾标点、中西混排、数字与单位相邻关系，放大与窄屏后文字仍可选择、搜索和复制。

中文断行按语言、地区与文字系统核对。简繁体不能单独决定全部排版规则，句首句尾禁则、成对标点和不宜拆开的破折号、省略号等需要在真实字符串中检查。排版引擎与实际可用字体共同决定最终效果，复杂情形查 [CLReq](https://www.w3.org/TR/clreq/) 的对应地区与条款。CLReq 是持续更新的中文排版需求资料，采用时核对状态与版本。

日期、数字、货币、单位与时区采用使用情境所需的 locale 和业务语义，显示与编辑保持一致。组合句子按完整语义模板生成，翻译后检查文字伸长、从右向左布局及混合方向内容。界面接受多语言文本时检查输入法组合输入与真实字符串，伪本地化可用于暴露空间和顺序问题。来源见 [Microsoft 软件国际化](https://learn.microsoft.com/en-us/globalization/methodology/software-internationalization) 与 [Unicode 换行算法](https://www.unicode.org/reports/tr14/)。

## 文字覆盖与缩放

支持用户放大和改变文字间距，检查操作、标签与必要信息仍可取得。WCAG 2.2 AA 的文字间距检查是在用户同时覆盖行高为至少字号1.5倍、段落后距为至少2倍、字距0.12倍、词距0.16倍时，内容与功能没有损失。它定义覆盖后的检查条件，作者的默认排版值按内容决定。语言/脚本不使用的间距属性按标准例外处理。

回流检查按 WCAG 2.2 AA 采用纵向滚动时320 CSS px宽、横向滚动时256 CSS px高的条件，核对必要信息和操作。地图、复杂图形和需二维关系的表格等按条款例外处理，将横向滚动限定到实际需要的区域，正文和其他操作继续可读。320 CSS px 是回流检查条件，项目布局断点由内容失效位置决定。详细输入与焦点检查读取 [可访问交互](accessibility-interaction.md)。

## 完成检查

沿作品正常入口查看本次受影响的主题、视口、真实字体、素材、状态与主要操作。修复后重查对应部分。对比度数值检查与实际可读性检查一起进行，文件存在或截图生成不代替查看当前页面。

用户要求不试跑时，按授权做静态核对，并说明哪些显示或行为尚未验证。核查范围和实际结果交给实现与验收负责人，沿 [界面设计交接](design-handoff.md) 接入成品检查。

# 设计原件库

设计原件库由接收方在项目资料中配置，索引记录完整页面项目、组件实现、图片、字体、许可和可编辑样本的准确入口。先读取已有总索引，选择与当前任务相符的来源。尚未建立库时，结合本 Skill 的来源入口取得当前需要的原件，在项目内保存来源及使用记录。下面的目录名是已有库的组织示例，实际路径以接收方索引为准。

## 定位实际原件

| 当前需要 | 从库中读取 |
|---|---|
| 完整站点、产品介绍页或营销页 | `sites/*/RESOURCE-RECORD.md`、对应 `source/` 的页面、分区组件、主题与素材；也可查看 `apps/shadcn-dashboard-template/source/vite-version` 的完整 landing |
| 表格、任务、邮件、设置与工作台 | `apps/README.md`，对应应用 `RESOURCE.md`、页面路由、组件、主题和本地数据 |
| 知名网站的布局、图像配置与动画实现 | `replicas/README.md`、对应 `source/`；这些来源的品牌图片和设计用途需保留记录中的具体条件 |
| 标准化控件、状态、字体和色彩变量 | `components/README.md`、`runtime-components.md`，选择当前框架能消费的 shadcn、Material 或 Fluent 源码及主题 |
| 比较成套字体、配色、按钮、卡片与表单 | `brand-previews/awesome-design-md/offline-previews/README.md`，再打开对应品牌的 HTML；同目录资产清单映射本地 CSS、字体二进制、许可与原地址 |

完整页面、控件样本页与品牌还原分别按其实际覆盖使用。需要原站整页时继续搜索原站、完整模板或可编辑项目。库里没有合适对象时，结合搜索 Skill 追到新来源，并将实际文件、固定版本和素材补入项目资料。

## 从原件进入制作

查看完整画面和必要的内页、窄屏或状态后，读取实现这部分的页面、组件与样式。保留确定采用的字体角色、色彩、留白、图片裁切和交互关系，再用当前真实内容检查整页。用户接受或否决的具体画面作为选择依据，源码能启动与用户喜欢分别记录。

复制组件时同时取得主题变量、工具文件、导入依赖和必要状态。Fluent、Material 源码来自 workspace，取一份 TSX/JS 不构成独立项目；按现有工程使用已发布包，或补齐源码构建所需工作区。图片与字体从真实文件和资产清单取得，按源记录处理不同用途条件。

在现有工程继续使用其框架和组件体系。独立参照从各记录中的正常入口查看，开发服务器停止后用相同目录和命令重启。Windows 的图集深目录可能超过浏览器文件路径长度，使用离线图集记录中的短路径入口或本地 HTTP 入口。

原件源码与适配工程分开保存，修改后检查真实中文、图片、宽窄布局和主要操作。沿用本 Skill 的界面文案审查与运行验收。上游文档用于理解来源，当前用户要求决定本任务采用的内容与方法。

# 视觉稿还原

用于把已采用的完整视觉稿实现为网页。原稿承载设计决定，是整页的视觉规格；实现者以基本复刻为目标，尽量忠实呈现构图与细节，再把内容和操作落实为可编辑、可操作、可适配的前端。需要从需求另行形成设计时，使用主 Skill 的设计流程。

## 先取得设计本身

读取当前有效原图，先看整页，再看关键区块。委派中的文字摘要、组件名称、配色和素材目录用于定位，不能替代原图。多人交接时，主 agent 交清原图版本、真实内容、现有素材与允许变化，实现者实际打开图像。

从画面而非通用网页类型建立实现依据：主体与文字的位置和尺度、各区块高度与宽度关系、图文比例、留白、对齐、遮挡、出血、斜切或曲边、跨区衔接、字体气质、材质和装饰层次。可测量的关系用当前可比较视口记录；截图无法确定的动效或行为另行补足，不编造精确规格。记录服从工作需要，不强制另建整套文档。

## 基本复刻整页

从原稿建立页面，不先套入常见网格、卡片或组件骨架再重做布局。尽可能保留主体与文字的位置、大小和比例，区块关系、图文搭配、字体角色、留白节奏、线条形状、材质、光影与装饰细节。结构可按工程职责拆分，屏幕上呈现的整体关系仍以原稿为准。

版式、字级、字体角色、文字块的位置与相互关系属于视觉规格；文字内容采用项目确认的真实文案或指定作者提供的文本，不照抄生成稿里的伪文句，也不由前端为迁就图框擅自改写或删减。正文确需精炼、重组或补充以适配版面时，将具体版面问题、原稿、已核事实和须保留的含义交给指定作者协作修订；保留原稿与改稿供核对，前端核对事实和含义，并在实际页面检查呈现。文本长度不同，保持原有文字主次、分组与阅读秩序，让页面自然延伸。

文字和控件保持真实网页元素，不能用整页位图替代；绘制稿中的精细纹理、插画和纯图像细节可以由原图或对应素材承载。先以原稿对应的展示尺寸实现和比较，再处理实际需要的其他宽度。窄屏重排以确有失效的内容为范围，尽量保留原稿的主次、分组、图文关系和阅读路径；泛化的响应式习惯或组件库默认行为本身不足以成为改版理由。

## 从构图落实布局

先把原稿中的整页区块、区块间关系与层级落实到真实页面结构，再组织组件与复用。逐块核对其位置、尺寸、相邻内容和跨区衔接；只移动 hero、覆盖主题色或保留同一套固定 DOM，并不能证明整页已还原。组件边界可以与绘图区域不同，屏幕上呈现的关系仍须保留。共享组件或设计系统服务于原稿；若其既有结构妨碍这些关系，先调整页面组合与局部样式，不让组件限制反过来改写已采用的视觉规格。

展开较大的还原工作时，先用真实文字和美术实现足以检验关键构图的代表区块，实际渲染后连同整页骨架对照。结构已经偏离时先修正，避免沿错误框架复制到全页。普通小改直接核对受影响的完整场景。

还原模式中的真实文字、自然换行、语义控件与必要响应式由实现者完成；重要构图、主要素材和内容量的改变按已有授权处理。窄屏可以重排，依据当前内容与失效位置保住原有主次和主要操作。

## 局部适配的条件

要调整原稿前，先寻找更忠实的实现方式：组合现有素材，使用裁切、遮罩、SVG 或 CSS，或将绘画细节保留为图像层，并把真实文字和操作放在原有视觉位置。确实无法用合适实现表达的细节，或原稿关系与真实内容、语义交互、可访问性要求相冲突时，才调整受影响的局部。说明要保留的设计意图、具体约束依据和最小替代，并保住周围构图与关系。

原稿是位图、通用工具或组件的默认行为、尚未核实的库能力、文字变长或泛称“需要响应式”，都不能单独作为整体改版的理由。先在原稿对应尺寸还原并检查；较窄尺寸再按实际失效位置局部适配。

示意插画、生成概念图与实景或实机证据按实际来源辨识，在需要判断的位置保留必要标注，并保住原稿的重要美术关系。纠正内容身份与删减美术是两项不同改动。

## 美术依赖与实现权限

按原稿区域对应素材路径、用途、裁切与组合关系，缺件标明位置与处理者。不同构图职责的插画、图案或材质分别核对；同一图可以复用的前提是其实际构图适用。不能为方便实现，用一张图的裁切压暗或通用形状顶替原稿中缺失的重要美术。

图片、字体、遮罩、SVG、CSS和其他成熟前端能力按画面需要组合。可准确表达的几何与装饰可以用代码实现，但不能因此删掉具有识别作用的边缘、材质或层次。缺少关键美术时，由负责人取得、提取或交绘图模型补齐；独立的行为与结构可以先做，该区域的视觉还原仍为未完成。

## 按偏差类型反馈

| 实际问题 | 谁处理、怎样继续 |
|---|---|
| 原稿有效，页面比例、位置、层次或裁切偏离 | 前端依据原图修实现，再查看受影响画面。 |
| 原稿中的重要美术没有独立资源，或素材质量不合用 | 交清缺件区域、使用条件与原稿关系，由负责人协调美术补齐。 |
| 真实内容或使用要求与原稿冲突 | 可在原有层级与关系内处理文字流动、语义控件和可访问性细节；若必要变化会改主要构图或含义，带原稿、页面和具体影响回到设计决定，不能自行换成另一套布局。 |
| 用户要求新美术方向 | 作为新候选形成决定，保留当前有效设计；探索图不自动覆盖原稿。 |

需要绘图模型继续设计时，反馈实际画面、问题位置、用途和须保留关系，由其完善相应美术。实现偏离直接修代码；不为普通工程问题反复重画。

## 用真实画面验收

在首个整页可浏览版本与交付前，以同一展示尺寸将有效原稿与真实渲染并排或叠合比较。先看整页主次、区块位置与比例、阅读节奏和跨区关系，再逐一核对各区块与对应画面的关系；不能只检查溢出、素材存在或源码结构。具体观察方法见 [视觉评审与打磨](visual-critique.md)。有意义的差异分别作为必要适配、已授权设计变化或实现偏离处理；实现偏离修回后再次查看实际画面。

实现者交回原稿、截图和差异处理的可查入口，说明仍缺什么。主 agent 亲自核对支撑整体还原结论的图像；独立审查也取得同一组材料与还原要求。功能可用、没有溢出、素材存在和独立图片美观，各自只证明对应部分，不能替代整体构图验收。

没有实际渲染画面时，可以报告素材与源码检查，但视觉还原保持未验证。完成声明对应最终候选与实际范围；局部修正通过不扩大为整页通过。

## 依据

[Design2Code](https://arxiv.org/abs/2403.03163)评测真实网页截图转码中的元素遗漏和布局错误；[DCGen](https://github.com/WebPAI/DCGen)提供分区生成与整合的研究实现。[Playwright视觉比较](https://playwright.dev/docs/test-snapshots)可辅助定位变化。上述材料提供检查与实现入口，视觉差异仍须结合原稿和用途判断，不按历史模型结果预设当前模型能力。

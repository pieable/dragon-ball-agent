# 浏览器运行与视觉质量验证

用于页面、图表或交互已进入可运行状态，需要确认真实入口中的布局、字体、资源、操作和辅助技术结果时。检查范围随本次作品、风险和用户交付约定确定；截图或静态结构检查不能代替实际页面行为。

## 沿项目正常入口检查当前候选

先确认用户会打开的正常入口、实际运行方式和本次修改产生的候选页面，再用该入口打开当前结果。已有服务沿其项目命令、URL 或宿主运行；直接文件交付沿实际 HTML 文件路径打开。对照当前文件、版本或构建结果，确认页面加载的是刚修改的候选，而非旧缓存、旧文件或另一条入口。

在用户实际使用的浏览器面板宽度和主要设备条件下查看受影响的路径。检查真实内容、字体和字体回退、长中文及中西混排标签、图注、箭头、链接、焦点、状态和代表性交互。屏幕窄到内容失效时再查看对应重排；局部图表或数据表确有二维信息时检查其自身的滚动与操作。按任务检查文字放大或用户文字间距覆盖会不会裁切、遮挡或阻断操作；这些是条件化的适应性检查，不把它们当作默认字号或统一断点配方。

图片、字体、脚本和数据都沿真实加载路径核对。实际打开外部资源或使用冷缓存时，查看异步资源是否使页面内容突然位移，尤其是用户正要操作的位置。点击后出现的等待反馈也应保持布局稳定。修复后重新查看受影响路径，确认当前页面显示的是修复结果。交付约定要求离线时，实际断网检查加载和操作。

需要判断整体审美或完成实质视觉修改时，结合 [视觉评审与打磨](visual-critique.md) 查看当前页面的整体层级与局部细节。截图标明入口、视口和当前状态，评审后的修正回到同一场景核对。功能、资源、可访问性与视觉判断分别按实际结果报告。

沿本次操作路径核对实际出现的文案，包括选项、等待、成功、错误和详情等当前场景中的状态。对照 [界面文案审查](interface-copy.md) 检查文字是否准确说明当前对象、真实状态与可用动作，辅助技术名称与可见标签是否同义。源码中的文案审查与运行时实际触发的状态分别记录。

## 操作、辅助技术与依赖故障

浏览器操作类型不同，分工也不同：一般打开、导航和功能操作交 `operator`；需要首次用户视角完成一项实际目标时交 `visual-usability-tester`，由其只依可见界面完成路径。报告具体入口、操作和观察结果；角色或截图本身不是通过证据。

当目标包含键盘或屏幕阅读器使用时，除代码语义与可访问性树检查外，还通过实际辅助技术完成受影响的路径。对于复杂图表，检查用户能否找到描述或表格、按结构导航并访问所需数据；标记结构正确与辅助技术操作结果分别记录。单有 alt 文本或通过自动化规则检查，不能证明逐项数据或复杂关系已能非视觉使用。适用的对比、触控、放大和辅助技术指导按当前交接与[信息可视化](information-visualization.md)中的图表替代要求读取。

先列清核心任务依赖与可选增强，再决定是否测试依赖失败。核心内容、导航、表单或交易若依赖 CSS、JavaScript、第三方资源或网络服务，测试该依赖失败时用户是否仍能完成核心任务，或是否有明确的替代路径与数据获取方式。不要把某种渐进增强策略、禁用单页应用或服务器结构要求扩展成所有项目的规则；GOV.UK 的强制性架构要求适用于其政府服务，其他项目只在自身依赖、交付合同或用户要求需要时采用对应检查。

## 需要时测量页面稳定和操作反馈

测量前说明指标覆盖什么路径、设备类别、数据来源和统计分位。CLS 是页面生命周期内最大一组连续布局位移的累计分数；Google 的“良好”参考值为手机和桌面分别统计真实用户访问的第 75 百分位不高于 0.1。它会排除最近一次用户输入后 500 毫秒内的位移，这是计分定义；被排除不表示该次操作中的跳动对用户无影响，所以仍需实际检查。只测首次加载会漏掉滚动、后续内容和请求返回造成的位移。

INP 衡量用户交互开始到浏览器下一次绘制的时间，不包括网络请求或后台任务最终完成。按手机与桌面分别查看真实用户数据，第 75 百分位不高于 200 毫秒为良好参考，超过 500 毫秒为较差参考；它不覆盖悬停、滚动和缩放，且没有相关交互的页面没有 INP 值。用代表性交互测输入响应、主线程处理和绘制；对持续较久的请求另查任务进度、结果正确性和完成时间。首次可见的“已收到操作”反馈与后台任务最终完成是不同结果，分别记录。仅页面加载实验室报告或 Total Blocking Time 不能代替真实交互路径和 INP 数据。

这些数值用于适用页面的性能评估，不自动成为每项任务的硬性完成时限。报告需说明采集的是现场真实用户数据还是实验室测量，不能把不同数据口径混为同一结论。

## 来源与证据边界

- [Google, Cumulative Layout Shift](https://web.dev/articles/cls)：官方 Web Vitals 定义与测量指导，支持 CLS 的页面生命周期、最大位移簇、第 75 百分位参考值及 500 毫秒输入排除机制。
- [Google, Interaction to Next Paint](https://web.dev/articles/inp)：官方 Web Vitals 定义与测量指导；支持输入至下一次绘制的范围、第 75 百分位参考值、排除的交互类型以及它不涵盖后台网络完成这一限制。
- [GOV.UK, Progressive enhancement](https://www.gov.uk/service-manual/technology/using-progressive-enhancement)：政府服务工程指导。政府服务的政策要求不自动适用于其他项目；本处仅在任务依赖增强能力时采用依赖失败和核心任务替代路径检查。
- [WCAG 2.2 SC 1.4.10 Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)与[SC 1.4.12 Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)：规范解释材料，分别给出重排和用户文字样式覆盖的适应性测试条件。它们不是所有页面的固定布局、断点或文字样式要求。
- [CLReq 中文排版需求](https://www.w3.org/TR/clreq/)：中文布局任务组工作草案与排版实践说明；断行与标点规则须按地区、文字系统和真实浏览器字体条件核对。
- 本仓库的[界面设计交接](design-handoff.md)、[视觉质量与具体检查](visual-quality.md)与[信息可视化](information-visualization.md)：提供当前组件状态、文字和图表的交接检查；它们指导页面检查范围，不代替实际入口中的操作结果。

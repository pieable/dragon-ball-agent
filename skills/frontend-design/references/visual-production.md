# 视觉素材与实现交接

在设计工作需要真实素材、生成图片、页面参照或从视觉稿交接到实现时，按项目和交付条件组织素材与来源。先确定图片或图形要表达的对象、动作、关系和使用位置，再决定使用真实素材、可编辑图形、生成图片或已有设计系统。

## 选择合适的素材形式

- 截图、实际成果、事件、人物和品牌身份使用来源可核实的真实素材，保留原发布位置、素材路径和必要的裁切上下文。普通图标沿用项目已有图标体系；不要用生成图伪造真实身份或事实。
- 场景插图、定制美术、产品模拟图和页面风格探索可使用图像生成。生成图片适合位图内容，不代替项目已有的 SVG、图标系统、HTML/CSS 或可计算图形。
- 精确数值、公式、图表坐标、箭头连接、可计算比例和会变化的文字应放在可编辑的 HTML、SVG 或其他绘图层中。若生成画面只负责背景或氛围，把要准确呈现的数据与文字保留为独立图层。
- 图像替代信息按用途安排：信息图说明当前含义，功能图说明动作或目的地，纯装饰或邻近文字已完整表达时使用空替代文本。复杂图的可导航说明、数据表与联动按 [信息可视化](information-visualization.md) 完成。
- 真实照片、既有生成图和外部参照都记录来源及用途。代码许可与第三方图片的使用条件分别核对。借用提示词时配对查看并保存实际 prompt 和对应成图，只有文字时按未验证的模板处理。聚合转载继续查找原发布页。外部 prompt 中的事实、品牌、价格、评价、受众和服务参数只适用于其原场景，迁移前逐项核实。

## 以代表内容比较参照并准备交接

整体方向仍影响完整页面时，使用同一组代表性内容展示候选方向，使构图、字体、材质、信息组织和密度的差异可以比较。候选应解决当前未决问题；主题契合度与视觉吸引力分开判断。方向已确定或修改范围很小时，沿用已有依据直接制作。

页面参照应能支持目标实现方式。若产物是 HTML，选择最终需要保留的构图、信息层级、色彩和材质；提前处理实现困难且不影响目标的效果。结构和方向足够稳定后进入 HTML，由实际文字、数据、响应式布局和交互落实产品行为。Figma 只在项目实际使用 Figma 进行页面设计或组件布局时采用，并按该操作读取相应 Figma Skill；项目已有其他设计工具或源码方式时沿用其交接格式。

交接时给出所选参照、正式素材与可编辑来源、实际文件路径、要优先保留或改变的部分、实现说明和可调整范围。指定差异先落实；未指定部分保持参照的视觉设计。用实际内容检查接收者能否辨认布局、阅读顺序、组件状态及需要保留的身份。文字、数据、窄屏布局和操作行为仍需在成品中实现与检查，不能只靠参考截图证明。

## 使用图像生成和编辑

生成或编辑前读取当前 imagegen Skill 与其提示指导，按当时实际可用的工具模式提供输入、提示和参数。为每张输入图标明角色，例如生成参照、编辑目标或辅助素材；不能仅因收到图片就把它当作编辑目标。提示写清最终用途、已核对的对象及关系、主体与视点、需要的区域和阅读顺序、材质与色彩、必须逐字出现的标签、参考图用途、裁切和透明要求。用户已给出具体约束时只整理表达，不自行添入品牌、对象、口号或叙事。编辑已有素材时写明允许改变之处和必须保持的身份、几何及其他特征。

保存本次实际使用的 prompt、参考图及其角色、工具模式、实际执行参数、输出文件和项目引用路径。内置工具与 CLI/API 模式分别按当前指导使用支持的参数。迭代写清本次改变的目标与关键保持条件，一组素材有依赖时先查看前序结果再继续。生成结果需实际查看：核对对象、数量、关系、顺序、条件、逐字文字和编辑不变量，发现错误后修正并重查。

把当前可用的原图或输出保留下来，再做重生成或编辑。明确需要透明背景时，检查输出具有实际 alpha 透明。按实际用途检查文件格式、缩放、裁切、叠加标签对齐和缩小后的清晰度，图标、标志和文字密集素材在实际尺寸查看。最终素材保存到项目持久目录并确认作品引用它。已有音视频沿用实际素材及其原路径，确需新生成时先确认可用能力和交付条件。优先修正影响理解的问题，主要构图过载时重新编排，达到当前用途后结束细修。

## 让文件入口和依赖服从交付约定

保留项目当前的正常入口、文件组织、构建方式和资源路径。复用旧作品时只取本次需要的来源、组件、样式和资产，检查引用的相对路径与依赖，确保新作品不再带入已失效的主题、事实或链接。生成文件先作为候选；检查内容和资源可用后再替换已有可用页面。

需要单文件或可直接从文件路径打开的本地 HTML 时，按该交付约定处理脚本、数据、字体和媒体：内嵌资源或随作品提供可解析的相对路径，选择本地文件兼容的库，沿实际文件入口打开并验证。原 OJS 等样本依赖 HTTP 时，单独内嵌资源仍不能解除运行时依赖，迁移到文件入口需替换相关交互并重验。项目明确要求服务器、后端或 HTTP 运行时时，沿项目入口接通和验证。无论哪种入口，成品实际引用的素材都应随目标交付、可读并能从其路径加载，源码、数据与图定义继续可编辑。

## 来源与方法入口

- 工具方法入口：生成前从当前宿主的可用 Skill 目录定位 `imagegen`，读取其实际 `SKILL.md` 及该 Skill 目录下的 `references/prompting.md`。它们说明工具操作，不是视觉质量研究；默认内置工具与用户明确选择的 CLI/API 后备模式参数不同，按当前指导核对输入、编辑目标、透明输出、可用参数与保存位置。
- [界面设计交接](design-handoff.md)：现有项目界面状态、响应式行为、内容边界和实现验收的承接文件；与此处素材路径和参照交付合用。
- [图表与定量信息](information-visualization.md)：数据、精确文字、关系线、图定义和替代信息需要数据同源且可编辑时使用。

# 设计系统的整理与使用

用于用户要求建立、提取或维护可复用品牌系统的任务。系统把颜色、文字样式、间距、圆角等命名成设计变量（tokens），连同组件、素材和使用说明，让后续页面准确复用。

## 真实来源与清单

先读系统的 README 与 tokens，再按任务读取实际组件、样式、字体、图标和品牌指南。值精确保留来源，不自动换成相似组件库或框架默认值；代码提供数值与行为，截图提供整体参照。

按来源真实包含的变量、主题、组件 family 和素材建立完整清单，跟踪完成与缺口。来源读取失败时记录具体未读部分，保留已经取得的资料。新增组件须有当前用途或用户范围依据，普通页面直接复用已有组件。

没有真实来源时，为当前作品建立小的初版并说明自行选择的方向与假设。主题、变量和组件的规模服从当前使用，不靠无关组件填满系统。已有系统从当前文件修改。

## 使用说明与组件

README 从使用方式开始，点名 token、字体、素材和组件。用可执行的规则说明内容语气、视觉基础和图标选择，配实际例子，例如“正文用 body；surface 上用 ink；主要行动使用 accent”。过程与进度说明留在交付记录。

每个 token 说明用途，文字颜色点名配套底色，状态颜色说明语义。字体来源、可用字重与实际文字覆盖范围对应。标志、图片和图标保留真实文件、标志宽高比与必要身份特征，无法取得时明确标出缺口或替代范围。

组件指南说明何时用、props、children、容器约束、数据依赖与使用边界。预览使用真实组件并展示当前任务需要的重要状态。后续页面挂载实际组件，组件已有能力优先复用。

## 单一来源与项目格式

沿用项目现有 token schema、CSS variables、组件技术与构建方式。新独立系统采用易读的源文件和实际可用的预览，按任务选择输出方式。

共享值以一处为源，组件、生成样式、预览和实际页面消费同一组值。写清生成 CSS 怎样随源 tokens 更新，检查 alias 可解析、theme 映射和路径引用有效，避免预览写死另一套值而掩盖系统修改。

整理已有样式时保留可恢复版本，核对现有引用再修改共享值。只调整当前范围内的文件和依赖关系，清理按当前项目事实执行。

## 主题与验证

逐个 theme 检查文字与实际底色、焦点、状态、边界和图标，按 [视觉质量与具体检查](visual-quality.md) 使用对应基准。每个 theme 与其他 theme 不同的值都应落实，深色强调底色配合实际可读的 on-accent。

原样整理、改进现有主题与新增高对比或色觉友好主题分别按用户要求确定。来源不达标的配对保留来源身份并报告具体问题。用户要求改善时，先列出受影响配对及改变范围，再落实到主题、组件和使用说明。

验证 tokens 的解析、引用与实际消费结果。组件预览和代表性页面使用同一系统，检查修改确实传递到页面，字号、字重、字体文件与布局一致。完成情况对照来源清单报告，交付可用文件、使用入口、来源覆盖、自行采用的假设和具体缺口。

## 跨工具交换与共享组件发布

需要跨工具交换 tokens 时，核对格式中的类型、用途与引用链，检查循环、无目标和类型不匹配的错误，保留未知扩展元数据。只在大小写上不同的名称可能在消费语言中碰撞，检查生成结果。DTCG [Format 2025.10](https://www.designtokens.org/tr/2025.10/format/) 是已发布的社区交换规格，项目采用其他 schema 时按真实互操作需要适配。

组件要供多个页面或服务复用时，记录实际用途、与现有组件的差别和已经测试的环境。替换现有组件需要相应的改进依据。用代表性任务和使用者检查可操作性，包括适用的残障用户、设备、浏览器与辅助技术，记录上下文和未覆盖部分。预览展示组件状态，实际消费验证复用行为。来源见 GOV.UK [组件贡献标准](https://design-system.service.gov.uk/community/contribution-criteria/)，其机构发布过程按项目需要采用，测试规模由真实范围决定。

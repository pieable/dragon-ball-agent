# 界面文案审查

用于撰写、修改或审查界面中的标题、说明、标签、按钮、选项、状态、错误、空状态、图注和链接等文字。界面文字应帮助使用者理解当前对象、作出判断或完成操作。只请求审查时交回具体发现与依据，已授权修改时修正本次范围内的文案。

## 先判断文字是否必要

对每段说明、每个标题和标注，先问它在当前位置增加了什么信息。辨识对象、解释必要条件、提示操作后果和帮助恢复都属于实际作用。与已有标题、控件或画面重复，或者只作空泛介绍和装饰的文字应删除或合并。缺少布局层次时从结构解决，新增文案须有理解或操作依据。

保留用户作决定所需的前提、费用、作用范围、不可逆后果和真实缺口。关键条件在对应决定附近可见，复杂操作的解释按任务需要提供。审查以减少阅读负担和准确理解为目标，篇幅由需要传达的关系决定。

## 区分操作界面与阅读内容

先确定文字的职责。页头、导航、工具栏、控件和状态直接点名当前对象、可用动作与实际结果。控件本身已能表达的操作，无需再在页头用长段文字复述。帮助说明出现在操作确有理解困难的位置，详细方法提供清楚的查阅入口。

先列出使用者在当前屏幕要识别、选择、输入或查看的具体内容，再写对应文案。操作入口应能让用户直接开始使用。标题中的问题应对应当前要回答的问题或作出的选择，例如确认“删除这 3 个文件？”。概括性的提问、引导用户思考的方法和作者对页面的介绍，按作品目的判断是否属于阅读正文。模板预留了副标题、提示或空状态说明，也须逐项判断是否有信息需要表达。

例如设计比较工具的标题写“设计对照”，用“任务”“版本”“宽度”组织选择。用户可以直接选择活动页、调整后和窄屏，查看对应结果。关于怎样比较视觉重点、为什么这样安排的说明放在“设计说明”中，按阅读需要展开。

文章、教材和教学页的正文承担解释责任，保留读者需要的条件、因果与例子。围绕这些内容的操作界面仍使用明确名称和动作。审查时分别判断正文是否讲清楚、界面是否便于操作。

先检查命名、选项和结构是否清楚，再补帮助。例如用户分不清两个选项，应先把选项改成能辨认的差别；长提示难以弥补含混的选项。多数用户完成任务所需的信息保持可见，只对部分用户有用的补充才按需展开。语气随任务、受众和状态调整，日常操作直接说明对象与结果，需要引导时提供具体帮助。

## 结合教学的表达审查

开始文案审查前，完整读取 [教学与解释](../../teach-and-explain/SKILL.md) 中的“中文表达”及“写后检查”章节，并核对当前生效的写作规则和用户已确认的表达要求。同一连续任务已读且仍有效时沿用。

这里承接其必要信息、具体对象、标题定位、术语一致、语气、标点及修改后含义的审查方法。界面标签与短提示按它们的使用位置检查；需要完整教学解释或报告时，继续按教学 Skill 的相应方法组织正文。

## 逐项通读实际文案

写完后必须单独进行文字审查。完整成品逐项通读全部用户可见文字与相应辅助技术名称，局部修改检查受影响文字、关联状态和邻近内容。源码有助于列清文案，实际页面与操作路径用于核对其出现位置和后果。

| 检查 | 具体判断与处理 |
|---|---|
| 信息与位置 | 这句话帮助用户理解或操作什么，已有内容是否已经表达，必要条件是否出现在需要作决定的位置。重复内容通过删去或承接处理，缺失关系补在对应对象附近。 |
| 标题与标签 | 单独读标题和入口名称，是否能预告实际内容，层级是否表达从属关系。标题、眉题和副标题各有实际用途，命名采用用户能辨认的对象。 |
| 句子与指代 | 谁做什么、作用于哪个对象、当前是哪种状态是否清楚。术语、简称和同一动作的名称保持一致，条件与结果连接完整。 |
| 措辞与语气 | 逐句删除防御性辩解、无人提出的否定、空泛预告与评价、抽象黑话、刻意悬念和临时创造的花哨说法。用自然、具体的中文说明对象、行动和结果，品牌语气服务当前受众与用途。 |
| 行为与状态 | 按钮说明实际动作，链接和折叠入口说明将打开什么。等待、成功、失败与空状态对应真实原因、进度和后续路径，实际可用能力与文案一致。 |
| 修正后的含义 | 对照原材料、有效决定与实际实现，复核事实、数字、单位、条件、范围、顺序和确定程度。关键说明和数据口径保持完整，图文和辅助技术名称使用同一含义。 |

标点按句意与文体检查，中西混排、数字与单位按当前地区和业务语义核对。若问题来自组织顺序或关系缺失，连同邻近文字一起重写，再复查含义。

## 按使用位置检查

操作文案写实际动作与必要对象，例如“保存修改”“查看记录”。若动作有重要后果，在动作前说明对象和范围。字段标签说明要填什么，占位示例帮助理解输入形式，必要标签保持可见。

错误写清发生了什么、用户能修正什么和怎样继续，已输入内容按真实流程保留。服务故障、权限不符和无搜索结果各自采用对应说明。成功提示确认实际完成的动作，过程状态准确表达已发生和仍在进行的部分。

解释性文字保留用户当前需要的原因、条件与联系。图注补充图中未清楚表达的关系，图例和单位对应实际编码，辅助技术名称与可见对象一致。制作经过和验收记录保存在任务材料中；当作品本身讲解设计、展示比较或帮助用户理解方案时，其设计关系、条件与理由属于阅读内容，保留在对应正文或明确的阅读入口中。

## 修正、复查与交付

发现问题后先修正，再通读受影响的完整文字及相关图文。措辞改变后核对对应组件和状态，结构调整后核对原有必要信息是否仍能找到。通过当前运行入口触发本次适用状态，检查生成、插值、翻译、截断和动态消息的实际内容。

后续整合、视觉修改或实现新增和改动的文字也必须经过同样审查。普通局部修改由执行者完成，完整解释作品由教学负责人统一审查，前端负责人核对最终界面、操作和状态中的表达。主 agent 在整合后核对用户将实际看到的文字。

具体问题、修正和复查结果留在现有任务检查记录中。仍影响用户理解或操作的文案问题继续修正，验收按具体文案和实际情境判断。

## 方法来源

教学 Skill 已有的标题、表达和写后检查方法为本节的基础，原文与译本见其 [来源索引](../../teach-and-explain/sources/index.md)。本节将这些方法用于界面中的实际位置与状态，并结合以下公开指导：

- [GOV.UK：Designing good questions](https://www.gov.uk/service-manual/design/designing-good-questions)：先修正问题、选项和结构，帮助补充用户需要的条件。
- [GOV.UK：Details](https://design-system.service.gov.uk/components/details/)：补充信息按需展开，大多数用户需要的信息保持可见。
- [Microsoft：User Interface Text](https://learn.microsoft.com/en-us/windows/win32/uxguide/text-ui)：区分标题、主说明、控件标签与补充说明，删除重述。该指南面向 Windows 7；借用文字角色与判断方法，原排版、标点和平台惯例保留原适用范围。
- [Shopify：Voice and tone](https://shopify.dev/docs/apps/design/content/voice-and-tone)：日常任务帮助用户高效操作，教学、错误和完成提示随情境调整。

这些材料是官方实践指导。具体中文表达和交互效果按当前用户、页面用途和实际操作验证，原文中的语言惯例与篇幅数值按其原情境理解。

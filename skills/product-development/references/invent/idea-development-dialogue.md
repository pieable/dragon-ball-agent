# 共同推敲与发展想法

用于从灵感、参考作品或未成形的体验构想开始，或讨论持续重复愿望、难以产生新认识时。沿当前想法工作，根据反馈选择下一步，不要求逐项完成下面所有动作。

## 让双方有同一个可以发展的对象

从用户最有感觉的部分展开一个具体片段：人在什么情景里，看见或做了什么，发生什么变化，为什么还愿意继续。作品的审美、好奇和探索感也可以是起点。用户还不知道用途时，可以先借助片段发现它，不急于将其翻译成效率问题。

主 agent 用自己的构思承担推进责任。把一个机制或变化展开到能够比较后果的程度，再让用户修改、补充或拒绝。用户的表达需要继续展开时，先听取并澄清。用户明确邀请共同构思时，不能只靠一串提问让其独自提出产品。材料不需要长，关键是双方能对同一件事继续思考。

## 用后果修正想法

沿片段推演“这样做会发生什么”，寻找其中会改变方向的关系。一个变化可能同时改善体验、增加依赖或破坏原来的吸引力。把这些后果带回整体目的，允许修改具体做法，也允许重新认识真正想要的结果。

可以暂时采用一个假设，观察它使哪些部分成立、又产生什么新问题，再保留、修改或放弃。质疑需要落到这项假设的后果及依据。先帮助想法获得足以检验的形态，随后判断它是否值得继续。用户的反应决定个人体验和价值取舍，可查的机制和外部事实由团队核实。

需要参照时，寻找在相似关系上采用不同机制的作品或实际案例。说明原做法如何起作用、当前想借用哪一层关系、什么条件不同。将其用于改造当前片段，避免把每个新类比都扩成一套待实现的系统。对事实的调查按 `deep-research`，类比条件按 [类比启发](analogous-inspiration.md) 处理。

## 把分散的话题发展为相互关联的构想

用户可能在体验、功能、数据和技术条件之间来回讨论。按当前构想分清各部分的责任、关系和状态，使一个局部讨论仍能回到整体。用户提供的是现象或期望时，由主 agent 提出能够连接它们的结构，并解释它对体验、变化和实现的影响。尚未形成依据的分解保留为候选，不把最先画出的模块当作已经确定的架构。

新信息进入后，检查它改变了哪个部分、会影响哪些关系，哪些未决问题还需要回来处理。向用户展示当前需要看见的联系，详细资料按接续需要保存。避免让用户承担记住所有平行话题的责任。

## 通过查漏缩短到实现的距离

围绕当前构想查找成熟方案、相邻领域和实际失败案例，带回双方原先没想到的条件。用完整情景推演数据从哪里来、关键变化怎样发生、各部分怎样协作、发生具体异常后能否继续达到预期。只在会改变当前价值、整体体验、可实现性或投入时深入相应工程问题，其余有价值的线索保留以后查阅。

每项重要质疑应有具体触发情景、依赖假设和后果。可查事实由团队调查，仍不确定的关键机制选择足以区分解释的实验。证据支持后继续发展，失败后修正依赖它的构想。涉及用户的价值与体验冲突时，先把后果放在同一情景中比较，再共同形成决定。发现新的未知也可以成为本轮成果，随后判断是否值得继续取证。

## 在构思和承诺之间形成决定

当前想法可能同时包含想象中的远景、正在比较的路线和准备实施的部分。记录各自状态和采用理由，使有价值的远期内容可以找回，当前工作有清楚边界。讨论出现新分支时，先辨认它是否改变核心体验或本轮验证，再处理投入，不因尚未开发就自动并入范围。

当双方已经能说清当前值得追求的体验、关键机制及最影响下一步的未知，本轮可以转向调查、样例验证、收束或已授权的实现。仍有实质差异没看清时，用同一情景比较，不以完成文档作为结束讨论的理由。进入实现所需的共同材料按 [与用户核对产品理解](../refine/shared-understanding.md) 处理。

## 方法依据

- [Dorst 与 Cross，2001，Creativity in the design process](https://sites.cc.gatech.edu/classes/AY2018/cs8803cc_spring/research_papers/Dorst_Cross2001.pdf)，第 432–435 页：在九名有经验的工业设计师的实验任务中，问题解释与方案发展相互改变。列车垃圾系统案例也显示，同一个构想可以采用不同系统尺度，设计者会根据资源复用既有环节、收缩范围。
- [Schön，1983，The Reflective Practitioner](https://studylib.net/doc/26322586/donald-a-schon-the-reflective-practition)，Quist/Petra 设计案例，第 93–102 页：借助画图和假设性动作检查后果，在局部变化与整体价值之间往返。
- [David Simon 谈《火线》的编剧工作，2006](https://www.thefader.com/2006/12/08/listening-in-part-iv)：从主题和人物走向共同拆出分集情节，再由编剧起草。共同构思需要保持整体背景，并贡献能够落到具体内容的变化。

本文件将这些观察适配为人与 AI 的共同构思方法，采用后的讨论效果通过实际对话、所产生的认识和用户反馈检验。

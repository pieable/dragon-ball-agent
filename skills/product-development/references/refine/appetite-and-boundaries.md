# 投入与边界

在产品概念可能无限扩张、估算讨论代替价值取舍，或者团队无法判断什么程度算本轮完成时使用。

先根据问题价值决定愿意投入的时间、人员和不可承担的风险，再设计能在该投入内成立的产品范围。投入约束方案，而不是等全部需求列完后被动接受估算。无法缩小时，寻找仍能独立产生客户价值的较小完整结果。

个人与 AI 团队协作时，同时考虑用户需要理解、决定、操作和验收的负担。AI 能更快实现，不会自动消除这些成本。先用代表情景看用户需要掌握哪些关系、哪些重要选择仍需自己作出、怎样观察结果与追查变化，再判断当前范围是否合适。未知投入先保留未知，不为填表编造时间或分数。

起初无法可靠估计所需工作时，明确已知约束与投入未知，先做能帮助判断范围的小计划。根据实际进展、新增依赖和累积修正更新剩余工作判断，不编造总工期或把未知理解为无限投入许可。涉及明显投入变化时与产品责任人形成决定。

明确核心体验、允许实施者调整的范围、有意不做的情境，以及可能使工作失控的高危难点。提前解决会拖垮交付的未知；普通实现选择保留给负责团队，不把边界写成逐项任务清单。

新增内容与核心体验的关系决定处理方式。维持完整体验或验证关键假设所需的内容，与可以独立延后的扩展分开判断。愿景可以很大，本次承诺应具体。缩减会破坏最初吸引力时，先比较其他办法，如复用成熟能力、让团队承担内部复杂度、选择仍能保留该体验的较小样例。改变目标和明显投入继续由产品责任人决定。

减少界面元素或引入自动化也可能把依赖藏起来。用可走查的样例看用户能否找到当前状态、理解关键部件的作用、追问重要变化的原因，并判断当前结果。依照发现决定是缩小范围、改善表达、补足解释还是调整交互。用户无需读懂实现细节或承担技术测试，团队准备足以支持其价值与体验判断的材料。

当团队知道为什么值得投入这么多、在期限内必须成立的客户结果是什么、遇到什么情况应缩小或停止时结束。边界以后可以根据新证据改变，但不能在实现中静默漂移。

来源：[Basecamp Shape Up: Set Boundaries](https://basecamp.com/shapeup/1.2-chapter-03)、[Write the Pitch](https://basecamp.com/shapeup/1.5-chapter-06)。

理解和操作负担的分析参考 [Blackwell 与 Green：Attention Investment and Cognitive Dimensions](https://www.cl.cam.ac.uk/~afb21/publications/PPIG99.html) 及 [Cognitive Dimensions 教程](https://www.cl.cam.ac.uk/~afb21/CognitiveDimensions/CDtutorial.pdf)。这些材料用于识别注意力成本、隐藏依赖、部件作用和随时检查结果的取舍。个人与 AI 团队的投入安排由本次项目条件和用户反馈形成。Shape Up 的团队规模与固定周期不作为默认期限。

# 产品开发 Skill

来源：同目录 `SKILL.md` 和 `references/toolbox.md`。

## 骨架正文

通过倾听客户、定义问题、发明解决方案、完善解决方案、测试并迭代，形成能让客户取得更好结果的产品。证据可以使工作回到前面的任何环节。

这是一套连贯判断，工作按证据和未知在各环节之间调整。其他方法只补足当前缺口，不另加主流程，也不照搬其来源公司的完整制度。

先确定谁的结果决定产品价值。客户提供现实、愿望、选择和使用结果，产品团队负责理解其含义、调查事实并定义产品形态。用户或产品责任人决定价值、体验、范围、明显成本和权限等重要取舍，普通可逆细节由团队推进。

利用已有一手材料了解客户的完整任务、行为、困难和代价。区分客户原话、观察事实与团队推断。理解不足时用开放问题取得具体经历，不能接触真实客户时保留替代证据的限制。

把材料收束为值得改变的处境，说明谁在何种情境下追求何种结果、现有方式为何不足，以及为什么值得解决。问题定义给不同解法留下空间。证据改变问题时重写定义。

从客户完整的未来经历发明产品，说明介入方式、核心机制和改善结果。需要比较方向时探索本质不同的选择，向用户说明同一层级的差异和当前倾向，由合适的责任人决定重要取舍。

将概念完善到其他设计者或开发者能够还原价值、体验、机制、约束和成功标准。根据关键未知逐步展开，明确会导致产品失败的问题，保留普通实现空间。

推进粒度由风险、依赖、可逆性和客户影响决定。尚未设计的细节保留为未知，不用一次性总计划制造确定性，也不以固定阶段或逐项请示替代判断。在目标投入内解决使产品失效的关键问题，明确有意不做的内容。完善和迭代以改善客户结果为准，功能数量不能证明产品更好。

把设计要求落实为产品的信息、结构和行为。需要展示的事实和文字按要求保留，用户界面表达使用者当下需要识别、判断或操作的信息。

选择与风险和成本相称的验证，先说明何种观察会支持、否定或改变判断。原型真实到足以检验当前未知，依据实际行为和结果迭代。产品上线后继续用同一循环改进。

交付当前决定所需的最小完整产品定义。进入实现后，普通细节由实施者补足，目标客户、核心结果、完整体验和明确边界的变化带回产品判断。最终验收端到端使用结果。

### 各块的使用条件与动作

- 最近情景访谈：现有材料过于概括时，沿最近一次具体事件恢复行为链，取得足以理解采用和失效原因的材料。
- 情境观察：环境、他人或工具影响行为而访谈不足时，观察实际任务及变通办法，处理知情、隐私与观察影响。
- 旅程还原：问题跨时间、角色和渠道时，按证据恢复完整任务，区分客户体验与后台流程并定位断裂。
- 领先用户研究：类别快速变化或普通研究只支持渐进改进时，寻找提前遇到需求并自造解法者，再验证其向目标客户迁移的条件。
- Working Backwards 五问：机会尚未清楚时，检查客户、问题、收益、需要的证据和未来体验是否相互一致，缺口转为取证问题。
- 研究材料综合：材料多但判断仍依靠印象时，把观察独立记录、聚类并保留反例，由可追溯证据形成解释和行动。
- 问题重构：输入已暗含功能或局部症状时，恢复客户稳定结果和失败机制，形成既聚焦又容许不同解法的问题。
- 未来体验叙事：团队对产品理解不一致时，从触发到结果写出代表性客户经历，明确价值与核心机制。
- 不同产品世界：候选仅有表面变化时，改变解决问题的核心机制，以假设、代价和完整体验比较真正不同的产品。
- 类比启发：被行业形态限制时，跨领域寻找相同底层关系，再按客户、环境和约束检验可迁移性。
- 客户共创：语言不足以表达取舍时，用可操作材料让客户展示选择；团队继续承担产品定义，作品作为证据。
- PR/FAQ：已有方向需要共同讨论时，分别表达客户价值、外部疑问和内部难题，证据缺口保留为假设和验证责任。
- 端到端慢速走查：跨页面、角色或系统可能有空洞时，逐步检查知识、动作、响应、责任转移和失败恢复，提前处理关键未知。
- 产品风险检查：准备显著投入或未知可能推翻产品时，把价值、使用、实现与经营风险写成可反证假设，优先查会改变决定的风险。
- 投入与边界：范围可能无限扩张时，根据价值先确定愿意投入的成本，再形成该投入内能独立成立的结果和停止条件。
- 实验方式选择：缺少决定性证据时，按价值、可用性、实现或经营未知选取足够真实且成本相称的实验。
- 测试与迭代判断：实验前明确假设、代表性条件、支持与否定证据及限制，按行为结果决定继续、修改、补查或停止。

上述列表用于维护者定位 17 个实际存在的独立方法，不要求运行模型依次使用它们。每块内部的证据边界、参与者代表性和停止条件仍属于该方法的完整内容。

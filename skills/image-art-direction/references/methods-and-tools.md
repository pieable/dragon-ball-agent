# 专业方法与工具

按当前困难选用，不把工具列表变成必装清单。外部软件的功能不等于内置绘图接口已经支持；使用前核对环境、当前文档、模型兼容及权限。下面是工作方法入口，未在本机实测外部软件。

## 专业工作提供的提醒

- 接收原始内容与使用版面，让创意服务真实主题。Tom Richmond 的委托案例中，艺术指导交核心需要，插画师自行提出概念；合作熟悉且改动小，可以省去一轮粗稿。[项目过程](https://www.tomrichmond.com/sunday-mailbag-224/14/11/2010/)
- 参考用于核对具体对象和关系。Kateryna 的植物插画同时研究生长阶段与视角，完成后整理为透明 PSD 交刊物排版。[项目过程](https://www.windonpaper.com/blog/2024/3/7/case-study-editorial-illustration)
- 探索可以落在视觉隐喻、剪影、明暗和媒介，不只改变配色。是否需要草图或三维参照，取决于当前难以确定的结构；普通小图不强制经过完整制作流程。
- 区分概念探索与局部精修，需要时相互返回。新手短时实验揭示生成过程可能被早期图像锚定，但不能推断所有专业工作都如此。[CHI 2024 研究](https://arxiv.org/html/2403.11164v1)

## 按困难选择工具

| 当前困难 | 成熟能力与输入输出 | 使用判断 |
|---|---|---|
| 参考散落，难以比较 | [PureRef](https://www.pureref.com/handbook/) 参考板；[Krita Reference Images](https://docs.krita.org/en/reference_manual/tools/reference_images_tool.html) 可排列、保存多参考并去饱和观察明暗 | 先整理和标明每张图的用途；已有项目图集足够时直接沿用 |
| 文字难以传达风格或身份 | 内置 imagegen 传参考图并说明角色；[Firefly](https://helpx.adobe.com/firefly/web/work-with-images/generate-images/match-image-composition-to-reference-image.html) 另有构图参考入口 | 区分风格、身份和构图，不默认一张参考的所有特征都需保留 |
| 姿势、透视或接触关系反复错误 | 照片、手绘结构、[Clip Studio Paint 三维姿态](https://help.clip-studio.com/en-us/manual_en/660_3d/Posing_3D_drawing_figures.htm) 或已有三维场景提供可查看的结构参考 | 先检查参考自身；骨架关键点不包含完整人体轮廓与体积 |
| 需要更明确的结构条件 | [Krita AI Diffusion 控制层](https://github.com/Acly/krita-ai-diffusion/blob/main/docs/src/content/docs/control-layers.mdx)；ComfyUI 中相容的 ControlNet / IP-Adapter 工作流 | 草图、深度、姿势和图像参考各控制不同信息；需额外环境与匹配模型，不能把参数直接传内置工具 |
| 局部修好但其他地方被破坏 | 选择可靠底图，写清变化与保留项；专用编辑器可用选区、图层、蒙版保留未修改像素 | 修改范围覆盖关联对象；核实当前工具是否支持精确遮罩或局部合成，检查未修改区域与接缝 |
| 需要后期整合、可逆调整和分层交付 | [Photoshop 非破坏编辑](https://helpx.adobe.com/photoshop/desktop/create-manage-layers/create-layer-compositions/non-destructive-editing-techniques.html) 的调整层、智能对象和蒙版等 | 按交付需要选择可编辑来源；普通单张图片无须为此新建整套管线 |
| 网页形状、图标和动态效果需准确维护 | 已有 SVG 图标、CSS、Canvas、着色器及成熟组件；浏览器截图反馈 | 需要精确、响应式或可交互的部分用工程表达，插画与界面统一设计 |

默认仍遵循 imagegen 的内置绘图与图片编辑规则。外部编辑器、CLI 或额外模型路线在工具能力及授权满足时采用；不能因某条路线出现在此表就擅自切换接口或安装环境。

工具名不是质量结论。判断是否有用，要看它能否解决当前可见问题、减少不可控变化，并交付本任务需要的文件。跨模型参数、默认值与示例次数不迁移成长期规则。

## 纹理伪影的检查与清理

这项检查适用于各种画风。用户所说的“扩散纹”作为现象入口，先定位具体画面问题：半透明条带、条纹叠影、随机碎线、无结构斑块、重复或漂移的纹样、重影、局部糊化、边缘融化，以及材质细节与形体不一致。结合目标画风、物体结构、材质和光照判断；有意的颗粒、笔触或图案可以保留，破坏轮廓、体积或材质辨认的部分需要修正。

查看原始文件和最终使用尺寸，并按需要放大疑点。记录问题所在对象、位置和可见影响，例如发丝粘成碎条、衣褶被杂纹割裂、皮肤出现无来由色块、建筑构件在交界处融化；不要用一个笼统的“画质不好”或“增加高清细节”代替定位。检查整张图的主体、过渡区域与背景，不能只看脸或缩略图。

修复前选定可靠的身份、构图和画质依据，分别标明参考用途。已有干净版本时从该版处理；问题已经融入底图时，不要求模型原样保留所有纹理。可将问题图只用于身份、结构或构图，以干净参考说明画质，按工具支持选择局部重建或重新生成。提示说明可见问题、希望恢复的画面效果和需保留的设计，把具体笔触、像素调整与修复手法交给绘图模型。可以让它在这些约束内自行修复，再比较实际输出；修复无效或退化继续时更换底图，必要时整体重画，不持续沿问题版本叠加修改。避免一面要求清理，一面要求继承全部原有笔触和纹理。

修后比较同一区域及整张图：问题是否减轻，结构和材质是否清楚，身份、构图、色彩与有效细节是否保住，是否新增斑块、过度平滑或锐化痕迹。仍有缺陷时保留未通过状态，按变化决定继续局部处理还是回到可靠依据重建，不把更高分辨率、纹理更多或换了版本当作画质改善。

## 多轮编辑退化的依据与判断

用户已多次报告连续改图后半透明条纹越来越明显，后续编辑应主动对照早期干净版本检查。该经验用于安排检查和选择底图；具体是否退化及退化成因，以本次版本对比和可核验证据判断。OpenAI 的[Images 2.5 系统卡](https://deploymentsafety.openai.com/chatgpt-images-2-5/limitations)说明了 C2PA 元数据和不可见的 SynthID 水印，未将这种可见条纹认定为水印表现。水印与扩散机制保留为待查假设，修图简报直接描述可见缺陷。

[WACV 2024 研究](https://openaccess.thecvf.com/content/WACV2024/papers/Joseph_Iterative_Multi-Granular_Image_Editing_Using_Diffusion_Models_WACV_2024_paper.pdf) 与 [REED-VAE](https://reed-vae.github.io/) 在所研究的潜在扩散编辑流程中观察到重复编码、解码带来的累积伪影，并研究了保留潜表示或改进自编码器的办法。这些机制解释有适用范围；闭源工具出现相似斑块，不足以证明其采用相同架构，更不能据此声称继承自 Stable Diffusion。

检查实际输入输出关系、提示和前后图，比较同一区域的形体、笔触与纹理。已融入明暗结构的斑块可能被继续当作参考特征；清理也可能简化有效设计。没有干净底图时，可用问题图约束身份与结构、用合适参考说明画质，尝试局部重建或重新生成，再核对设计变化，不将重新生成称为无损恢复。以上是按问题选择的方法，不要求每次编辑重建整套流程。

# 网页视觉稿与前端交接

用于整体美术或新视觉身份是作品关键、方向仍开放时，让绘图模型完成页面的整体布局与美术，再交给前端实现。符合这些条件时先取得完整视觉稿；已有设计的局部修改、明确只需单图的任务按对应范围处理。普通信息报告按内容关系与成熟、朴素的排版组织，精确路线图沿用 Mermaid 或程序化绘图；已有组件与交互约束进入简报，不自动把整体设计缩成插图任务。

## 给绘图模型

确认整体美术或新视觉身份对当前作品确实重要且仍开放后，负责人整理能够独立理解的创作背景：读者、设备与使用情景，页面帮助其理解或采取什么行动，当前成熟度、真实内容关系及有效限制。明确委托“完整页面设计”，交入真实内容、必要操作和原始参考，让模型发展整体视觉方案；不要先由调用方规定大部分版式，再把绘图只当素材生成。

将主要信息、行动与必要条件的优先级及理由交给模型，准确文字与可探索的艺术处理分开。信息取舍尚未确定时，说明具体阅读问题，让模型提出视觉组织；不把未核对的权重当成已确定要求。

参考图标明身份、风格、构图或编辑对象等用途。项目资料、用户反馈和 Skill 不会自动传入绘图模型；将影响本轮创作的原文、图片和条件写入实际调用，避免只列名词，也不堆入无关历史。网页稿明确为平面页面设计，具体字体气质、色彩、构图和图像关系留给模型形成整体处理。

明确画出页面中可见的导航、标题与正文层级、主体图文、主要操作、区块连接及结尾等适用部分，让这些元素与插画、美术共同组成页面。内容量、栏目关系和操作位置应可判断；准确文案后续由前端校正，不能以此为由只提供几句标签而省掉正文区域。长页面可先形成整页结构与视觉关系，再以衔接的分区稿细化；多页面按实际范围覆盖关键页面和状态，共用已采用的视觉语言。稿件数量服从设计覆盖与可读性。

## 核验并采用设计

打开实际成图，按页面用途检查内容主次、主要行动、必要条件和美术质量，并落实主 Skill“看图后继续指导”中的画面完整性与采用条件：整体及使用尺寸检查通过后才拆素材和交前端。第一眼的吸引力与完成度属于本次检查，功能完整或内容齐全不能替代。发现问题时，把具体画面现象与使用背景反馈给模型，完善有效稿件。文字错字、日期或价格在实现中准确修正，通常无需为此重画。

采用时覆盖整页确认主体与叙事的主次、区块构图和比例、字体色彩、素材装饰及衔接节奏。只画出了总览插图、首屏或局部时，继续补齐约定页面范围，不能据此判为整页设计完成。探索稿经核对采用后成为整体实现依据；仅作风格参考的图片应另行说明用途，完整页面仍需形成有效设计。需要改变主要设计时，回到相应决定，而非在编码中默默替换。

## 交给前端

交入当前有效原图、准确内容、独立美术、使用入口，以及须保留的关系和允许适配。文字摘要用于索引，接收者仍须实际查看原图。设计版本与用户反馈保持一致，未采用的探索图不能覆盖当前依据。

沿原稿区域交清素材路径、用途、裁切与组合条件、透明边缘和缺件处理者。角色、故事插画、场景、材质与重要装饰按实际职责核对；需要共同透视、接触和光影的对象可保留整体。缺少关键美术时先取得、提取或补生成，不以整页位图、预览拼图或通用占位物当作已完成的资源包。

实现从原稿建立构图、落实布局、补足工程行为与验收的具体方法由前端的 [视觉稿还原](../../frontend-design/references/visual-reconstruction.md) 承载。此处负责交清设计与美术输入，不另维护一套前端实现规则。

## 承接真实页面的反馈

接收原稿和实际页面在相近宽度下的对照，以及偏差位置、使用条件和仍缺资源。实现偏离有效原稿时由前端修代码；缺少或不合用的美术回到本流程补齐；设计本身与真实内容发生冲突时，带着具体场景完善设计并更新有效版本。

新图或修改放回真实页面后，重新核对其构图职责、画质、裁切和整套一致性。原图好看、资源已经写入和网页完整还原分别依据实际结果判断。用户认可的气质与设计关系保留为下一轮输入，不把修复局部问题扩成未经决定的换风格。

## 方法入口

[Eric Jordan 的过程记录](https://ericjordan.design/process)提供了方向明确后进入前端并用截图反馈的案例。此 Skill 的整页出稿用于整体美术或新视觉身份是作品关键且仍开放的情境；已有设计的局部改动可以直接实现。前端的视觉还原规则保护已采用的设计，绘图与实现共同围绕真实使用结果迭代。

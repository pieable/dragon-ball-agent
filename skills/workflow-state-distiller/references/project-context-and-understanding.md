# 项目背景与共同理解

用于持续合作中保存和调用项目知识，让材料、共同理解、新联系与实际决定能够接续。当前负责人沿用已有资料入口，一次性、背景清楚的任务直接完成。下文按实际需要往返使用，已有依据充分的环节直接沿用。

## 建立一个可找回的背景入口

先查项目已有的概览、规格、设计记录、学习状态和研究索引，确定它们各自承载哪些事实与决定。已有入口可用时补足关系与引用。缺少入口且背景需要跨阶段使用时，在项目资料内建立简短的背景说明，按项目约定命名，无约定时可用 `docs/project-context.md`。材料少时与当前状态放在同一文件的不同部分，无需先拆分目录。入口位置写入已有项目说明或接续记录。

背景覆盖项目用途、用户已有知识与关切、领域与业务规则、代码和运行条件，以及方案形成的原因。按实际对象组织，保存后续理解、判断或查证所需的内容，详细材料留在其权威位置。入口说明在哪里、何时需要查，未调查范围与未知保持可见。

对关键对象，说明它是什么、在项目中承担什么作用、与其他对象怎样相互影响。关系可以是依赖、约束、因果解释、比较、类比或待研究联系，写清关系的含义与成立条件，并将事实和解释分别对应到来源。重要资料保留可定位的版本或日期。代码事实指向具体实现、接口合同或有效验证，当前配置指向实际配置来源，摘要随来源变化核对。

对影响重要选择的判断，保存其支持依据、所依赖的前提及尚缺的关系。共同成立才能支持结论的条件一起说明，其他独立支持分别保留。候选解释和未知按其后续理解价值保留入口，当前摘要按行动需要选取；多个视图引用同一主要来源。

例如，记录“学习者不熟悉异步调度”时，连到本节要练的判断：当前目标若是指挥 AI 调查并核对证据，可以先用输入、输出和责任解释内部机制。调度行为开始影响判断时，再展开相应知识。记录接口失败时，连同实际失败表示、调用方处理和最终可见结果一起保存，使后续实现与验证能采用同一份已核实依据。

## 恢复此前没有连续记录的旧项目

当前入口不足以解释目标、实际结果或路线来由时，先恢复这些关系，再依赖它们继续重要工作。项目早于本 Skill、没有状态文档或路线图，都可以从已有资料开始。已有背景足以支持当前局部任务时直接沿用。

从现有概览和实际成果确定要查的对象，再沿影响当前选择的线索查计划、设计记录、版本与提交、运行或试用证据，以及可取得的相关会话。代码、数据或其他实际产物用于核实当前机制，原始反馈和决定用于还原用途与取舍。先找关键决定及出现矛盾的位置，再按具体缺口扩展，材料范围以能判断当前路线为准。

将重要选择连成“当时要取得什么结果—依据什么作出选择—实际做了什么—验证了哪部分—用户得到什么—后续怎样调整”的关系。区分用户决定、模型解释、计划、实现与实际验证，记录可定位的来源和适用时间。缺少当时理由时保留未知，不能用现在合理的解释补造过去的决定，也不能把今天才出现的条件当作过去已经可知的事实。

用恢复结果检验当前路线：实际结果是否达到有效目标，局部通过能否支持整体完成，以及继续采用现有办法所依赖的条件是否成立。不同局部问题指向同一前提、责任安排或验证缺口时，查明这些关系怎样造成当前代价。结合具体依据比较继续局部处理与调整有关方法或结构，保留各自能复用的成果、依赖、迁移和验证成本。软件中的重构或替换只是可能的选择，旧项目的年龄、材料数量或错误次数本身不能决定路线。

将能够影响选择的发现用于当前行动：有依据地保留路线、改变有关做法，或先取得足以区分选择的证据。重要方向和明显投入的变化仍由主 agent 与用户形成决定。[探索路线图](../../workflow-route-mapper/SKILL.md)保存恢复出的选择、结果及当前路线的关系，当前负责人负责核实并采用这些发现。沿用项目已有资料建立一个背景与当前状态入口，保留历史缺口、重要旧路线及其来源，后续从这里继续维护。

## 区分背景、当前行动和形成过程

项目背景保留可复用的对象、关系、依据、未知与重要决定的理由。当前行动状态引用其中本阶段需要的内容，说明目标、进展、待定问题、负责人和下一步。形成过程记录证据怎样改变了理解与路线，由[探索路线图](../../workflow-route-mapper/SKILL.md)承载。三者可以共用文件，已有事实只维护一个主要来源。

暂缓的方向保留其价值线索、成立条件及何时值得重看。旧解释被替代时，在当前入口使用新解释，仍有解释价值的旧路线保留原因和来源。压缩当前状态时，保留背景入口，不把暂时离开注意范围当作删除知识的依据。

用户已掌握什么，依据其自述、实际表达和运用情况判断，连接到相关概念或任务，保留来源与范围。讲过的内容可记录为已介绍，熟练程度沿用教学 Skill 的证据标准。项目中的理解记录用于承接交流，跨项目个人档案按原有维护权限处理。

## 选择现在值得关注的内容

将用户反馈放回成果用途与当前阶段，追查结果成立还依赖哪些专业条件。给一个事项排优先级时，说清它保护或改善什么结果，遗漏或延后会造成什么具体后果，哪些后续工作依赖它，以及现有证据和处理投入。按这些关系决定先解决、继续取证、边推进边补足或暂缓。

已经暴露的核心错误、会使后续工作建立在错误前提上的未知，需要及时处理。普通局部问题可以直接修正。只有抽象可能性、且与当前用途缺少具体联系的完善项，先保留线索。原型与正式使用按各自用途决定完成深度，重要暂缓项写明重新考虑的条件。

同时考虑当前成果价值与后续理解价值。反复影响路线、跨多个功能解释现象、或能够帮助用户形成新判断的核心知识，值得逐步讲深。只影响一次实现的细节由 agent 处理并保留查阅入口。已有明确交付优先要求时围绕交付推进。明显增加学习或探索投入的选择，说明收益与影响后与用户形成决定。

分开工作优先级与用户参与优先级。agent 查明事实、提出关系、完成范围内专业处理。需要用户经验、偏好或重要取舍时，准备足以比较的材料。重要事项可以由 agent 自主完成，不以提交用户确认作为重要性的标志。

## 将新联系发展为判断

用户或 agent 提出联系时，先保留所连接的对象、预期变化、价值和尚未说清的部分。能从现有材料恢复的背景自行查明，只有用户独有的经历或意图会改变理解时才询问。

把联系展开到中间过程：哪个条件通过什么作用影响哪个结果，在哪些情境成立，有哪些已知事实支持或冲突，是否存在另一种解释。类比先核对对应关系及差异。已有材料足以推理时直接比较，需要新增证据时用[深度研究](../../deep-research/SKILL.md)或相应专业能力处理约定范围的问题，并遵守用户对调查、实验和投入的限制。

判断所得认识改变的是问题定义、候选路线、实际决定，还是一个值得保留的探索方向。尚未成熟的想法保留为候选，写清缺什么和何时重看。改变目标、主要形态或明显投入时，由主 agent 与用户形成决定。形成决定后更新受影响的规格、工作顺序和完成依据。

## 能力接续与更新责任

主 agent 持续负责整体问题、取舍与当前理解，明确每批成果由谁接收并用于哪项工作。按需要调用现有能力：

| 当前需要 | 能力及交回内容 | 接收后怎样使用 |
| --- | --- | --- |
| 取得材料、比较解释或查明关系 | 研究或本地取证交回主张、依据、条件、冲突及未知 | 主负责人核对决定性依据，更新项目背景与受影响的问题 |
| 让用户理解关键对象和关系 | 教学与解释围绕完整情境讲清机制、差异及适用条件 | 承接用户的自然表达、质疑和运用，调整解释或问题理解 |
| 形成产品与完整体验选择 | [产品开发](../../product-development/SKILL.md)沿用户经历与证据形成方案；软件实现继续使用[代码开发](../../code-development/SKILL.md) | 主负责人处理跨责任取舍，更新有关规格和工作安排 |
| 核查产物与结论 | 评审交回具体问题、依据和未解决事项 | 负责人组织修正，将改变理解的发现带回原资料 |

一个负责人可以连续使用多项能力，无需为每一行另建代理。下游所需输入齐备后推进，独立准备可以并行。研究结论的成立与用户是否采用该方向分别处理。接收者将结果落实到实际决定或说明保留、暂缓的原因，不以报告已经交回作为接续完成。

选择重要方案、改变范围、恢复或交接工作时，先从入口读取相关背景，再回查会影响判断的原始依据。新证据、用户理解或决定发生变化时，由当前任务负责人更新主要来源、当前状态和必要的过程记录。子代理交回变化与依据，由接收方整合。保持对象名称与引用一致，来源失效时标明并核实受影响部分。

用户在调查、开发和试用中重新认识问题时，记录旧判断的适用情境、促成变化的认识以及已形成的新决定。沿前提和支持关系核对受影响的结论与工作，保留仍有独立依据的部分，按主 Skill 的范围与决定要求同步需求、设计、委派和验收。新方向尚未决定时保留为候选，并写清继续判断所需的证据或体验。

## 检查资料是否起作用

从一项当前选择回查，检查能否找到它服务的目标、所依赖的事实与条件、采用理由和未知，以及条件变化后能否定位受影响的决定与工作。再从用户阅读入口检查：能否理解核心对象与关系、找回先前讨论的问题，并继续提出联系或质疑。按缺失的关系和依据修正资料，避免只增加记录数量。

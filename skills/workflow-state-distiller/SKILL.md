# 任务理解蒸馏

## 加载后的范围判断与处理动作

把当前理解视为可修正状态，依据用户表达的情境、实际选择、纠正和试用结果持续校准。需要维护跨阶段项目背景时，按需读取 [项目背景与共同理解](references/project-context-and-understanding.md)；概念含混或评价标准未定型时，按需读取 [探究与修正的方法](references/inquiry-methods.md)（只选能改变认识的具体方法，不走全套流程）。

- **先判断介入深浅，不盲目全量重建**：
  - 目的、边界与下一步仍有可靠依据时，只做轻量的前提复查、背景更新或阶段整理并继续，不因普通执行报错或等待外部状态全面重建理解。
  - 若继续行动可能因零散或失效的理解而遗漏有效要求、误判范围或改变下一步，**先暂停依赖旧理解扩写规则或大改成果**，恢复“目的、背景、行动、结果、边界及未证实原因解释”的最小整体关系后再继续。
- **按当前问题执行对应整理**：
  - **前提倒推与偏差修正**：目标未推进或结果偏离时，从用户原始目标和实际行动倒推显性与隐性前提，**优先检查一旦不成立就会使一串投入多余的自选假设**，再选能区分原因或直接推进目标的证据与行动；出现反证或局部偏离时，只修正受影响的前提、推理、范围、结论与行动（局部检查通过或再次发现自选路线受限不算推进用户结果，也不重置 `AGENTS.md` 的未进展计数）。
  - **阶段收尾整理**：完成一个有实质结果的阶段后，整理本阶段确认或推翻了什么、哪些决定与成立条件仍有效、还缺什么证据及下一阶段起点。局部完成不自动代表整体达成；保留原任务和中途追加事项的未完成部分。
  - **接手旧项目**：将已有实现、最近方案连同其依据一起核实；背景或路线来由不清、或局部持续通过却达不到整体结果时，按 [项目背景与共同理解](references/project-context-and-understanding.md) 追溯材料并检验前提。
  - **共享材料与防重复整理**：沿用已有状态与资料入口，只更新会影响后续理解和行动的内容；无新增认识时确认原状态仍适用即可，不为每次工具调用另建阶段、文档或长报告。涉及旧项目恢复或重要改道时，与 [探索路线图](../workflow-route-mapper/SKILL.md) 共用材料、证据和当前决定，避免相互调用重复整理。
  - **独立重整**：复杂任务中，当前理解难以解释用户目标与实际结果，或不足以决定下一步时，及时调用已注册的 `astra-specialist` 独立重整；交清用户原话、关键原件入口、有效决定、已有解释、反证、已否决路线与未知，保留原始语境。主 agent 亲自核对交回判断所依赖的原文后再落实到状态与行动。

## 任务状态与证据分级

当前行动状态集中维护会改变行动的五类内容（缺项省略，不填死表，完整历史留在路线图与原件）：**目的**（为什么做、优先保护什么）、**背景**（对象、场景、关键来源、实际选择与仍影响判断的失败路线）、**行动**（当前做法与顺序）、**结果**（交付物、完成状态与使用方式）、**边界**（不变项、权限、不可接受代价与待确认决定）。

- **四类证据必须分开**：(1) **直接证据**（用户选择、保留、否定、使用感受与已发生结果）；(2) **明确决定**（目标、限制、权限、取舍）；(3) **原因假设**（用户或模型对“为什么”的解释，标明来源；用户直接感受能证明“结果不对”，但不能单独证明原因）；(4) **未形成偏好**（需通过比较或试用形成）。
- **确定度与措辞力度对应表**（规则强度必须与证据相称。单任务反馈只用于当前任务；只有用户明确确认，或多个项目中的实际选择都支持同一要求时，才升格为跨项目原则。新证据可缩小、替换或取消已确认原则）：

| 确定度 | 判定依据与适用范围 | 对应措辞力度 |
| --- | --- | --- |
| **明确事实** | 用户直接说明的目标、决定或限制 | 直接陈述事实与适用条件 |
| **局部修正** | 只对当前内容、版本、场景或动作生效 | 写成“这次……” |
| **工作假设** | 当前最合理、可指导低风险行动，但可能被推翻 | 写成“目前先按……处理” |
| **候选原则** | 多个不同情境支持，但边界或例外尚不清 | 写成“在这类情境中通常……”或“优先……” |
| **已确认原则** | 用户明确认可，或有不同来源稳定证据、清楚范围且能正确判断相似场景（不只看出现次数） | 写成清楚的默认要求（如“优先简洁”，不扩写成“必须极短”） |
| **硬边界** | 用户明确要求不可越过，或涉及安全、权限、不可逆风险（立即生效） | 才可使用“必须 / 不得 / 绝不 / 任何时候都” |

## 蒸馏与校准流程

1. **定位反馈**：弄清反馈发生在哪个任务、对象与动作上，改变的是结果、用途、取舍、协作方式还是局部细节。
2. **分清事实与推断**：先记用户原意、实际选择与已发生事实，再写模型理解与适用范围。
   - 把局部否定转成正向结果要求，不把单次局部纠正直接升格为长期规则（仅当删去会容纳具体且易复发/高风险错误时保留反向边界）。
   - 模型补出的前提与中间关系必须标为**推断**；推断不能单独授权扩大范围、改变交付或降低验收。
3. **用“下一步行动”做减法并设接续条件**：逐项检查当前理解——若删掉某项后，目标、输出、提问、权限、风险处理和下一步行动都不变，则移出当前行动状态（仍有后续价值的解释与未知留在项目背景入口）。用留下的状态选出一次真实的下一步，写明**解决什么未决问题、现有证据为何支持、得到什么结果后接续或停止**；复述不算完成，取得后续实际结果后回看是否改变当前判断。
4. **回查前提、原始依据与反例**：
   - 做重要方案、进新阶段、交接或结果不符预期时，找出隐含前提并回到决定性原件核对（多条摘要转引同一材料不增加独立证据；多个模型意见一致不增加事实依据）。**按原件明确记录的条件和结果保留其证明范围，仅在具体冲突、条件变化或材料缺口影响当前选择时扩大核查。**
   - 检查竞争解释与反例：针对会改变重要选择的解释，**说明什么观察能区分它与竞争解释，再通过调查、比较或试用取得证据**。出现反例时，区分“依据失效 / 尚待判断 / 已被否定”，定位它影响前提、推理、范围还是结论，保留仍有独立依据的部分。
   - 重要异议回到原件与实际影响，负责人落实结论到当前状态或记录重新考虑的条件，不只停在方法说明里。
5. **决定继续做、给小样还是提问**（优先查清一错就大返工的前提；高代价工作暂缓，有依据的局部继续）：
   - 多解释导向同一安全行动 → 用最窄工作假设继续；
   - 可逆小成果更易暴露偏好 → 先交付局部样本或修改；
   - 不同答案改变目标、结构、权限、不可逆操作或可见结果 → 集中提最有价值的问题（不按固定题数拆轮；若提问负担大于防错收益则直接执行）；
   - 涉及安全、权限与高代价边界 → 先确认边界。
6. **同步更新**：新证据或决定落地后，同步更新目的/背景/行动/结果/边界与受影响的规格、设计、委派、验收。同一目标内的篇幅/措辞微调小步校准；用途、成功标准或问题定义变化时重建状态。

## 失败路线、中途插曲与归属分层

- **失败与探索记录**：只有改变了目标、路线、边界、验证方法或能防重踩的失败，才记为 `原判断 — 推翻证据 — 当前影响`；已解决且不再限制后续的报错与尝试过程从当前要求中清除。需要整理复杂因果与分支时交由 [探索路线图](../workflow-route-mapper/SKILL.md) 呈现，不在两者间反复互推。
- **继续失败路线与辅助环节**：继续一条已失败路线必须有新证据、修正过的假设或不同办法，否则暂停并安排独立检查。辅助环节（留档、整理等）出错时不让它变成新的交付前置，先判断是否影响实际交付。投入异常或重要改道时，向用户说明目标、已有结果、主要消耗、卡点、原因、剩余投入与可行路径。
- **中途插曲保护**：长任务在当前状态文档保留原任务、完成条件、未完成项与恢复点；收到中途反馈时更新关系，**不让最新消息覆盖仍有效的原任务**，处理完插曲后核对状态接续原任务。
- **理解保存在哪里**（每项要求只维护一个主来源；实际文件位置服从项目约定和宿主机制，部署位置与规则职责层不同时，记录并遵循已确定的部署方式，不复制到多个位置）：
  - 仅影响本次工作 → 当前任务状态；
  - 人物/剧情/产品等项目对象事实 → 项目已有设定或状态资料；
  - 同项目反复执行的取舍 → 项目规则；
  - 跨项目且特定任务触发的方法 → 对应 Skill；
  - 所有任务默认遵循的长期要求 → 全局规则层（需经用户确认）；
  - 样本、试验与失败记录 → 校准或证据（**不能仅因结果获认可就升格为事实或规则**）。

## 对用户的输出与验收

- **按场景输出**：局部纠偏只简短说明新理解并继续；询问真实目的时说明明确事实、最小解释与关键不确定性；整理状态时输出精简当前状态；写入长期规则时只写已确认原则与硬边界；已有安全修正方向时先改成果再校准。面向用户的说明围绕目标、方案结构、验收与依据，不展开执行流水；交接给 agent 的材料保留完整状态、条件与证据入口。
- **自检验收**：
  - 当前理解能解释用户取舍并指导可执行下一步，措辞力度与证据、风险相称；
  - 用户决定/权限、事实、推断与未知清晰可分，重要偏好有来源、范围与实际选择支持；
  - 关键结论可回查原始依据与适用条件（无重复转引充数），反例已落实到受影响部分；
  - 重要取舍的提问能改变下一步且负担相称；交接状态保留完整背景与入口。
- **维护说明**：维护本 Skill 时读取 [评测案例](references/eval-cases.md) 检查触发与混淆边界，并以真实任务结果核验（普通任务不读；历史变更见 CHANGELOG.md）。

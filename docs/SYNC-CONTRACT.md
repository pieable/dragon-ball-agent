# 安装与同步约定

## 当前可运行入口

`python tools/preview_sync.py --codex-home <实际目录>` 只读取白名单文件，输出新增、相同及冲突项，不写运行目录、不创建目录、不安装依赖、不调用模型。`system-manifest.json` 明确列出本批已纳入文件和尚未迁入的组件。

这份清单中的 SHA256 对应审核候选。源文件改动后须重新检查并更新清单，预览器不会自动接受不一致来源。固定机器路径已转换为 `{{CODEX_HOME}}`，预览时按目标目录渲染。不同 Skill 根目录的支持留到安装适配阶段，本批不默认移动既有 Skills。

## 正式应用阶段需要满足的行为

1. 保存本次实际将替换的字节、候选哈希、安装前哈希和目标路径，记录位于本机私有安装状态目录。
2. 首次接管已有不同文件时展示差异，由维护者合并。后续更新用上次安装哈希判断本地是否改变；本地改动与候选同时变化时不覆盖。
3. 仅写清单内明确托管的目标，不替换整份 config，不递归删除运行目录。退役组件单独列出并核对本机状态后处理。
4. 私人学习档案、素材库、业务案例和会话绑定保持本地原文件，发行包提供可新建的模板或本地入口。缺少必需材料时显示具体缺项，不能把依赖删除当作已完成安装。
5. 写入后逐文件核对结果。中断时根据日志判断已完成、未完成和未知项，再继续；回退仅恢复本次改动，若安装后又有用户修改则先报告冲突。
6. 账号授权、凭据和安全设置继续由原环境管理。依赖安装、工具启动和模型调用作为独立步骤，不藏在文件同步中。

## 发布顺序

核心指令、Skills、工具与插件、配置适配、安装验证分别保留 Git 恢复点。完成源文件和再分发授权审查后才更新公开分支；当前本地候选不触碰已运行的 Codex 或 Luna 执行层工作。

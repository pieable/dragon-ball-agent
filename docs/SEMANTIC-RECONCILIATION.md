# 同名文件差异的处理

对照的是实际安装内容与本次候选，不以字数、文件日期或宿主名称判断谁应覆盖谁。原35份冲突文件已在仓库外私有基线保存，运行目录未改动。

## 已回收的宿主适配

DSH的Playwright入口、CLI参考、工作流示例以及路线图侧栏参考，保留其pwsh/npx与present文件交付协议。以 `adapters/deepseek-harness/skill-deltas.json` 保存对共享来源的精确差分，不复制一套Skills。差分记录基础文件和结果哈希；共享源变化后构建会要求重审适配，不自动套用陈旧补丁。个人安装路径渲染为目标Harness目录。

四份候选重建后与现役DSH文件字节一致，DSH只读比较变为63项相同、24项冲突、37项新增。其余冲突仍保留。

研究方法中的具体模型名已从“使用Skill不自动升级Astra”改成“使用Skill不自动更换模型”，继续遵守前句的当前配置，不把模型选择写进通用专业方法。

## 共通改进

候选中的职责边界、状态分析、适用条件下的变异测试、产品构思、成本估算和项目背景等方法没有发现需要保留的宿主独有行为，继续由共享源维护，不为每个产品另存副本。

Claude旧公司研究方法的市场估算把年度支出再乘替换周期、年度合同额再乘续约率。当前共享方法按收入期间、采购频次和存量替换机制分别估算，避免重复计算。该修正保留在共享源；真实安装仍需先解决其个人报告流程，不能绕过同名冲突。

## 保留到集中决定的语义事项

1. **开发/评审的短主干与长正文。** DSH短版已涵盖实际入口、验收、独立评审与交付，不能仅凭短就认定缺漏；固定要求每次单列兜底检查与按存在条件才检查也不同。需按行为用例选择共同主干及按需引用。
2. **过程资料留存。** 一份旧规则要求工作结束删除状态文件、过程不入仓库；当前共同规则要求保留有用尝试和证据。迁移按当前接续方向准备，但要登记政策替换，不能当格式修改。
3. **任务编号和路线编号。** 已有“不另造路线编号”与单独路线/证据编号的相反要求，需确定定位职责，再同步正文、元数据与评测。
4. **个人报告工作流。** Claude公司研究含特定写作者分工、报告长度、结论位置、引用另附和Word样式要求。这些不是Claude能力差异，保留本地profile及模板，不能公开成所有用户的默认流程。是否仍有效需结合用户后续决定核对。

目前按对应宿主原配置保留这些未裁定行为。`registry.json` 的 `retain_local_targets` 明确列出DSH的12份、Claude的2份文件及原因，构建不把它们列入托管覆盖清单；原目录及私人模板保持原状，新环境缺少这些文件时仍需完成对应配置，不把留空当作完整安装。后续决定会落实到共享源或适配层，再撤掉相应保留项。

上述事项不影响继续做独立的适配、来源审查和同步验证，也不授权覆盖现有私有规则。
